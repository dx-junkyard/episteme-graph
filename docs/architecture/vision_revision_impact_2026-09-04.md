## 0. 結論

研究調査による再審が要求した原則改訂のうち、**既存コードの挙動を変えるべきもの**は二つに
絞られる。ほかは文言の精密化（既に構造的に守られている）か、研究知見が「未証明」と判定した
仮説であり、実装ではなく §9 の候補として置くのが正しい。

| 処置 | 件数 | 内容 |
|---|---|---|
| **実装** | 2 | ①一括確定の**確定文脈の記帳**（原則1・8・14）②**制度指標カタログ**（原則4） |
| 文書のみ | 9 | 原則2・3・5・6・7・9・10・11・12・13 の精密化 — 現行コードが既に満たす |
| 保留（仮説） | 6 | 人に関するデータの消去請求 / 帰属開示の分離 / group を第一の器に / 研究転用の五条件 / claim type 別検証契約 / 転移課題 |

「実装しないこと」もこの整理の成果である。討論が合意した機構（group 上限・輪番切断・検証労働の
供給）を、研究照合が「未証明」「要修正」としたので、コードにしない。

## 2. 保留した機構と理由

研究照合の判定に従い、次は**実装せず** vision.md §9 に仮説として置いた。

| 機構 | 討論の合意 | 研究照合の判定 | 保留の理由 |
|---|---|---|---|
| 人に関するデータの消去請求（学習者本人による痕跡本文の消去・保持期限） | — （再審 §7 原則3 の限定から派生） | 要修正（原則3を絶対化しない） | 保持期間・法的根拠・墓標の形式をオーナーが決める必要がある。既存の `DELETE FROM` 禁止ガードレール（2026-09-04 時点で14ファイルが「行削除」不在を検査）は知識オブジェクトの原則として正しく、人データ側は専用設計書で例外を宣言してから |
| 帰属記帳と開示の分離（輪番切断・開示を可視性勾配に載せる・ゼミ横断） | 第2回 論点5 | 不十分（制度構造の上でのみ機能） | UI だけでは異議のコストは下がらない。複数指導者・独立 ombuds 等の制度前提を設計書に明記できるまで着手しない |
| group を問いの第一の器に（未検証可視は group 上限・教員へ既定で流れない） | 第2回 論点4 | 原則は支持・固定閾値は未証明 | 可視性を一軸に畳まない（閲覧 / 名前 / 引用 / 評価利用 / 外部 index / 撤回）設計が先。現行 private / group / public の意味論変更は V層・可視性フィルタ全体に波及する |
| 学習者の確認記録の研究転用（検証の下書き） | 第2回 論点2・10 | vision の主目的から外す。五条件 | 「教育が検証労働を供給する」を根拠にしない。opt-in・代替課題・品質確認・名前付き credit・撤回経路の五条件を満たす設計書が先 |
| claim type 別の検証契約 | 第2回 論点2（検査器に相対的） | 強く支持（方向）・単一軸でない | 最初の非物理系コーパス投入時に分野別対応表と併せて。現行 `verification_scopes` は物理中心 |
| 転移課題 | 第2回 論点1（答責の作法は転移する） | 条件付き支持（転移は自動でない） | 学習成果の直接測定を伴う pilot 設計が先。単独機能として作ると評価装置になる |

## 3. 実装した2件の設計・UX の要点

### 3.1 確定文脈の記帳（decision_context）

- **問題**: 「次へ」＝承認とみなす（RR2）は、研究照合が指摘した automation bias / moral crumple
  zone の典型条件を満たしていた — 確認者は根拠引用を見ておらず（DTO の `evidence` を UI が
  描いていない）、監査には「何が提示され、何が選べたか」が無く、事故時に教員だけが責任を吸収する。
- **UX の判断**:
  - 「次へ」の文言・1操作の軽さは**変えない**（RR1/RR7: リリースを止めない・摩擦税を作らない）。
    変えるのは**確認者に見えるもの**（各行に「根拠を見る」）と**後に残るもの**（記帳）。
  - 再審の経路を事実文で明示する（「確認後も…個別に再検討・却下へ戻せます」）。拒否可能性は
    既存の 「あとで」（工程スキップ）と各行 [却下][再検討] が担う。
  - 提示と適用の一致（`presented_matches_applied`）を応答で返し、不一致なら事実文で知らせる。
    画面の陳腐化を黙って承認に変換しない。
  - 数値は増やさない（RR6 の件数「未確認 N件」は既存のまま）。
- **記帳**: `basis` / `presented` / `applied` / `presented_matches_applied` / `alternatives_available` /
  `decline_possible`（導出・常に真）/ `reopen`（path・statuses・actor）/ `evidence_shown` /
  `client_reported`（クライアントの来歴申告はサーバ導出値と混ぜない）。代替が無い確定は
  ValueError — ゴム印を記帳できない構造にした。
- **適用範囲**: 一括確定の2経路（リリース前の確認・説明レビューの一括承認）。単発の承認・凍結・
  公開への拡張は段階適用（vision.md §9）。

### 3.2 制度指標カタログ（indicator catalog）

- **問題**: 原則4「数値を見せない」は宛先三分（他者 / 本人 / 制度）で運用されていたが、制度側の
  計器の**定義と用途**が散文に散らばり、学習者は「自分の活動が何に集計されるか」を一覧できなかった。
  研究評価（Leiden Manifesto / DORA）は、見せないべきは個人ランキングであって指標の定義と
  利用法ではない、と判定した。
- **UX の判断**:
  - 値の宛先（SYSTEM_ADMIN / TEACHER / 本人）は**一切変えない**。公開するのは定義だけ。
  - 管理UI では計器が描かれる場所に「計器: ラベル — 目的。個人の比較・成績・自動判定には
    使いません」の事実行を置く（数値の隣で、それが何であるかを言う）。
  - 学習者側は UI を増やさず、マニュアル（help_kb・インスペクトから到達）に「あなたについて
    集計される計器」の節を置き、カタログの label と逐語一致をテストで固定する。
  - 「目標にせず自動ゲートにしない」（DO5）を全計器の必須宣言（`not_used_for` 4項目）へ一般化。
- **ガードレール**: カタログに無い集約 API を新設できない（既知の集約経路の網羅リストをテストが
  保持）。route 実在・非利用4項目・k-匿名と粒度の整合・学習者マニュアルとの逐語一致。

## 4. 変えなかったもの（明示）

- **RR6 の「件数は出してよい」** — 研究照合は制度指標の透明性を求めたが、確認者への件数表示は
  既存どおり（未確認 N件）。confidence / weight の生値は引き続き出さない。
- **CandidateFlow の API** — decision_context は companion primitive として置き、既存8系統の
  候補→確定フローは非改変（巻き取りは非スコープのまま）。
- **k=3 の正本・段階ラベル・閉世界語彙** — 変更なし。カタログはそれらを**参照**する側。
- **学習者向け DTO** — 一切変更なし（`/api/indicators` は新設・値を返さない）。

## 5. 次に確かめること（研究照合 §8 の pilot に接続）

- 確認者は「根拠を見る」を開くか。開かずに「次へ」を押した割合は制度指標として観察できる
  （decision_context の `evidence_shown` は affordance の有無であって開封ではない — 開封を
  記録するなら別途カタログに載せ、個人に紐づけない）。
- 一括確定の後に再審（PATCH で `review_required` / `rejected`）へ戻った配置の割合。
- 学習者が指標カタログの節を読んだか（help_usage 痕跡の anchor 単位・k-匿名）。
- これらは**目標にせず自動ゲートにしない**（IG3）。
