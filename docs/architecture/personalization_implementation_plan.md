## 1. フェーズ分割の原理

討論記録が確定させた依存関係・原則から、分割は以下の4原理に従う。

1. **基盤ガードレール先行** — 「痕跡kind登録簿＋除外許可リストの網羅ガードレールは
   どの機能よりも先に実装すべき基盤」（討論記録 §8 監査横断所見⑤・§9.6）。
   痕跡を増やす全提案（提案1・2・3・6、鏡面化）の共通前提。
2. **台帳先行原則** — 「痕跡の拡張には主権台帳が先行する」（討論記録 §8 の全員収束原則）。
   鏡面化（EX-3b）の実装前提条件は台帳v1の来歴欄整備（§9.5）。
3. **薄い層から** — 新テーブルなし（migration 0）・非LLM・既存正本モジュールへの
   接ぎ木で実現できる v1 を先に出し、運用実測を後続判断の材料にする。
4. **ガバナンス例外は後続で専用手続き** — P3 改正（手渡しチャネル）・P4 例外（封印の
   暗号消去）を要する v2 群は、vision §10 の手続きに従い**着手時に専用設計書**を切る。
   本計画では範囲の予約のみ行い、仕様を先取りしない。

## 3. フェーズ間の依存関係

```
Phase 1（痕跡登録簿＋台帳v1）
  ├─→ Phase 2（帰還の三段: leave_note kind を登録簿に登録して増設）
  ├─→ Phase 3（降下路: 楽屋の集約除外を登録簿の許可リストで構造保証）
  └─→ Phase 5（鏡面化: 台帳v1来歴欄が実装前提条件・confirm痕跡を登録簿に登録）
Phase 4（教員の弁と計器）は Phase 1 と独立（痕跡を増やさない）
Phase 5 のブリーフは Phase 1 と独立（読み時合成のみ）
```

Phase 2〜5 は Phase 1 完了後であれば順序を入れ替えてよい（相互依存なし）。
上記の順序は「学習者価値の早期投入 → 教員価値 → 対話系の新move」という投入判断であり、
技術的制約ではない。

## 4. 全フェーズ共通の設計規範（討論で確立・変更不可）

- **分業定式**: 測ってよいのは素材、書くのは本人、誤るのも本人、訂正するのは出典（§9.6）。
- **宣言された枠**: 揺さぶり系・留保系の機能は、学習者が枠の存在を常に知っている状態でのみ動く。
  無宣言の誤答混入・無宣言の出し惜しみは構造的に禁止（EX-3a/EX-3c裁定）。
- **置換ではなく結線**: 既存機構（tension/anchor digest・着地reflection・R層・D層反実仮想）で
  意図を満たせる場合、新機構を建てない（§9.6）。
- **偽の匿名を売らない**（SL1の一般化）・**AIは朗読者・計器であって著者ではない**・
  **痕跡の拡張には主権台帳が先行する**（§8 の三収束原則）。
- 既存不変条項（UC/P/KN/DM/G/W/SL、討論記録 付録A）はすべて非改変。例外は vision §10 手続きのみ。
