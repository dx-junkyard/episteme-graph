## §1 総括

vision の 14 原則は 2026-07 以降に積まれた層（理解サイクル・R層・D/SL層・W層・主権台帳・
decision_context）では丁寧に守られている。ギャップは新機能の不足よりも、**それ以前の層が
原則の外に残っていること**として現れた。6 レンズが独立に同じ箇所を指した。

**独立収束した 5 つの所見**（複数レンズが別の入口から到達）:

1. **AI が学習者について確定を書く経路が残っている。** 確認問題の合否を LLM が返し、
   トピック完了・コース完了として永続化される。LLM 失敗時は「40 字以上書けば合格」。
   不合格の回答逐語が教員向けテーブルへ流れる。（AI・学習者）
2. **切断（却下・撤回）が二級市民のまま。** 知識オブジェクト側の却下はすべて理由なしで通り、
   学習者には「自分の確定を取り下げる」語彙が無く、切断の理由は誰にも見えない。
   （教員・知識・学習者）
3. **学習者の産出物は完全に密閉されている。** 「本人が選ぶまで group を越えない」は、
   選ぶ操作が存在しないという形で満たされている。仲間はメールアドレスの一覧としてしか
   存在しない。（学習者・共同体）
4. **承認の弁がゴム印になる条件が揃っている。** 承認時に解析時の警告が空配列で消される。
   前提確定の理由欄に「確認した」旨の文がプリフィルされる。一括承認の `evidence_shown` を
   サーバがハードコードで断言する。承認の隣に否定側の検査が一つも無い。（AI・教員）
5. **時間が無い。** 再解析が `theory_claims` / `theory_components` を物理 DELETE して新 UUID で
   作り直し、FK CASCADE で学習者の再構成産出物と教員の説明・承認・引用が消える。監査台帳は
   書かれているが、オブジェクト単位で読む API が存在しない。（知識・教員）

vision が最も強く語る 3 つの像にはそれぞれ実装上の「閉じ方」がある。**可逆な循環**（§3.7）は
「論文と議論」の中でしか閉じていない。**近傍との関係でのみ成り立つ知識**（§2.1）は論文の中に
閉じていて、支持経路・反実仮想・負荷度は論文をまたぐ辺を一本も持たない。**どこまで引き受けるか
を選べる環境**（§1.1）の引き受けの段は private 一枚しかない。

## §3 判断の仕分け規則（オーナー確認を価値のあるものだけに絞る）

- **R1** 原則違反の是正は問わない。原則を書いた時点で判断は済んでいる。
- **R2** 実装方式・順序・命名・規模の切り方は担当が決める（正本モジュールが決まっている）。
- **R3** 問うのは 3 種だけ: ①不変条項の解釈を変える（例外・適用範囲の移動）②人の権利・
  制度・法に触れる（個人データ・同意・可視性）③後戻りしにくい構造（正本テーブルの意味論・
  A層/persist への手入れ）。
- **R4** 問うときは推奨を付け、原因を共有する項目は 1 つの判断に束ねる。

既知リストで「オーナー判断」札が付いていた 23 件は、この規則で §6 の 6 件に畳んだ。
