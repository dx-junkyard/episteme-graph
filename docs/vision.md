## §1 ミッション

**大学院生（研究の入り口に立つ学習者）の学習プロセスを支援する知識グラフ管理システム。**

研究者・大学院生が直面する2つの課題 —

1. **散在する先行研究の統合** — 論文は読めるが、分野の中でどこに位置づくか・他の論文と
   どの部品を共有しているかが見えない
2. **前提知識の体系的習得** — 「式変形は追えるが物理が見えない」まま論文の表面をなぞってしまう

— に対し、PDF 論文を**構造化された知識**（概念・主張・数式・導出・理論操作グラフ）へ変換し、
その構造を土台に**対話型・産出型の学習体験**を提供する。

ゴールは「答えを配る」ことではない。**学習者が自分の理解ネットワークを、論文と分野の
公共ネットワークに重ねながら育てていける環境**を作ることである。

### 1.1 一文（2026-09-04）

> **episteme-graph は、学習者が仮説を作り、根拠と結び、再現・反証・比較を行い、異議を受けて
> 改訂し、どこまでを自分の判断として公に引き受けるかを選べる、保護された認識実践環境である。
> 研究成果は、権威ある完成品ではなく、他者が検査・再解釈・再審できる来歴付きの主張として
> 共有される。**

### 1.2 対象と、対象から外さないもの

- 一次の対象は**研究の入り口に立つ学習者**（大学院生）と、その学習を支える教員・研究室である。
- ただし**研究職へ向かわない学習者を対象の外に置かない**。修士の大半は研究に触れずに出る。
  砂場（private / group）で産出・確認・改訂して完結する学習は、公開へ進まない**正規の経路**で
  あって未完ではない。教育の目的は研究者を作ることではなく、分野の外にも持ち出せる
  **判断能力（epistemic agency）** を育てることにある（§3.7）。
- 教育と研究は**一つの台帳に混ぜて**再統合するのではなく、目的の異なる三領域（学習記録 /
  研究記録 / 制度監査）を**分離してリンク**することで接続する（§5.4）。

## §2 知識観 — このシステムが前提とする認識論

システムの設計判断はバラバラの UX 選好ではなく、一貫した知識観から導かれている。

### 2.1 知識は近傍との関係でのみ成り立つ — 全体の完成形は無い

知識ネットワークは「全体で一つの完成形」があるのではなく、近傍との関係でのみ成り立つ
小さなネットワークが幾重にも重なり、全体として堅牢な「一つに**見える**」状態を目指す
（[knowledge_network_vision.md](features/knowledge_network_vision.md) §1-6）。

- だから **踏破率・カバー率を数値にしない**（Field Atlas）。
- だから **全体グラフを一枚に描く画面を作らない**（KN-1「神の視点を作らない」。
  すべてのネットワーク表示は論文起点・パーツ起点・学習者起点の egocentric）。
- だから 分からない場所へは数値やランキングではなく「**旅**」（journey: 論文ローカルグラフ →
  同一性リンク → 共通部品ハブ → 分野骨格 → 本人の別ノード、の事実文による経路提示）で向かう。

### 2.2 検証と合意は別の軸 — 検証を単一ブールにしない

D層（認識的地位台帳）は「みんなが認めている」（合意の強さ）と「確かめられている」
（検証の強さ）をデータ構造レベルで分離した（[doubt_layer_issues.md](features/doubt_layer_issues.md)）。
検証は真偽の一bitではなく **`verification_scopes` の配列**（どの条件・領域・精度で
確かめられたか）で持ち、全称検証（「証明済み」）を構造的に禁止する。

SL層（賭け金の台帳）はこれを反証側へ双対拡張した: 「何が起これば覆るか」（反証条件）・
「覆れば何処まで届くか」（観測反実仮想）・「どこが一点吊りか」(独立支持経路) ・
「どこで確かめられていないか」（晴れ間）（[stakes_ledger_design.md](features/stakes_ledger_design.md)）。

### 2.3 スコープの空欄は失敗ではなく発見

「検証スコープが空欄」「地図に配置できない論文」「コースと骨格の対応がゼロ」は、
エラー表示や警告色の対象ではなく**正常な状態であり発見**である
（D層 / [knowledge_landscape_design.md](features/knowledge_landscape_design.md) LS「配置不能は信号」 /
[atlas_binding_lifecycle_design.md](features/atlas_binding_lifecycle_design.md) AB1「一致ゼロは正常」）。
反復する「置けなかった」だけが候補として浮上し、地図を育てる入力になる
（[category_gap_candidates_design.md](features/category_gap_candidates_design.md)）。

### 2.4 コーパスは分野ではない — 閉世界の正直さ

システムが知っているのは高々数十〜数百論文のコーパスであり、分野そのものではない。
検証記録の不在について言えるのは「**このコーパスの中では**検証記録がありません」だけで、
「この分野では未検証」「誰も検証していない」という語彙は構造的に禁止する（SL1）。
晴れ間は発見の候補地であって発見ではない — 空の穴だと確かめるのは望遠鏡ではなく人間の仕事。

### 2.5 表現の多様性は情報 — 正規化は追加であって置換ではない

論文ごと・分野ごとの表記の違いを潰すと、その論文との接続が悪くなる。だから:

- `theory_claims` は原文 `text` と `normalized_text` を**両方**保持する。
- 「実は同じもの」は**マージではなくリンク**（`element_identity_links`）で表現し、
  各論文側のインスタンスは何も書き換えない（KN-2）。共通部品ハブ（L層 `library_entries`）が
  「この分野ではこう呼ぶ / この論文ではこう書く」の対応表を持つ側になる。
- 標準化判定は LLM 単独主張を幻覚とみなし、LLM 事前知識 + 分野ライブラリ凍結版 +
  コーパス内反復の**三角測量**で行う。コーパス内で反復するのに外部標準が無い
  `emerging_common` こそ本システムの発見的価値の在り処。

### 2.6 知識は時間の中で変化する生き物

式・概念は完成品ではなく、適用範囲を持ち、破れ、派生する。V層（共有物のバージョン管理）の
不変スナップショット、`theory_review_events` の全監査記録、versioned な地図骨格は、
「共同体がいつ何を受け入れたか」を後年たどれる一次史料としての側面を持つ
（[vision_expansion_proposals_2026-08.md](features/vision_expansion_proposals_2026-08.md) 提案4「時間レンズ」が将来形）。

### 2.7 結合には答責性が要る — 切断は結合と対等（2026-09-03/04 追補）

結合（「これは同じ」「この式はこの claim を支える」）の確定に情報量があるのは、遅いからでも
人間が押したからでもなく、**その表明を後から取り消したときに失うものがあり、訂正・撤回の
宛先が記帳されているから**である（答責性）。生成 AI が起こしたのは「結合がタダになった」
ことではなく、**未検証の主張を作るコストだけが崩落し、検証コストは同じ速さでは崩落しなかった**
非対称である。だから:

- **切断は結合と対等の一級市民**。「これは同じではない」「この経路は行き止まりだった」
  「私はこれを取り下げる」は、理由と帰属を伴って結合と同資格で記帳される（D層の疑義・
  却下・撤回・SL層の反証条件はその実装）。dismiss を保持するだけでは足りない。
- **免疫記憶（却下の記録）は近傍ごとに持つ**。ある研究室・ある条件で切られた結合は、
  別の近傍では `rejected` にならない（伝播するのは「近傍 A・条件 c で切断された」という
  来歴付きの警告だけ）。共有地全体の負例集合を作らない。異端は同じ共同体の再審ではなく
  別の近傍から戻ってくる。
- **砂場では却下された結合を張り直せ、切断の理由が見える**。免疫記憶は候補生成を絞る
  道具ではなく、切断の理由を学習者に見せる道具である（原則8「出所の正直さ」の切断側）。
- **足場と主張は別の台帳**。学習者へ通すための単純化（段階的翻訳）は捨てられる道具で
  あって答責の対象にならず、共通部品として還流させない。

### 2.8 検証可能性は一本の軸ではなく、検査器に相対的である（2026-09-04 追補）

「検査に開かれている」は少なくとも次を区別する: **機械的再実行**（同じ入力・環境で同じ出力）/
**分析妥当性**（コード・分析が主張を実際に支えるか）/ **経験的再現**（新しいデータでも
得られるか）/ **外的妥当性**（別の対象・時点・文脈へ一般化できるか）/ **解釈妥当性**
（史料・概念・規範的前提からその読みが正当化されるか）。機械検査の成功を「真」に昇格させては
ならない（コンテナが再実行できることと、出力が論文の記載と一致することは別の検査である）。

何が「機械検査可能」かは検査器の進歩で動く。したがって検証状態は静的な三段階ではなく、
**claim type ごとの検証契約**（必要な証拠・独立性・未充足条件・既知の反例・再審条件を先に
宣言し、完了した検査を紐づける）として、時点付きで記帳する。公開は真偽の認証ではなく、
**現在の検証状態を正確に伝える行為**である。安くなるのは検証全体ではなく形式化できた部分で
あり、データ生成・測定妥当性・史料文脈・倫理・境界条件・別説明との比較には人間の判断が残る。

## §3 学習観 — 理解は産出から始まる

### 3.1 ELICIT-first — 開示の前に学習者自身の産出を挟む

2026-08 の7分野専門家パネル討論で、脳科学（予測誤差が符号化をゲートする）・学習科学
（pretesting effect）・宇宙物理（研究者は式を自分で導いてから紙面と照合する）・ゲームデザイン
（地図を描かせる）の4分野が**独立に同じ構造**を提案した（独立収束は実装価値の強い証拠）。

- R層（再構成ループ）: ELICIT → CAPTURE → DIFF → REVEAL → SELF-CHECK → REVISE/DESCEND
  （[reconstruction_loop_design.md](features/reconstruction_loop_design.md)）
- 理解サイクル: **OPEN → ELICIT → DIFF → REVEAL → UPDATE → ANCHOR → LEAVE → REVISIT**
  を一級の体験とし、AI をその補助レイヤーとして再配置する
  （[understanding_cycle_design.md](features/understanding_cycle_design.md)）

ただし **opt-in**（UC1）: 予測を挟む読み方は「精読モード」の明示トグルのみ。通覧という
読書実践に摩擦税をかけない。自分で選んだ縛りは没入を生み、押し付けられた縛りは離脱を生む。

### 3.2 DIFF は採点しない — 権威は常に出典

構造照合の判定は「食い違いの可能性」の**仮説文体**で提示し、正解/不正解・点数・正答率を
出さない（UC2）。判定を authoritative に見せず、権威は常に出典リビール（原文）に置く。
自由記述の予測は判定せず**並置**のみ（機械にできない判定を偽装しない）。

### 3.3 違和感と問いは理解の証 — そして構造に帰属する

- tension（違和感）は「未理解の穴」ではなく「**理解した上での引っかかり**」であり、
  それを生成するのは人間。LLM は候補を出すだけで、本人の確定（そう、これ / 違う）を
  経てのみ痕跡になる（B層 TensionMining, P1）。
- 問いは質問文の保存ではなく「提示された情報構造の**どこに・どう**引っかかったか」
  （anchor × doubt_type）として記録する（構造帰属型の問い記録）。
- 誤解は除去すべきバグではなく「スコープを誤って拡張された局所的に正しい信念」であり、
  洗練の素材（knowledge in pieces）。D層の scope 語彙は学習者の理解にもそのまま適用できる。

### 3.4 セッションの間は埋めない

問いを持ち越して終え（LEAVE）、次回その問いから再開する（REVISIT）。その間、
**システムは何もしない**（UC4）: 督促・プッシュ通知・連続日数・未消化バッジ・忘却曲線を
作らない。「間」を埋めないこと自体が設計である（オフラインの統合に処理を委ねる）。

### 3.5 学習を演技化させない

バッジ・ランキング・進捗率・的中数を出さない（P7 / UC9）。学習者に見せるのは
数値ではなく段階ラベルと事実文。教員に対しても同じ（多くの数値は教員にも見せない —
評価装置化・監視化の防止）。

### 3.6 沈黙適応をしない — 学習者モデルの推定で挙動を変えない

能力・理解度・スキーマ距離の推定で提示内容・提示順・対話方針を暗黙に変えない（UC5）。
初回利用でも過去データからの推定入口分岐を作らない（UC7）。個人化はすべて
「本人の産出物を本人に見せる」形か、本人が選ぶ提案型でのみ行う。
見えない並べ替えは「誰も宣言せず誰も異議を申し立てられない正典形成」である。

### 3.7 学習は頂点のない可逆な循環 — 階段ではない（2026-09-04 追補）

学習は次の**可逆な循環**として表す（研究調査による再審 §6.2）:

`問い/予測 → 産出 → 根拠への接触 → 比較/再現 → 異議 → 改訂/保留/撤回 → 必要なら公開 → 再審`

- この循環には**頂点が無い**。public へ進まない完結も、public から退くことも、同じ対象へ別の
  近傍から戻ることも正規の経路である。「答責の階段を上がる」を教育の目的にしない —
  頂点に職を置くと、研究職へ向かわない学習者にとって教育は未完で終わり、上がるほど
  失うものが増える階段は上がることを躊躇させる。
- **「産出」はクリック数や文章量ではない**。根拠との結合・比較・自己説明・改訂を生む
  **認知行為**として定義する（active learning の効果は「何かを作らせた」ことではなく、既有
  知識との統合・説明・比較・フィードバックを含むかで決まる）。
- **砂場は放任ではない**。失敗を保存するだけでは学習にならない。何を試し、何が崩れ、どの
  証拠で更新したかを比較でき、必要なときに足場掛け（構造の降下路・出典リビール・教員の
  介入）を得られることが、生産的失敗の条件である。
- **転移は自動ではない**。「答責の作法はどの職にも持ち出せる」と断定せず、異分野の事例で
  同じ判断構造を再適用する転移課題を設け、実際に持ち出せたかを確かめる（未実装、§9）。
- **再現は教育の一部になりうる**が、既知の効果ではなく**検証すべき設計仮説**である。
  人文・理論・実験・計算で「再現」の意味を分ける（一次史料の文脈判断 / 再導出 / 再測定 /
  再実行）。
- 学習者に**独立した理解の証拠**を求めるのは、AI の出力を見る前の予測・別の証拠での
  spot check・条件を変えた再実行・誤った AI 出力の診断・根拠を閉じた後の説明といった
  **選択的**な手段であり、全件に課して摩擦税を作らない（UC1 の opt-in と整合）。

## §4 AIの役割 — 「AIは候補まで、確定は人間」の根拠と条件

全レイヤーで最も強く反復される原則。AI（LLM）の出力は**常に candidate** であり、
確定という行為は人間（学習者本人 or 教員）に留保される。2026-09-04 の再審で、この原則の
**根拠**と**確定の条件**を次のように精密化した（原則自体は維持）:

- **根拠は能力ではなく宛先**。AI が人間より劣るからではなく、訂正・撤回・制裁の宛先が
  人間（と、人間が属する手続・制度）にしか無いからである。委譲と記帳によって将来その
  宛先が移動しうることは原則の内側に含める（自律ではなく委譲の問題）。
- **人間のクリックを正当性と誤認しない**。人間が時間・能力・情報・拒否権を欠けば、承認は
  ゴム印か、事故時にだけ責任を吸収する置き場（moral crumple zone）になる。自動助言は
  人間の正しい判断を覆すことがある（automation bias）ので、「確定は人間」は**確定者を
  責任の置き場だけにしないための条件**を伴わなければならない。

> **改訂原則1（2026-09-04）:** AI は生成と検査を担いうる。確定は、十分な能力・情報・時間・
> 拒否権を持つ人間の判断を含み、後から再構成・異議申立できる手続にのみ与える。

**確定を再構成可能にする最低限の記帳**（一括確認・承認・凍結・公開のすべてに適用）:

1. AI・人間・外部ツールがそれぞれ行った操作（誰が手を動かし、誰が判断したか）
2. 確定者に**提示された**根拠・代替案・既知の不確実性（何を見て判断したか）
3. 承認しない選択（却下・再検討・後回し）が可能だったか
4. 誰が再審を開始でき、どの経路・どの証拠で覆せるか

一括承認（「次へ」＝承認とみなす等）はこの記帳なしに行わない。
実装上の正本は [確定文脈の記帳](features/decision_context_design.md)（`core/decision_context.py` が
`theory_review_events` の payload に `decision_context` を積む。適用先は [リリース前の確認](features/release_review_flow_design.md)
§6 追補と説明レビューの一括承認）。影響機能の整理は
[原則改訂の影響整理 2026-09-04](architecture/vision_revision_impact_2026-09-04.md)。

AI の役割は候補生成に限らない。**検索・形式化・再実行・矛盾探索・検査計画の下書き**にも使う。
AI の関与を理由に自動棄却せず、人間の関与を理由に自動承認もしない。学習者が「自分で確かめた」
と言えるのは手を動かしたからではなく、**判断の宛先が自分になった**ときであり、手を動かした
主体（本人 / AI / 他者）は来歴に記帳する。

| 側面 | 規約 |
|---|---|
| 出力の地位 | 常に `status='candidate'`（tension / anchor / 前提 / 疑義スコープ / 同一性リンク / 配置 / 説明 / 図解析 / 反証条件 … すべて）。AI 出力で `source_backed` や confirmed を自動付与しない |
| 根拠 | evidence-based: 逐語 `evidence_quote`（verbatim 検査＝捏造ガード）+ `reason` + `confidence` を必ず付与。根拠が無ければ生成しない（無理に配置・創作しない） |
| 文体 | 断定しない。「〜の可能性があります」の仮説文体。AIに疑わせない・「反証不可能」と断定させない（SL2） |
| 幻覚対策 | 三角測量（LLM 単独主張は `unknown`）・閉世界語彙の固定・スキーマ検証 + repair（2回失敗は情報を落とさず `unclassified` で保持） |
| 配置 | 同期パスに LLM を入れない（P6/UC8）。体験の骨格は非LLM・決定論で完結し、LLM は非同期の候補生成か明示操作のみ。LLM 失敗時は degraded 縮退で体験を止めない |
| 役割 | チャット（回答装置）を主役にせず、**理解行為を主役に**。AI は Elicit（問いを引き出す）/ Diff（差分候補）/ Explain（要求時の説明）/ Reflect（言語化の補助）に分解されて配置される |
| コスト | すべての LLM 呼び出しに日次上限（CostGate）と U層計測（usage_context）。モデル選択は M層の単一正本（`llm_policy`） |

「モック」や「とりあえず自動確定」を許さないこの流儀は、初期の EPISTEME_MOCK 台帳
（MOCKS.md）が candidate/status 遷移パターンへ発展的に統合されたものと読める。

## §5 人間の役割 — 教員・学習者・共同体

### 5.1 教員は「確定の弁」であり監査役

生成は AI が大量に行い、**共有された知識になる直前に必ず人間の弁がある**:
claim 承認・説明の査読（C層）・同一性リンク確定（W層）・骨格の凍結（Atlas）・
配置の確認（ランドスケープ）・カテゴリギャップの採用・反証条件の確定（SL層）。
弁の操作はすべて `theory_review_events` に**帰属付きで監査記帳**される（匿名の疑義・
匿名の承認は存在しない）。承認と疑義は対等の一級市民である（C層 ⇄ D層）。

弁が**ゴム印にならない条件**（§4 改訂原則1）を弁の側にも課す: 弁の前には提示された根拠と
代替（却下・再検討・後回し）があり、弁の後には再審の経路が残り、監査記録から「何を見て
何を選べたか」が再構成できること。**弁の収支** — 新機能は教員の確定行為の総量を増やさない
（作るなら既存を畳む）— は第15原則の候補として §6.2 に記録する。

### 5.2 学習者は主権者 — 監視しない・評価に使わない

- 学習者の痕跡（問い・違和感・予測・意図）は**本人のみ可視**（PN-1）。
- 教員へ渡るのは **k-匿名集約のみ**（k=3 の正本は `core/privacy.py`、n<3 セル非表示、
  人数はレンジ表示）。個別履歴の閲覧経路を作らない。**評価利用禁止**（P3）。
- 学習者の重ね合わせから浮かぶのは教育的知識（どこで橋を架けるか・どこでつまづくか）で
  あって、ドメイン知識ではない。コーパス / 専門家 / 学習者の3系統の重ね合わせを
  混ぜない（KN-4）。学習者の素朴な連想をドメイン知識候補に自動昇格させない。
- 削除ではなく状態遷移: dismiss・書き直し・撤回も履歴として保持される（P4）。
  本人による「地図には反映しない」（map_exclude）のような**訂正主権**を提供する。
- **学習者は答責を負わない砂場のノード**である（2026-09-03 第3類型）。撤回しても何も失わ
  ないことが教育の条件であり、産出物は本人が選ぶまで group を越えない。未検証の産出物に
  本人の名前が付いて public に永続することを、既定にしない。
- **研究への寄与は学習の副産物であって目的ではない**（2026-09-04 再審）。学習者の確認記録を
  研究の検証の下書きとして使う経路を開く場合は、①授業の学習目標だけで完結し研究利用を
  断っても不利益がない ②研究への流用は明示的 opt-in で対象・公開範囲を再選択できる
  ③教員または独立者が品質を確認し学生の記録をそのまま証拠にしない ④貢献を名前付きで
  credit し著者資格とは別に記録する ⑤訂正・公開撤回・異議申立の経路を残す、の五条件を
  満たす（未実装、§9）。「教育が研究の検証労働を供給する」を再統合の経済的根拠にしない。
- **人に関するデータの保持と、知識オブジェクトの履歴保全は別**。「情報を落とさない」
  （原則3）は知識オブジェクトの原則であり、個人情報・撤回要求・保持期限と衝突する場合は
  消去または非可逆匿名化を認める（アカウント削除の墓標化がその第一の実装）。

### 5.3 共同体 — 重なるが同じではない理解の並存

同じ論文の同じパーツへの各人の理解は「重なるが同じではない」。だから一つのコンポーネントに
複数の説明バージョン（標準 + 教員の独自解釈）が**並存**し、マージされない（C層）。
承認は説明バージョン単位で、重みは段階ラベル（「専門家3名が承認」）であり数値スコアではない。
引用は帰属付きで記録され、versioned な共有（V層）が「所有者の一方的な更新・削除」から
消費側を保護する（発行版へのピン留め・削除猶予・adopt の明示同意）。

- **開放は読む側と砂場、成員資格は確定側**（2026-09-04）。科学が歴史的に開放したのは読むこと
  であり、確定すること（成員資格・査読者の選任）は常に閉じていた。これは後退ではなく明示。
- **異議のコストは設計で下げられるが、UI だけでは下がらない**。役割化（輪番の切断者）・
  帰属記帳と開示の分離（開示を可視性勾配に載せる）・ゼミ横断のレビューは補助策であり、
  単一指導者が学位・資金・推薦・研究アクセスを同時に支配しない**制度構造**（複数指導者・
  研究室外の定期レビュー・独立 ombuds・報復の事後監査・別 group へ安全に移れる経路）の
  上でのみ機能する。システムはこの制度構造を前提として書き、代替すると称しない。

### 5.4 三領域を分離してリンクする — 教育と研究の結節点（2026-09-04）

教育と研究は、一つの台帳に混ぜることでなく、**目的の異なる三領域を来歴付きで接続する**
ことによって再統合する。「砂場由来 / 答責由来」のタグだけで同じ台帳に載せる案は採らない —
目的・権限・保持期間・検索可能性・公開の法的・社会的効果が異なるため、分離してリンクする
（原則7「リンクであってマージではない」の制度への適用）。

| 領域 | 第一目的 | 既定の保護 | 他領域への接続 |
|---|---|---|---|
| 学習記録（interest_traces・再構成・意図 …） | 判断能力の形成 | 本人主権・可逆・評価利用禁止（PN-1 / P3） | 本人の明示同意による複製と来歴リンクのみ |
| 研究記録（claim・台帳・承認・疑義 …） | 検査可能な知識の共有 | claim type 別の検証状態・訂正・撤回・再審 | 学習素材として参照可能（読む側は開放） |
| 制度監査（U層・観測基盤・k-匿名集約 …） | 権力・負担・偏りの検出 | 個人ランキング禁止・小集団保護（k=3） | 指標の定義・用途を公開し、独立監査に再検査を許す |

可視性は一軸に畳まない。少なくとも「閲覧できる audience / 名前を見られる audience / 引用・
再利用できる条件 / 評価に利用できるか / 外部 index や外部 AI に渡るか / いつ撤回・凍結
できるか」を独立に扱う（現行の private / group / public はその第一軸）。

### 6.1 数値の宛先と用途（原則4の改訂内容）

| 宛先 / 用途 | 規約 |
|---|---|
| 個人（他者を測る） | 比較・ランキング・成績・推薦に**使わない**。学習者個人の産出量・切断された回数は**測ってはならない** |
| 本人 | 自分の資源（残りの注意・日次上限の残数）と履歴は本人にだけ見え、訂正できる |
| 制度（運営者） | 小集団を特定できない集約（k=3）で観察する。**目標にせず、自動ゲートにしない**（DO5 の一般化） |
| 全当事者 | 指標の**定義・収集法・保持期間・意思決定への使い方・副作用レビュー**を読める（機械可読の指標カタログ + マニュアル） |
| 独立監査者 | 集計と運用を再検査できる（権限分離された全体視点） |

「測れないが書く」成功条件（学習者が共同体の基準を疑えるようになったか・異議を受けて壊れ
なかったか）は、測れないと明記して置く。忘れないためであって、代理指標を作るためではない。

### 6.2 第15原則の候補（検討記録・未採用）

| 候補 | 内容 | 由来 | 状態 |
|---|---|---|---|
| 入口の正直さ | 取り込む論文・資料の完全性と出所（取得元・改変の有無）を記帳し、内部産出物の還流にも入口の弁を置く | [2026-08-29 討論](architecture/vision_review_debate_2026-08-29.md) | 候補。URL 取得・ディスカバリーの許可リスト・`documents.source_url` が部分実装 |
| 弁の収支 | 新機能は教員の確定行為の総量を増やさない。作るなら既存を畳む。本人にだけ見える注意の予算（在庫制） | [2026-09-03 討論](architecture/vision_future_debate_2026-09-03.md) §7.2 | 候補。U層 forecast（`{show, message}` のみ）が部分実装。原則1改訂の「確定者が時間を持っていたか」と同根 |

いずれも原則1〜14 のどれかの具体化として書けるかを見極めてから採用を判断する
（原則の本数を増やすこと自体は目的にしない）。

既知の効果として書かず**検証すべき設計仮説**として設計書に明記する。

## §10 本書の運用

- 新しい層・機能を追加したら: ①専用設計書（不変条項付き）②
  [レイヤー索引表](architecture/layer_registry.md) への行追加 ③ CLAUDE.md の節追加 ④
  本書 §8 の該当機能群への1行追記、を同時に行う。
- ドキュメント運用規約（機能解説の同時更新・設計書の状態ヘッダ・想定 migration 番号を書かない・
  リポジトリ外正本の禁止・カウント記法）の正本は
  [開発運用チェックリスト](development_checklist.md) §5 — 機械検証つき
  （`backend/tests/test_docs_registry_guardrails.py`）。
- 本書 §6 の原則に**例外を作る**設計をする場合は、例外であることと理由を設計書に明記する
  （黙って逸脱しない）。原則3・13 の「人に関するデータ」例外も、個別の設計書で保持期間と
  消去手続を明記した上でのみ使う。
- 原則そのものを改訂するときの型（2026-09-04 に確立）: **討論（発散）→ 関連研究との照合
  （支持 / 条件付き支持 / 要修正 / 未証明を区別）→ 本書 §6 の改訂 → 影響を受ける機能の整理 →
  設計書追補 → 実装 → 実装記録**。討論の合意だけで原則を書き換えず、研究照合で「未証明」と
  された機構は §9 に仮説として置く。
- 本書は「なぜ」の正本であり、「どうやって」（テーブル・API・画面）は書かない。
  実装詳細が書きたくなったら、それは各設計書に置く。
