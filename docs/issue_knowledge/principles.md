# 解決原理（型を横断する条件付きの解決知識）

[← 課題ナレッジの入口](README.md) ｜ [分類体系](taxonomy.md) ｜ [辞書](dictionary.md) ｜ [索引](index.md)

> **状態:** 生きたリファレンス（2026-09-27 新設・2026-09-30 `route-all-surfaces-through-one-point` を追加。probe-agent の「課題・ソリューションの抽象化層」検討
> （IP-20260927-02）を本リポジトリの既存の層に照らして当てはめたもの。規則は [taxonomy §9](taxonomy.md)）。
> 辞書の**型**が「どんな原因の一般形か」を持つのに対し、本書の**原理**は「何を守るため、どの条件で、
> どの部品を併用し、どの派生形を選ぶか」を持つ。原理は型を横断して束ね（多対多）、エントリは
> `resolution.principles` で原理を参照する。**参照するエントリの無い原理は置かない**（ガードレール）。
> 読んで当てるのはエージェントで、人の確定は待たない（人は問題が明らかになったときだけ介入する）。
> 成立（`consulted` が別々の型から 2 件以上・適用後に同型の見逃しなし）／暫定の区別と、原理ごとの実際の利用
> （直す前に読んで選んだ `consulted` ／ 直した後に抽出した `extracted`）は [index.md §15](index.md) が機械生成する。

各原理の見出し直後に次の表を書く（行の見出しは固定・機械検査）。

| 行 | 書くこと |
|---|---|
| 原理 | 機能名・層名・ファイル名を含まない一文。何をどうする原理か |
| 守る条件 | 不変条項・原則の ID（vision §6 の原則 N・各層の P* / KO* / CR* / DM* 等）。原理は「原則 X を仕組み M の下で守る手段」 |
| 破られる条件 | どの状況・どの仕組みで守る条件が破られるか。独立に破る要因は分けて書く |
| 当たる型 | [辞書](dictionary.md) の型 slug（実在検査）。1 原理は複数の型に当たってよい |
| 併用する部品 | **補完関係**の部品。「どれか 1 つでは何が残るか」を根拠エントリ付きで書く（1 つ選べば足りる、と読ませない） |
| 派生形 | **選択関係**の派生形。どの状況でどの形を採るか（選択条件） |
| 非適用 | 同じ形でも当てない場合。当てると別の型（責務の二重化・投影の混同）になる場合を含む |
| 反例 | 部品ごとに、何を壊してみれば確認になるか（処方。型の「確かめ方」は型単位、ここは部品単位） |
| 正本 | 部品を実装した正本モジュール・設計書。原理文書は正本の代わりにしない |

事例ごとに「採った部品・派生形・固有の差分」はエントリ側の `resolution.principles[].note` に書き、索引が
原理ごとに並べる（ここに事例を列挙しない）。

## 再実行と同一性

#### sync-by-stable-key-and-protect-human-decisions

| 行 | 内容 |
|---|---|
| 原理 | 再実行や取り込みは前回の成果を消して作り直さず、内容由来の同一性キーで既存の行と突き合わせて同期し、人が確定した列を保護し、成果を指す参照を結び直す |
| 守る条件 | 原則 1（確定は人・再構成可能な手続）/ P4（情報を落とさない）/ KO3（再解析は DELETE しない。FK 経由の CASCADE も含む）/ LS3（再生成で倒してよいのは候補だけ） |
| 破られる条件 | 再実行が「前回の成果を消してから書く」経路で実装されているときに、次のどれか 1 つで破られる。①識別子が出現順など実行のたびに変わる材料から作られる ②人の確定が成果と同じ行・同じ列に同居している ③他の記録（説明・台帳・注釈・痕跡）が成果の行を FK や ID で参照している ④解析時点の値が投影に焼き込まれ、現在の判断より優先される |
| 当たる型 | `reexecution-overwrites-human-decision` / `delete-cascade-loses-derived-records` / `id-not-stable-across-versions` / `stale-derivative-served` |
| 併用する部品 | ①内容由来の安定キー（無いと突き合わせができず全件が新規になる: IK-0106）②DELETE ではなく「一致は同じ ID で更新・不一致は superseded の刻印・新規は INSERT」（無いと連鎖で派生記録が消える: IK-0002・IK-0109）③人が触った列の保護（無いとキーが一致しても本文・審査状態が AI 出力で上書きされる: IK-0108・IK-0110）④派生物の再係留か読み時の合流（無いと旧 ID を指す参照や焼き込み値が現在の判断に勝つ: IK-0106・IK-0302）。4 つは補完で、どれか 1 つでは残りの破られ方がそのまま残る |
| 派生形 | 成果の行に人の列が同居する表 → ③は列単位の保護（触った列だけ不変） / 派生物が別表で位置キーを持つ → ②は位置キーの upsert と FK の SET NULL（余剰行だけ削除） / 取り込みのように「束に無い行を表示対象から外す」要求がある → 人が確定した行を取り込み側で合流させてから同期に渡す（同期は非改変） / 焼き込み値と現在値が別の場所にある投影 → ④は読み時に人の語彙だけ現在値を優先し、解析由来の語彙は焼き込み値を保つ |
| 非適用 | 人の判断を持たない純粋な派生構造（リンク表など）は削除して作り直してよい（設計で明示する）。draft/freeze の版管理は同期ではなく版の追記であり、`revision_store` の対象で本原理の対象ではない。人の確定を持たない一時キャッシュも対象外（無効化で足りる） |
| 反例 | 同じ入力で再実行して ID が変わらないこと（①②）/ 承認済みの行の本文を変えた入力で再実行して承認と本文が残ること（③）/ 旧 ID を参照する説明・台帳・注釈が再実行後も解決できること（④）/ 空入力で再実行して生きている行が消えないこと（②）/ 焼き込み値と現在値が食い違う投影で、承認後にレビューが閉じること（④）。複製 DB か scratch DB で実測する |
| 正本 | `backend/core/knowledge_objects/stable_key.py` / `sync.py` / `remap.py`、`backend/core/document_pipeline/persistence.py`、`backend/core/candidate_flow.py`（`select_supersedable`）、設計書 `docs/features/knowledge_objects_design.md` §12・`docs/features/candidate_flow_design.md` |

## 条件の伝達と強制

#### enforce-condition-in-query-with-required-argument

| 行 | 内容 |
|---|---|
| 原理 | 権限・可視性・対象範囲の条件は呼び出し側の善意に頼らず、必須引数として受けて問い合わせの内側で強制し、判定できないときは閉じる |
| 守る条件 | CR1（document 可視性が唯一のゲート・fail-closed）/ DM1（該当ゼロでも他スコープへ無断でフォールバックしない）/ KO10（学習者向けの DTO に内部列を出さない）は隣接する別原理の守る条件で、ここでは「範囲を広げない」側だけを担う |
| 破られる条件 | ①条件が省略可能な引数か既定値付きで、渡し忘れが型に現れない ②条件の判定と問い合わせが別の層にあり、新しい経路が判定を通らずに問い合わせへ届く ③役割（教員か否か）だけを見て対象単位の所有・共有を見ない ④空集合や解決不能を「制限なし」に倒す |
| 当たる型 | `condition-not-propagated` / `scope-widened-silently` / `entry-scope-mismatch` |
| 併用する部品 | ①必須キーワード引数（省略すると例外。無いと新経路が条件を渡し忘れる: IK-0119）②問い合わせの内側での集合強制（無いと後段が引数を読まずに全域を返せる: IK-0119）③空集合は問い合わせを発行せず空で返す（無いと「対象なし」が「制限なし」になる）④不在と不可視を同じ応答にする（無いと存在の列挙が漏れる）。①だけでは後段が引数を無視する経路が残り、②だけでは呼び出し側が全域集合を渡せる |
| 派生形 | 検索（RAG） → 可視集合を必須引数で受け、`None` はテスト専用と明示する / URL に course が含まれる直読み → 全域の可視集合ではなくその course の sources に絞る（コースへの正規アクセスが開示根拠） / 書き込み経路 → 対象の編集権限を確かめる共通関数 1 本をすべての経路が通す（IK-0316） / 持ち出し・記帳を伴う受け口 → 対象単位の閲覧判定に加えて監査を残す（IK-0012） / 候補表・文脈の組み立て → 素材の集合と可視集合の積を取る（IK-0119） |
| 非適用 | 対象が URL で一意に決まり、既に対象単位のゲート（`_ensure_document_editable` 等）を通っている管理経路に同じ判定を重ねない（責務の二重化）。学習者向けの列の絞り込みは条件の強制ではなく投影であり、別の原理。役割ゲート（`_require_teacher`）は本原理の代替にならない（③） |
| 反例 | 不可視の document を含む集合で呼んで結果に混じらないこと（②）/ 引数を省略して呼んで例外になること（①）/ 空集合で問い合わせが発行されないこと（③）/ 不在の ID と不可視の ID で応答が同一であること（④）/ 役割だけ満たす別ユーザーで書き込み経路を叩いて拒否されること（③） |
| 正本 | `backend/api/services.py`（`list_visible_document_ids` / `resolve_document_access` / `search_chunks_with_metadata(allowed_document_ids=)`）、`backend/api/routes/lecture_studio/_shared.py`（`_ensure_chunk_editable`）、`docs/backend/rag-chat.md`（Phase 0 可視性フィルタ）、`docs/features/corpus_roaming_design.md` CR1 |

## 規則の置き場所

#### route-all-surfaces-through-one-point

| 行 | 内容 |
|---|---|
| 原理 | 同型の是正が複数の面・複数の周にわたって出たら面ごとに塞ぐのをやめ、規則を全経路が必ず通る 1 箇所に置き、新しい面がその 1 箇所を迂回できないことを全経路を走査する検査で固定する。上流の損失なら下流の読み替えではなく上流の入力と条件を変える |
| 守る条件 | 原則 4 改訂（数値の用途と粒度を統治する）/ PL7・TM10（内部 ID を表示ラベルにしない）/ DM1（スコープを無断で広げない）/ DM4・DA4（問い返しは 1 つ）/ P4（情報を落とさない） |
| 破られる条件 | ①規則が消費面ごとに書かれ、新しい面は規則を持たずに生まれる ②面ごとの規則の語彙・優先順位が少しずつ食い違う ③規則の判断が生成器（LLM）の自制や継ぎ足しの指示に任され、規則同士が衝突する ④上流の損失を下流の各面が読み替えで補い、損失そのものは戻らない |
| 当たる型 | `rule-enforced-per-surface` / `upstream-loss-masked-downstream` / `guardrail-does-not-cover-new-path` |
| 併用する部品 | ①1 箇所の正本（純関数・語彙の正本。無いと面ごとの語彙が食い違ったまま残る: IK-0579・IK-0580）②全経路が通る結線（ルートクラス・解決関数・生成後の組み立ての 1 点。無いと正本があっても新しい面が呼ばずに済む: IK-0579・IK-0582）③全経路を走査する横断検査（無いと ②を迂回する新しい面が緑のまま入る: IK-0579）④旧来の面ごとの実装を委譲だけにする（無いと 2 つの規則が並走して片方だけ直る: IK-0579）。①だけでは結線が漏れ、②だけでは検査が無く、③だけでは置き場所が無い |
| 派生形 | 出力の遮断 → 戻り値の直列化の直前に射影を挟むルートクラス（番地のキーは残す）/ 対象の選択 → 段順の解決関数 1 つと衝突時の fail-closed（推測で最初の 1 件を選ばない）/ 生成物の形 → 生成後・保存前の 1 点でサーバが区画を組み立てる（保存形は不変）/ 上流の入力 → 損失の少ない形式を既定にし、倒し先への切り替えは受理前に同期で確かめて呼び出しに上限を置く |
| 非適用 | 面ごとに意図的に違う判定（宛先別の段階ラベル・教員と学習者の粒度の差）は 1 つに潰さず、正本の中に系統別の定数として並べる。是正が 1 面だけに出た段階では 1 箇所への移設を急がない（型が見えるまで単点修正で足りる） |
| 反例 | 規則を持たない経路を試しに足して横断検査が赤になること（③）/ 旧遮断器・旧経路が正本と同一のオブジェクトを参照していること（④）/ 衝突する入力で推測の 1 件ではなく「解決できない」が返ること（②の fail-closed）/ 同じ入力を上流の既定経路と倒し先で通して成果を比べること（上流の派生形） |
| 正本 | `backend/core/display_projection.py`・`backend/api/display_route.py` / `backend/core/focus_document.py` / `backend/core/dialogue_shape.py` / `backend/api/source_resolution.py`、記録 `docs/architecture/root_cause_consolidation_2026-09-30.md` |
