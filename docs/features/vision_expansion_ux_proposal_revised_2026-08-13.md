## 0. エグゼクティブサマリー

本提案の中心は、AIチャットを高性能な「回答装置」として改善することではない。  
**学習者が自分で予測し、本文・証拠との差を見て、理解を更新し、問いを持ち越し、時間をおいて再訪する一連の理解サイクルを先に設計し、その中にAIを配置する**ことである。

元文書で強く支持された3つの独立収束は、次の3点である。

1. **ELICIT-first** — 開示の前に学習者自身の産出を挟む。
2. **セッションの縁と間** — 学習中だけでなく、開始・終了・次回再訪まで設計する。
3. **同一パーツの通時的な伝記** — 式・概念を完成品としてではなく、時間の中で変化するものとして歩く。

今回の対話からは、これらを単独機能として作るより、次の理解サイクルとして統合する方がよいという示唆が得られた。

> **OPEN → ELICIT → DIFF → REVEAL → UPDATE → ANCHOR → LEAVE → REVISIT**

- **OPEN**: 何を読むか・なぜ読むか・どこから入るか
- **ELICIT**: 先に自分の予想・連想・問いを出す
- **DIFF**: 自分の予想と本文・構造・証拠との差を見る
- **REVEAL**: 必要な情報を開示する
- **UPDATE**: 「何が変わったか」を本人が短く言葉にする
- **ANCHOR**: 引っかかり・問い・接続を教材上の場所に残す
- **LEAVE**: 次に持ち越す問いを一つ選んで終える
- **REVISIT**: 次回、その問いと前回との差分から再開する

AIアシスタントはこのサイクルの中心ではなく、**各段階で必要な問い・比較・説明を生成する補助レイヤー**として扱う。

## 1. 元文書が示す3つの独立収束

### 1.1 ELICIT-first — 「答えを見る前に、自分で一度つくる」

異なる4分野から、ほぼ同じ構造が独立に提案された。

- 脳科学: 予測誤差を学習・記憶の契機として使う
- 宇宙物理: 式変形を読む前に、自分ならどう進めるかを考える
- 学習科学: pretesting / generative learning
- HCI・ゲームデザイン: 地図を見る前に自分で地図を描く

元文書で想定されている実装は3スケールで共通化されている。

#### 式スケール

判断が分岐する箇所だけで予測を挟む。

例:

- 「この極限でどの項が残ると思うか」
- 「著者は次にどの近似を使うと思うか」

恒等変形のたびには出さない。

#### 論文スケール

タイトルやアブストラクトから、

- 何を示す論文だと思うか
- どんな主張の骨格が必要になるか

を先に予測し、その後で実際の paper skeleton と照合する。

#### 地図スケール

分野マップを最初から見せるのではなく、必要に応じて白地図に、

- ありそうな概念
- つながり
- スケール感

を本人が描いてから実際の地図と比べる。

### UX上の重要条件

- 常時強制せず、**精読モードとしてopt-in**
- 毎回予測させず、判断価値の高いポイントだけ
- モーダルな「クイズ画面」にしない
- 「霧が晴れる」ような連続的インタラクションにする
- リビール直後に任意の一行自己説明を置く
- 外れた予測は採点材料にせず、本人の理解履歴として残す

## 2. 今回の対話で追加した重要UX仮説

この節は元文書の直接記述ではなく、今回の検討から導いた追加提案である。

### 2.1 AIチャットを「入口」にしすぎない

既存のAIアシスタントは、多くの場合、

> 質問 → AIの回答 → 追加質問

という構造を持つ。

しかし本ビジョンでは、これをそのまま高度化するより、

> 学習者の産出 → 比較 → 必要な開示 → 更新

という理解サイクルを先に設計し、その中にチャットを埋め込む方が一貫する。

したがって、AIは常に会話ウィンドウとして存在する必要はない。

AIの役割は例えば次のように分解する。

- 予測を引き出す短い問いを出す
- 学習者の予想を要約する
- 本文との差分候補を作る
- 必要なときだけ説明を開く
- 「何が変わったか」を言葉にするのを手伝う
- 次回へ持ち越す問いの候補を整理する

**チャットを主役にせず、理解行為を主役にする。**

## 3. 初回利用（Cold Start）のUX

元文書は継続利用時の再訪設計には詳しいが、**その教材を初めて開いた瞬間のUXは十分に規定していない**。ここは追加設計が必要である。

### 3.1 初回からユーザー理解度に応じた完全適応をしない

過去データがない初回に、システムが「この人の理解度」を推定して入口を変えるのは危険である。

特に、元文書が退けた「スキーマ距離レンズ」と同じ問題を起こしやすい。

そこで初回は、**能力推定ではなく、その場で本人が生成した情報**を使う。

### 3.2 論文を開いた直後に取得する情報

最初から多くの質問を並べない。1〜2個の軽い問いから始める。

推奨する第一問い:

> **「この論文を、なぜ今開きましたか？」**

続いて必要なら:

> **「タイトルを見た時点で、どんな内容・結論を予想しましたか？」**

アブストラクトを開いた後なら:

> **「いま一番気になっている点はどこですか？」**

ここで取得したいのは正答ではなく、

- 読む動機
- 期待
- 既存の連想
- 予測
- 引っかかり

である。

これを「初期状態」として保持する。

### 3.3 初回画面で固定すべきなのは「情報」ではなく「文法」

全ユーザーに同じ本文断片を見せる必要はない。

共通化すべきなのは、

> **開く → 一度自分で考える → 実際を見る → 差を見る**

という操作の文法である。

## 4. 想像が本文から乖離したときのUX

ELICIT-firstには、「最初の想像が本文から大きく離れる」というリスクがある。

これを防ぐために、最後にまとめて訂正するのではなく、**小さなDIFFを頻繁に挟む**。

### 4.1 採点ではなく差分表示

避けたいUX:

- 正解 / 不正解
- 点数
- 「あなたは間違っています」

推奨するUX:

> **あなたの予想:** A → B → C  
> **著者の構成:** A → D → C

そして、

> 「分岐したのはここです。なぜ著者はDを選んだと思いますか？」

とする。

### 4.2 予測の役割を変える

予測は「当てるゲーム」ではない。

予測によって、

- 本人が何を前提にしていたか
- どこで本文とズレたか
- 何を読んだことで理解が変わったか

を見えるようにする。

つまり、**誤差そのものを理解の観測装置にする。**

## 5. セッションの縁と間 — 「一晩の航海」

元文書の第二の独立収束である。

一般的な学習システムは「使用中」の体験を設計するが、

- 始める直前
- 終える直前
- 学習していない時間
- 次に戻ってきた瞬間

はほぼ空白である。

本提案では、それらを一続きのUXとして扱う。

### 5.1 出発

そのセッションで確かめたい問いを一つ持つ。

初回は「読む動機」から生成してもよい。

例:

> 「この論文で一番確かめたいことは？」

### 5.2 滞在

読む途中で生じた、

- 問い
- 引っかかり
- 接続
- 予測と本文の差

を、すべてチャット履歴に押し込まず、**教材上の位置に係留する**。

#### 「気になるポイント」の拾い方

AIがリアルタイムに「あなたはここで困っていますね」と分類しない。

本人が簡単に付けられる、例えば次の操作を用意する。

- 「気になる」
- 「まだ分からない」
- 「あとで戻る」
- 「何かとつながりそう」

付箋や余白記号のような軽さが望ましい。

### 5.3 着地

セッション終了時に長い振り返りを書かせない。

その日に残った痕跡から一つ選び、

> **「次に持ち越すなら、どの問いにしますか？」**

とする。

新規入力ではなく、途中で生まれた問いから選択できることが重要。

### 5.4 セッション間

通知・連続日数・未消化バッジは出さない。

**何もしない。**

「間」を埋めないこと自体を設計とする。

### 5.5 再訪

次回は、前回の要約ではなく、まず持ち越した問いだけを見せる。

> 「前回、ここでこの問いを残しました。いまならどう考えますか？」

本人が一度答えた後に、前回から増えた接続や理解差分を見せる。

## 6. 同一パーツの通時的な伝記 — 時間レンズ

「通時的」とは、同じものを**時間を通して見る**ことである。

ここで扱うのは、単一論文の説明ではない。

システム内で同一性が人間により確定された式・概念について、複数論文をまたいで、

- 表記がどう変わったか
- 前提がどう変わったか
- どこで適用範囲が破れたか
- 共同体での承認・疑義がいつ変化したか

を年代順に歩く。

### 6.1 何が得られるか

学生は知識を「教科書に載っている完成品」として受け取りやすい。

時間レンズはそれを、

> **条件を持ち、修正され、分岐し、適用範囲を変えながら生きている研究対象**

として見せる。

研究者が論文を読むときに見ている、

> 「何が前と違うのか」

という視点を学習者に与えることが目的である。

### 6.2 UX

年表を眺めるだけでなく、一歩ずつ進む。

例:

1. 1960年代の形を見る
2. 「次に何が変わると思うか」を予測
3. 次の論文を開く
4. 前提差分だけを強調
5. 破れた条件を見る
6. そこから派生した別の定式化へ進む

ここでもELICIT-firstを再利用できる。

## 7. 賭け金の台帳（Stakes Ledger）

タイトルの「賭け金」は金銭ではなく、

> **「この主張は、何が崩れたら危うくなるのか」**

という意味である。

単に論文の結論を理解するのではなく、

- 何に依存しているか
- どんな観測なら覆るか
- その検証は今できるか
- 独立した別の支持線があるか

を読む。

### 7.1 推奨UX: 「主張の根を見る」

論文中の主張を選ぶと、横にその主張を支える構造を出す。

```text
結論 C
├─ 観測 O1
├─ 仮定 A1
│  └─ 理論 T1
└─ 観測 O2
```

各支点に、

> **「もしこれが崩れたら？」**

という操作を置く。

押すと、

- 影響を受ける主張
- そのまま残る主張
- 判定不能になる部分

を質的にハイライトする。

### 7.2 研究テーマ発見への接続

さらに、反証条件を、

- 現在検証可能
- 次世代装置なら可能
- 現状では困難

として整理する。

ただし、

> 「この分野では未検証」

とは言わない。

必ず、

> **「このコーパス内には検証記録がありません」**

とする。

コーパスの穴を研究上の穴と誤認しないためである。

## 8. 静かな開通と欲望の小径

これは「他の学習者の存在」を、SNS・ランキング・人気順とは異なる形で感じさせる提案である。

### 8.1 基本イメージ

知識マップ上で、複数の学習者が独立に同じ2点を接続したとき、

- 人数を出さない
- 誰かを出さない
- 人気度を出さない

まま、**そこに細い踏みあとだけが現れる。**

「誰かもここに橋を架けた」という気配だけを残す。

### 8.2 静かな開通

教員が新しいリンクを確定した瞬間には通知しない。

ユーザーが後日その場所に戻ってきたとき、

> 「前回ここは行き止まりでした。いまは先へ渡れます。」

という風景差として見せる。

### 8.3 必須ガードレール

これは魅力的だが、元文書で最も懸念が集中した提案でもある。

必須条件:

1. 本人が一度自力で探索した後にのみ他者の踏みあとを見せる
2. 一定期間使われなければ踏みあとを消す
3. 独立した複数コホートで再現された道だけを表示
4. 踏みあとを使って教材の提示順を裏で並べ替えない
5. 「踏みあとがない場所」を劣った道として扱わない

つまり、社会的情報は**案内ではなく、探索後の環境情報**として使う。

## 9. 全体UXアーキテクチャ案

### 9.1 中心は「チャット」ではなく「教材 + 理解レイヤー」

推奨画面構成:

```text
┌─────────────────────────────────┐
│              教材本文              │
│                                   │
│  タイトル / Abstract / 本文 / 式   │
│                                   │
│  [気になる] [つなぐ] [あとで戻る]   │
└─────────────────────────────────┘

        ↓ 必要な地点だけ ELICIT

┌─────────────────────────────────┐
│  あなたは次をどう予想しますか？       │
│  [ワンタップ / 一文 / スケッチ]       │
└─────────────────────────────────┘

        ↓

┌─────────────────────────────────┐
│  差分                           │
│  あなた: ...                    │
│  著者: ...                      │
│  「何が違いましたか？」（任意）       │
└─────────────────────────────────┘

        ↓

┌─────────────────────────────────┐
│ AIアシスタント（必要時のみ展開）       │
│ ・説明する                       │
│ ・比較する                       │
│ ・別論文へ橋を架ける               │
└─────────────────────────────────┘
```

### 9.2 AIの会話モードを4種類に分ける

#### A. Elicit

答えず、本人の予測を引き出す。

#### B. Diff

本人の予測と、論文・構造との差を比較する。

#### C. Explain

本人が要求した部分だけ説明する。

#### D. Reflect / Carry

そのセッションで変わった点と、持ち越す問いを整理する。

この4モードを内部的に分けることで、「AIが何でも答えてしまう」状態を避けられる。

## 10. 提案する理解サイクル

### Step 1 — OPEN

教材を開く。

初回なら:

> 「なぜこの論文を開きましたか？」

再訪なら:

> 前回持ち越した問いを先に表示。

### Step 2 — ELICIT

タイトル・Abstract・式・図などを材料に、最小限の予測を行う。

### Step 3 — DIFF

予測と実物の差分を見る。

### Step 4 — REVEAL

必要な本文、解説、関連論文、地図を開く。

### Step 5 — UPDATE

> 「さっきと比べて、何が変わりましたか？」

任意の一行。

### Step 6 — ANCHOR

問い・引っかかり・接続を、その教材上の位置に残す。

### Step 7 — LEAVE

その日生まれた問いから一つを「次に持ち越す問い」にする。

### Step 8 — REVISIT

次回、まず問いに再回答してから、前回との差分を見せる。

## 11. 実装優先度の再整理

元文書の優先度を維持しつつ、UX検討を踏まえて段階化する。

### Phase 1 — 理解サイクルの最小閉ループ

最優先。

実装:

- 初回OPEN
- 軽量ELICIT
- DIFF表示
- 一行UPDATE
- 「気になる」等のアンカー
- セッション末の持ち越し問い
- 次回再訪

ここまでで、

> **予測 → 比較 → 更新 → 持ち越し → 再訪**

が閉じる。

### Phase 2 — 深い読解

- 式スケールの予測
- 論文骨格予測
- 時間レンズ
- AIのElicit / Diff / Explainモード分離

### Phase 3 — 研究支援

- 賭け金の台帳
- 反実仮想
- 反証条件
- 支持経路

### Phase 4 — 集合知・persistent world

- 橋の生態系
- 静かな開通
- 欲望の小径

この段階はガードレールを先に完成させてから導入する。

## 12. 最初にプロトタイプすべき体験

最初から6提案すべてを実装する必要はない。

最小プロトタイプとしては、**一本の論文を読む体験だけ**でよい。

### Prototype A — 15分の精読セッション

1. 論文を開く
2. 「なぜこれを読みますか？」
3. タイトルだけ表示
4. 「何が書かれていると思いますか？」
5. Abstractを表示
6. 予測との差を2〜3点だけ表示
7. 本文へ
8. 途中で1回だけ、次の主張を予測
9. リビール
10. 「何が変わった？」を任意で一行
11. 気になる箇所を1つアンカー
12. 終了時、そのアンカーを次回の問いとして残す

### Prototype B — 翌日の再訪

1. 前回の問いだけ表示
2. 「いまならどう答えますか？」
3. 回答後に前回の痕跡を表示
4. 同じ箇所を再読
5. 差分を本人に確認してもらう

この二日間だけで、3つの独立収束のうち、

- ELICIT-first
- セッションの縁と間

を一つのUXとして検証できる。

時間レンズはその次でよい。

## 13. 成功条件

このシステムが成功している状態は、AIがたくさん話している状態ではない。

以下が増えている状態である。

- 本文を見る前に、自分なりの仮説を持てる
- 「どこで自分と著者が分岐したか」を言える
- 分からなさをその場で消さず、問いとして持ち越せる
- 再訪したとき、自分の理解の変化に気づける
- 式・概念を適用範囲と歴史を持つものとして見られる
- 主張が何に依存しているかを疑える
- 他人の経路を正解として追わず、それでも共同体の気配を感じられる

したがって、主要KPIを単純な正答率・滞在時間・連続利用日数だけに置くべきではない。

元文書の哲学どおり、UI上でも**数値を前面に出さない**ことが重要である。

---

## 14. 結論

本ビジョンの本質は「AI家庭教師をさらに賢くする」ことではない。

**人が研究対象と出会い、自分なりの予測を持ち、証拠とのズレに気づき、問いを残し、時間を経て戻り、別の論文・別の人・過去の自分との間に橋を架けていく環境をつくること**である。

そのため、設計順序は次のようにする。

1. **理解サイクルを設計する**
2. **教材上の痕跡と再訪を設計する**
3. **AIの役割を各局面に限定する**
4. **時間レンズ・賭け金の台帳へ拡張する**
5. **最後に集合知の環境表現を加える**

この順序なら、現在のチャットボットを全面的に捨てる必要はない。

ただし、チャットボットを中心UIとして少しずつ賢くするのではなく、**教材と理解サイクルを中心に据え、その中でAIチャットを再配置する**ことが望ましい。
