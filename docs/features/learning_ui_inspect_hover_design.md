## 0. 背景 — 現状の問題（実測）

1. **完全重複**: サイドバー「🗣 この論文と議論する」（`app.js` renderSidebar）と入力欄上
   「🗣 もっと自由に話す」（`discuss-free-link-btn`）は**どちらも `enterDiscussMode()` を呼ぶ
   同一機能**。同じ画面に別名で2つ出ており、別機能に見える。
2. **composer 行（`.ia`）の粒度混在**: `[🎙レクチャー][入力欄][質問][❓使い方][🤖]` の5要素に
   「画面全体の提示モード切替 / テキスト入力 / 送信 / ヘルプ / 別モード起動」という抽象度の
   異なる4種が同居。🤖 はラベルなし絵文字のみで機能が伝わらない。
3. **同一状態の3重表示**: サイドバー active・教材フッタ「本筋：〜」・モードバー
   「📘 本筋に沿って学習中：〜」が同じ情報を3箇所で表示。通常状態（本筋）では情報量ゼロの
   バーが1行を常時占有し、文言がレイアウト依存（「上の『確認して次へ』」）。
4. **視覚階層の不在**: 「質問」（青塗り）・「使い方」（枠）・「🤖」（枠）が同時に主張し、
   絵文字 📘🗣❓🤖🎙 が同一サイズで並ぶため優先度が読めない。
5. **破壊的操作の常設**: 「質疑応答履歴を削除」が右パネル最下部に赤で常時表示。
6. **軸の取り違え**: レクチャーは「順番に学ぶ/議論する」と同列のモードに見える位置に居るが、
   実装上 discuss モードでは音声状態を取得すらしない
   （`app.js` `refreshTopicAudioStatus`: `if (... || isDiscussMode()) return;`）。
   レクチャーは**いま開いている1セクションの提示形式**であり、セッション入口とはレイヤーが違う。

## 1. 不変条項（IH1〜IH10）

継承元の条項（P1/P4/P6/P7、DM1/DM5/DM6、W8/PN-4、help_kb 諸則）を本機能の語彙で言い直したもの。

- **IH1 出所を混ぜない**: マニュアル（使い方）と教材（内容）の解説を1つの吹き出しに混在させない。
  ツールチップには出所チップ（📖 使い方 / 📄 教材）を必ず付ける。chunks へのマニュアル相乗り禁止
  （help_kb 正本）の UI 版。
- **IH2 AI アシスタント OFF は LLM 0回**: ホバー解説は「既にあるもの」（マニュアル節・
  承認済み説明・要素の label/summary）を見せるだけ。生成するのは AI ON（音声対話）のときだけ。
- **IH3 見えない状態が回答を変えない**: ラッチされたアンカーは**可視のピン留めツールチップ**として
  送信時まで表示され続ける。不可視のラッチを `learner_selected` として記録することを構造的に禁止する。
- **IH4 インスペクト中のクリックは解除のみ**: 1クリック目はインスペクト解除だけを行い、
  下の操作（送信・削除等）を実行しない。操作したければ解除後の2クリック目。
- **IH5 candidate/確定の分離を継承（P1）**: 可視ピン付きで送信されたアンカーのみ
  `attribution_source='learner_selected'`（同期・非LLM・即確定）。LLM がラダーから推測した帰属は
  従来どおり `llm_candidate` で、本人確定まで確定しない。
- **IH6 同期パス 1 LLM コール上限を継承（P6）**: アンカー優先ラダーは既存チャットコールへの
  **ヒント同梱**で実現し、分類・選択のための追加 LLM コールを作らない。
- **IH7 数値を見せない（W8/PN-4）**: ツールチップ・帰属表示に confidence 等の生数値を出さない。
- **IH8 未整備は事実文 + 痕跡（捏造禁止）**: 解説が無い対象は「この部分の説明はまだ用意されて
  いません」の固定事実文を出し、`no_hit` を help_usage 痕跡に記録して G層
  `manual.help_gaps_pending` に流す。生成で埋めない。
- **IH9 ホバー対象はアンカーID保有要素のみ**: componentチップ・数式ブロック・図カード・出典チップ・
  スライド・UI部品（論理アンカー登録済み）に限る。素の本文段落は対象にしない
  （段落は既存のテキスト選択→`selection_text` 経路を使う）。
- **IH10 痕跡を汚さない**: ホバーの生イベントを痕跡に積まない。help_usage 痕跡は従来どおり
  逐語を積まず anchor/documented/no_hit のみ。no_hit 記録は滞留閾値 + セッション内 anchor 単位
  dedup でスパムを防ぐ。

## 2. 3軸モデル — 「トグルは、それが変えるものの上に置く」

| 軸 | 何を切り替えるか | スコープ | 置き場所 |
|---|---|---|---|
| **① セッションの入口** | 何を辿るか（コース順路 ⇔ 論文全体） | アプリ全体（サイドバーの意味自体が変わる） | サイドバー最上部（現状維持・DM5 等重） |
| **② 提示形式** | いま映している教材をどう見せるか（本文 ⇔ スライド講義） | 中央上段の教材区画のみ | **教材区画ヘッダ右**（composer から移設） |
| **③ 対話の手段** | どう入力・応答するか（テキスト ⇔ ハンズフリー音声） | 入力欄のみ | composer（現状維持・ラベル改善） |

レクチャー（②）が①と同列でない根拠: discuss モードではセクションが定まらないため
レクチャーは概念的に成立せず、実装もそれを前提にしている（§0-6）。②を教材区画ヘッダに
置くと、**discuss モードで教材区画がプレースホルダに変わる際にトグルが自然に消え**、
「議論中はレクチャーが押せない」が理由不明の disabled に見える問題も解消する。

「音声」の3つの別物を混同させない:

| 現行 | 実体 | 軸 | 新ラベル |
|---|---|---|---|
| `🎙 レクチャー`（lecture-toggle） | スライド+読み上げ（出力・TTS） | ② | `🎙 講義`（教材ヘッダのセグメント） |
| `🤖`（voice-mode-btn） | ハンズフリー会話（入出力・casual） | ③ | `🎤 音声で話す`（ID は維持） |
| `lecture-chat-mic` | 割込みチャットの音声入力 | — | §15 の裁定次第で廃止候補 |

## 3. 画面再配置の確定事項

### 3.1 サイドバー（①）
- 二枚看板「📘 順番に学ぶ / 🗣 この論文と議論する」は**現状維持**（DM5: 等重・既定選択なし）。
  件数バッジ等は付けない（DM6）。
  - 2026-07-26 追記: 表示形態のみセグメントコントロール（1ピル2セグメント・ラベル短縮
    「順番に学ぶ / 論文と議論」）へ変更した。等重・既定選択なしの趣旨と DM6 は不変。
    経緯と診断は `discussion_mode_design.md` §9.5。

### 3.2 教材区画ヘッダ（②）
- 教材区画（`#material-region`）上部にヘッダ行を新設: 左=「教材 · トピック名」、
  右=セグメントコントロール `[📖 読む | 🎙 講義]`。
- `lecture-toggle` と `lecture-toggle-hint`（「音声未生成」インライン理由表示）をここへ移設。
  hint は「この教材はまだ音声がない」と教材の属性として読める位置になる。
- discuss モード中は教材区画ごとプレースホルダになるため、セグメントも出さない。

### 3.3 composer（③）
- 構成: `[🎤 音声で話す] [入力欄] [送信]`。
- 「質問」→「送信」に改称し、プレースホルダを「質問や考えを入力…（Enterで送信）」に変更。
  **青塗り（プライマリ）は送信のみ**。
- `voice-mode-btn` は ID 維持のままラベルを `🎤 音声で話す` に変更（aria-label / title 付与）。
- `help-usage-btn` は composer から**トップバーへ移設**（§4）。ID・typed action 配線は維持。

### 3.4 モードバーの静音化
- 通常状態（on-path）のモードバーは**非表示**。discuss（🗣 論文と議論中）と寄り道
  （🔍 寄り道中 + ↩ 本筋へ戻る）のときだけ表示する。バーの出現自体が「特殊状態」の意味を持つ。
- 教材フッタの「本筋：〜」テキストは削除し「確認して次へ」ボタンのみ残す。
- 寄り道ブランチの文言・挙動は不変（explore の既存 UX を壊さない）。

### 3.5 重複導線の削除
- 「🗣 もっと自由に話す」（`discuss-free-link-row` / `discuss-free-link-btn`）を**削除**する。
  discuss への入口はサイドバー二枚看板に一本化（DM5 の等重併記はそちらが担保）。
- `discussion_mode_design.md` に本書参照の追記を行う（Phase 1 実装項目の supersede を明記）。

### 3.6 右パネル
- 「質疑応答履歴を削除」は折りたたみ（`▸ このトピックの操作`）配下へ降格。機能・確認ダイアログは不変。

## 4. 「？」= インスペクト・モード

composer の1アクションだった「❓ 使い方」を、**画面全体の「使い方インスペクト」トグル**として
トップバー右端へ移設する。§2 の原則どおり「画面全体のホバー挙動を変えるスイッチ」は
①②③のどこでもなくトップバーに置く。

- ON 中は常設バナーを表示:
  「使い方を確認中 — 知りたい部分にカーソルを合わせてください（Esc で終了）」。
- ON 中は `cursor: help`。UI部品（論理アンカー登録済み要素）へのホバーで
  **マニュアル節ツールチップ**（📖 出所チップ付き）を表示する。
- **クリック = インスペクト解除のみ**（IH4）。下の操作は実行しない。Esc / 「?」再クリックでも解除。
- インスペクトは「ホバー対象の切替スイッチ」であり、ホバー機能そのものの ON/OFF ではない:
  OFF = 教材の中身（§5.1）、ON = システムの部品（§5.2）。どちらの解説が出るかが常に一意。

### 4.1 4状態マトリクス

|  | AIアシスタント OFF | AIアシスタント ON（🎤 音声対話中） |
|---|---|---|
| **インスペクト OFF** | 教材要素ホバー → 既存情報のツールチップ（LLM 0回） | 同ツールチップ + ラッチして声で質問 → **教材 RAG ルート**（アンカーヒント付き） |
| **インスペクト ON** | UI部品ホバー → マニュアル節ツールチップ（LLM 0回） | 同ツールチップ + 声で質問 → **usage_help ルート確定** |

**インスペクト ON 中の発話は無条件に usage_help ルート**とする。現行の非LLM pre-route
`_is_usage_question()`（文面からの推測）に依存せず、UI 状態で誤爆ゼロを構造化する。
音声経路の会話調整（1 LLM コール、`feature="learning:help_usage"`）・quota 非消費・
無ヒット固定文は既存 HELP ルートの規約をそのまま継承する。

## 5. ホバー解説2系統（AI OFF = LLM 0回）

### 5.1 教材の中身（インスペクト OFF）
- 対象: componentチップ（⚓）・数式ブロック・図カード・出典チップ・スライド（IH9）。
- 内容: **既に配信済みのデータ**のみ。要素 label/summary、C層の承認済み説明
  （`component_explanations` teacher_approved のみ）、図キャプション等。
  深掘りは既存のチップクリック展開・`/api/learning/.../components/{id}/context` に委ねる。
- 大半はクライアント保持データで完結（API 0回・LLM 0回）。

### 5.2 システム UI（インスペクト ON）— UI アンカー表
- 学習者版の UI 論理アンカー registry を新設する。教員側 Admin Copilot の
  `registerUiAnchors`（論理ID→DOM 解決・バックエンドは DOM 非依存）と同じ規約。
- 正本: `backend/core/help_kb/ui_anchors.py` に
  `UI_ANCHORS = {"composer.send": "student/….md#anchor", ...}`（**student/ 配下のみ**参照可。
  audience 越境は構造的に禁止）。
- 起動時に `help_kb/validator.py` と同枠でファイル・アンカー実在を検証（fail-open）。
- 配信: `GET /api/learning/help/ui-anchors`（ログイン必須・audience=student で解決済みの
  {anchor_id: {title, body, manual_anchor}} を返す）。ログイン時に1回フェッチしてクライアントで
  キャッシュし、**ホバーごとの API コールはしない**。

### 5.3 未整備時（IH8）
- マニュアル節が無い UI 部品・承認済み説明が無い教材要素は、固定事実文
  「この部分の説明はまだ用意されていません」を表示。
- UI 部品側は help_usage 痕跡に `no_hit`（anchor 単位）を記録 → 既存 G層
  `manual.help_gaps_pending`（k-匿名・レンジ表示）がそのまま教員へ返す。
  **未整備アンカーの発見が自動で改善ループに乗る**のが本設計の副産物。

### 5.4 スパム防止（IH10）
- no_hit 記録はツールチップ表示が一定時間（目安 1 秒）継続した場合のみ・
  セッション内 anchor 単位で1回まで。ホバーの生イベントは記録しない。

## 6. ホバー+ラッチ（採用）

**ホバーは連続的で、送信の瞬間には失われている**（Enter 時のマウスは入力欄上・発話中も動く）ため、
「マウスオーバーした状態で話しかける」はどこかの時点でホバー対象を凍結（ラッチ）しないと
原理的に成立しない。ラッチの可視化は独立チップではなく**ツールチップのピン留め**が兼ねる。

### 6.1 状態遷移

| タイミング | 状態 |
|---|---|
| 非ホバー | 何も出ない（空の器を常設しない） |
| アンカー要素にホバー | ツールチップ表示（候補） |
| **入力開始（最初のキーストローク）/ 発話検知（既存 VAD）** | その時点のホバー対象を**ラッチ** → ツールチップをピン留め（マウスが離れても残る） |
| ラッチ後にマウス移動 | ラッチ値は**変わらない** |
| 送信 | ラッチ値をアンカーとして送信 → クリア |
| ✕（ツールチップ上）/ Esc | 手動クリア |
| ラッチ無しで入力開始 | アンカー無し（ラダー第2位以降に落ちる） |

- 発話検知は既存の WebAudio 無音検知（casual 音声モード）のイベントを流用する。
- テキスト入力でも成立する（手はキーボード・マウスは要素上に静止、が自然な姿勢のため）。

### 6.2 帰属の確定度（IH3/IH5）
- **ピン留めツールチップが可視のまま送信された場合のみ** `learner_selected`。
  実装は既存の明示アンカー経路（方法A: `chunk_id`/`element_id`/`element_type`/`element_label`）を
  そのまま使う — **教材側のバックエンド変更はゼロ**。
- 発話内容がアンカーと無関係でも、指した事実は事実として痕跡に残る（P4）。外れた帰属は
  既存 `POST /api/learning/anchors/{trace_id}/confirm`（doubt_type/anchor_type/anchor_id 訂正可）で
  本人が直せる。
- 不可視ラッチ（ピンが消えた後の送信・実装バグ等）を `learner_selected` にしない。
  ガードレールテストで固定する（§12）。

## 7. アンカー優先ラダーと応答帰属

**Step 1（非LLM・クライアント）** — 候補を順序付きで送る:

| 優先 | 候補 | 出どころ |
|---|---|---|
| 1 | ラッチ中のアンカー | §6（教材: `element_*` / UI: `ui_anchor`） |
| 2 | 表示中のスライド / セグメント | 既存 `position_anchor` / `selection_segment_id` |
| 3 | 現在のトピック | `currentTopicId`（サーバ側で解決） |
| 4 | 直近回答の第1根拠チャンク | 既存 `sources[0].chunk_id`（サーバ側の保存履歴から導出可） |

**Step 2（既存の 1 LLM コール内・IH6）** — ラダーは指示ではなく**ヒント**としてプロンプトに同梱:
「①が注視されている。発話が①に関係するなら①を優先して答える。関係しないなら②〜④から
最も近いものを選ぶ。どれに基づいて答えたかを明示する」。追加の分類コールは作らない。

**Step 3** — 回答冒頭または末尾に帰属を1行で明示: 「〈式 (2.7)〉についてお答えしています」。
数値は出さない（IH7）。

**Step 4** — 訂正は既存 confirm/dismiss API（新規実装なし）。

## 15. レクチャーの占有範囲 — 裁定済み（案①採用、2026-07-26）

現行 `.mn.lecture-on` はメイン列を全画面テイクオーバーし（chat-area/composer まで非表示）、
講義中の質問用に第2の composer（`lecture-chat-popup`: 入力欄+マイク+送信+再開）を別途持っていた。

**オーナー裁定: 案①（上段のみスライド化）を採用。**

- スライドステージは教材区画（上段）の差し替えとしてのみ表示し、下段の会話 UI・composer は
  講義中も残す。「②=教材区画の提示形式」という本設計の位置づけと完全一致。
- **`lecture-chat-popup`（第2 composer + `lecture-chat-mic` + 再開ボタン）は丸ごと廃止**。
  講義中の質問は通常の composer で受ける（送信時に講義を自動一時停止 → 回答後に再開導線を
  モードバー相当の位置に出す。既存 `openInterruptChat`/`resumeLecture` の一時停止・再開
  ロジックは流用し、UI だけ通常チャットに一本化する）。
- `.mn.lecture-on` の非表示対象は `#material-region`（→スライドステージに差し替え）のみに縮小。
  `#chat-area`/`#chat-input`/`#send-btn`/`#voice-mode-btn`/`#split-handle`/`#mode-bar` は消さない。
- 投影用に `⛶ 全画面` を教材ヘッダのオプションとして別途用意する（既定 OFF・任意）。
- 案②（全画面維持）は不採用: 「上段のモードなのに全部消える」不整合と第2 composer が残るため。
