- 対象: `frontend/public/admin.html`、`frontend/public/css/styles.css`、
  `frontend/public/js/admin-lecture-studio.js`、
  `backend/api/routes/lecture_studio/scripts.py`
- 非対象: 学習者画面からの音声生成、TTSプロバイダの選定、対応言語（`ja` / `en`）の追加

## 1. 背景と問題

現状は、原稿スタジオを開いた直後、コース未選択でも音声言語選択モーダルが表示され得る。
この段階では対象コースも読み上げ原稿の有無も決まっていないため、言語を選択させても
生成操作の意味が定まらない。

さらに、音声生成の可否が「コース内容の生成済み」と「チャンクの存在」だけで判定されると、
`spoken_text` が未生成のチャンクを含んだまま音声生成を開始できる。現行ワーカーはその
チャンクをスキップするため、タスクが完了しても一部のスライドに音声がない状態を
成功として扱い得る。

## 2. 操作状態と遷移

```text
コース未選択
  └─ コースを選択
       └─ コース内容・スライド・読み上げ原稿を読み込み中
            ├─ チャンクなし / コース内容未完了
            │    └─ 音声生成は無効。先に必要な準備を案内する
            ├─ spoken_text が不足
            │    └─ 音声生成は無効。原稿生成を案内する
            └─ 全対象スライドの spoken_text が準備済み
                 └─ 「音声生成」を有効化
                      └─ 押下時だけ言語選択モーダルを開く
                           ├─ 現在の言語: 未生成分の音声を作る
                           └─ 別言語: 原稿再生成 → 音声生成
```

### 2-1. コース未選択

- `#ls-audio-lang-modal` は必ず非表示にする。
- 音声生成、設定以外のコース依存操作は無効にする。
- 画面には「コースを選択すると表示されます」を表示する。

### 2-2. コース選択・読み込み中

- コース切替の開始時に、前コースの `chunks`、構造、分析状態、音声準備状態をクリアする。
- 新コースの `lecture-scripts` とコース構造の両方を取得し終えるまで、音声生成を有効にしない。
- 非同期応答が選択済みの `courseId` と異なる場合は破棄する。

### 2-3. 音声生成可能

音声生成を有効にする条件は、すべて満たすこととする。

1. コースが選択されている。
2. コース内容とスライド生成が完了している。
3. 音声化対象チャンクが1件以上ある。
4. **全対象チャンクに空でない `spoken_text` がある。**
5. 原稿・音声の生成タスクが進行中ではない。

`display_text` や元テキストが存在するだけでは条件を満たさない。TTS入力の正本は
`spoken_text` である。

## 3. UI仕様

### 3-1. 言語選択モーダル

- `#ls-audio-lang-modal[hidden] { display: none !important; }` を明示し、
  `.ls-settings-modal { display: flex; }` と競合しないようにする。
- モーダルを開けるのは、有効な `#ls-audio-all-btn` の押下時だけとする。
- コース選択・タブ初期化・原稿一覧の読み込みではモーダルを開かない。
- モーダルには選択中コース名、対象スライド数、選択言語での既存音声数を表示する。

### 3-2. 未準備時の案内

音声生成ボタンを単に無効化するだけではなく、近傍に理由と次の操作を示す。

| 状態 | 表示する理由 | 次の操作 |
|---|---|---|
| コース未選択 | 音声化するコースを選択してください | コースを選択 |
| コース内容未完了 | スライドの準備が完了していません | コース内容生成を行う |
| 原稿不足 | 読み上げ原稿が未生成のスライドがあります | 原稿生成を行う |
| 読み込み中 | コースの音声準備状態を確認しています | 完了を待つ |

### 3-3. 言語選択後

- 現在の `lecture_language` と同じ言語なら、未生成スライドだけを音声化する。
- 異なる言語なら、確認文を表示したうえで `spoken_text` を指定言語で再生成し、その完了後に
  音声生成を開始する。
- タスク進捗は「原稿再生成中」→「音声生成中」とフェーズを分けて表示する。

## 4. APIの防御

`POST /api/admin/courses/{course_id}/lecture-audio/generate` は、UIを経由しない呼び出しに対しても
同じ前提を強制する。

- コースに対象チャンクがない場合: 422。
- 1件でも空の `spoken_text` を持つ対象チャンクがある場合: 422。
- エラーには不足件数と、先に読み上げ原稿を生成する必要があることを含める。
- ワーカーが空の `spoken_text` を黙ってスキップし、見かけ上成功する経路を残さない。

言語変更による「原稿再生成 → 音声生成」チェーンは例外であり、原稿再生成後に全対象の
`spoken_text` を再取得してから音声生成を行う。

## 5. 受け入れ条件

- [ ] 原稿スタジオを開いた直後、およびコース未選択時に音声言語モーダルは表示されない。
- [ ] コース切替直後に前コースの状態で音声生成が有効になることはない。
- [ ] コース内容未完了・チャンクなし・`spoken_text` 不足では音声生成が無効で、理由が分かる。
- [ ] 全対象に `spoken_text` がある場合だけ音声生成を有効化する。
- [ ] 言語選択モーダルは有効な音声生成ボタンの押下時だけ開く。
- [ ] 同一言語では未生成音声だけを生成し、別言語では原稿再生成から開始する。
- [ ] APIは `spoken_text` 不足を422で拒否する。
- [ ] コース未選択、準備中、原稿不足、準備完了、言語変更の各状態をテストする。
