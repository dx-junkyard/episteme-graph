## §1 ビジョン（要旨）

1. **個人の理解ネットワークは重なるが同じではない**。一つの論文のあるパーツを取り上げて
   学習者が自分なりの理解を深めていくネットワークと、同じ論文の同じパーツを別の人が
   取り上げて深めるネットワークは、重なりやすいが同一ではない。
2. **重ね合わせから未登録の知識が浮かび上がる**。既知の領域であれば、多くの人々の理解の
   ネットワークを重ねることで、episteme-graph に登録されていなかった知識が浮かび上がる。
   これは異なる論文が共通のパーツを使ったときにも生じる。
3. **同一性の整理問題**。取り上げる論文が異なると、本来同じパーツであるはずのものが
   別物に見える場合がある。「実は同じものである」という整理が必要になる。ただし、
   分野ごと・論文ごとに異なる表現を**潰してしまうと、その論文との接続が悪くなる**。
4. **標準化済みと未発見の混在**。episteme-graph のコンポーネント/パーツは論文に紐づく形で
   検出されるが、科学の分野では既に標準化されたパーツとして認識されているものが大量にあり、
   それと「未発見の共通パーツ」が混ざる。前者は、その時点の上位モデル（frontier LLM）を
   参照することで判別できる可能性が高い。
5. **個人ネットワークを公共ネットワークと比較しながら育てる**。学習者が自分の中の
   知識ネットワークを、世間一般の知識ネットワークと比較しながら育てていける体験。
6. **全体の完成形は無い**。知識ネットワークは全体で一つの完成形があるのではなく、
   近傍との関係でのみ成り立つ小さなネットワークが幾重にも重なり、全体として堅牢な
   「一つのネットワークに**見える**」状態を目指す。ネットワークの一地点にいる人は、
   自分の知識を起点に構築されるネットワークとの接続で提示された知識を理解し、
   つながりが見出せないときは、手に取った論文を起点とする局所ネットワークから、
   関心が芽生えるネットワークをたどる**旅**に出る。

## §2 妥当性の根拠 — 既存公理との同型性

このビジョンは方針転換ではなく、**本システムがバラバラに選んできた設計公理に名前を付け、
学習者のネットワークにまで拡張したもの**である。同型性の証拠:

| 既存の設計判断 | ビジョンとの対応 |
|---|---|
| D層: 検証を単一ブールにせず `verification_scopes`（条件・領域・精度の**配列**）。全称検証の構造的禁止 | 「知識は近傍との関係でのみ成り立つ」（§1-6）の認識論版 |
| atlas: 踏破率を数値にしない・宣言しない・全体完成を演出しない | 「全体の完成形は無い」（§1-6） |
| `theory_claims` が `text` と `normalized_text` を**両方**保持 / P4 情報を落とさない | 「論文ごとの表現を潰さない」（§1-3）の既存前例 |
| C層: 同一コンポーネントに複数の説明バージョン（`kind='personal'`）が**並存**。マージしない | 「同じパーツへの各人の理解は重なるが同じではない」（§1-1）を教員向けに制度化済み |
| D層 assumption mining: 2論文以上の反復のみ候補化（コーパス横断クラスタ） | 「重ね合わせから未登録知識が浮かぶ」（§1-2）のコーパス版を既に実装済み |
| atlas の3層モデル（S=骨格 / C=コーパス / P=個人層） | 「個人ネットワークを公共ネットワークに重ねて見る」（§1-5）の骨組み |

## §3 ビジョンへの修正 4点

原案は妥当だが、以下4点を精密化しないと実装で誤る。

### 修正① 重ね合わせは3系統あり、浮かぶ知識の質が違う — 混ぜない

「多くの人々のネットワークを重ねると未登録の知識が浮かぶ」は、**誰の**ネットワークを
重ねるかで浮かぶものが異なる:

| 重ねる対象 | 浮かび上がるもの | 既存機構 | プライバシー体制 |
|---|---|---|---|
| **コーパス（論文群）** | ドメイン知識の候補（暗黙前提・未発見の共通パーツ） | D層 assumption mining / corpus_audit | 不要（公開文献） |
| **専門家（教員）の検討** | 解釈・意味づけの知識 | C層 explanations + W層注釈 | 帰属必須・匿名なし |
| **学習者のネットワーク** | **理解の経路の知識**（どこで繋がりが見出しにくいか・多くの人がどの橋を架けるか・つまづき） | interest_traces / stumble 集約 | k-匿名 k=3・本人確定 trace のみ・評価利用禁止（P3） |

学習者の重ね合わせから浮かぶのは主に*教育的*知識であって、ドメイン知識ではない。
学習者の素朴な連想がドメイン知識候補に混入しないよう、**3系統は別パイプライン・
別ラベル・別信頼度で扱う**（不変条項 KN-4）。

### 修正② 同一性は「マージ」ではなく「リンク」で表現する

「表現を潰すと接続が悪くなる」（§1-3）の解は、正規化をやめることではなく、
**正規化を「置換」でなく「追加」にする**こと:

```
共通パーツ（L層 library_entry）＝ハブ
   ├─ instance_of ← 論文Aの component_x（Aの表記・文脈のまま非改変で保持）
   ├─ instance_of ← 論文Bの equation_y（Bの表記のまま保持）
   └─ local_expressions: [{document_id, その論文での label / notation / 文脈}]
```

- 各論文側のインスタンスは**何も書き換えない**（A層非改変とも整合）。
- ハブ（library_entry）が「この分野ではこう呼ぶ / この論文ではこう書く」の**対応表を
  持つ側**になる。`aliases` は既存。`local_expressions`（出所付き表現リスト）を追加する。
- 同一性リンク自体も **candidate → 人間確定**の状態遷移（誤った同一視は誤った知識より
  有害。AIに確定させない既存原則がそのまま適用される）。
- W層設計の「昇格・統合」の意味論は「重心の移動」ではなく「**リンクの追加（非破壊）**」
  と読み替える（Phase W-α で W層設計書に反映）。

### 修正③ 標準化判定は上位モデル単独ではなく三角測量

上位モデル参照（§1-4）は概ね有効だが、2つの失敗モードがある: LLM が標準だと**幻覚する**
（もっともらしい正準名を捏造）/ 分派分野の別名を**見逃す**。よって3つの証拠の収束で判定する:

1. **LLM 事前知識** — 「これは標準的な概念/装置か？正準名は？」（structured output・
   candidate 止まり・claimed canonical name は教員レビューの証拠として記録）
2. **L層凍結版との類似** — その分野コミュニティ自身が既に標準化したもの（retrieval）
3. **コーパス内反復** — episteme-graph 内で複数論文に出現するか（D層と同じ閾値思想）

判定語彙（二値にしない）:

| standardization_status | 意味 |
|---|---|
| `standard` | 教科書級の標準（3証拠が収束） |
| `field_standard` | 分野内では標準（L層/コーパスが支持、LLM 一般知識では弱い） |
| `emerging_common` | **コーパス内で反復するが外部標準なし＝未発見の共通パーツ候補** |
| `novel` | 単一論文のみ・外部標準なし |
| `unknown` | 判定不能（そのまま保持、P4） |

`emerging_common` こそが本システムの発見的価値の在り処。「標準化済みと未発見が混ざる」
問題（§1-4）は、**混ざったまま候補化 → このラベルで分離 → 人間確定**という既存の流儀で解く。

### 修正④ 断片化リスク — 「一つに見える」はタダでは実現しない

局所ネットワーク優先の実リスクは全体主義ではなく**孤島化**（旅に出る前に迷子になる）。
「全体として一つに見える」性質は次の2投資で初めて成立する:

- **薄い共通骨格**: atlas skeleton（人間レビュー済み・凍結版）。骨格は「完成形」ではなく
  最小限の道路網。
- **リンク層**: 修正②の同一性リンクが局所ネットワーク間の橋。人間確定制ゆえ疎になりがち
  なので、候補提示（W層 cross-corpus レンズ）で確定コストを下げ続ける。

## §4 不変条項（KN-1〜KN-4）

子設計・実装はすべて以下を守る。既存の P1〜P7 系不変条項に追加される横断条項。

- **KN-1 神の視点を作らない**: 全体ネットワークを一枚にレンダリングする画面・API を
  作らない。**すべてのネットワーク表示は視点起点（egocentric）** — 論文起点・パーツ起点・
  学習者起点。「踏破率を数値にしない」と同族の、ビジョンを UI レベルで守る規約。
- **KN-2 正規化は追加、置換ではない**: 局所表現（論文の表記・分野の語彙）を書き換える
  経路を作らない。同一性はリンクで表現する（修正②）。`text`/`normalized_text` 並存
  パターンの一般化。
- **KN-3 同一視は人間が確定する**: identity link・標準化判定は常に candidate 始まり。
  LLM 出力による自動確定経路を作らない。確定・却下は状態遷移で保持（P4）し、
  `theory_review_events` に監査記録する。
- **KN-4 重ね合わせの3系統分離**: コーパス / 専門家 / 学習者の重ね合わせパイプラインを
  混ぜない（修正①）。学習者系は k-匿名（k=3・`core/privacy.py` 正本）・本人確定 trace のみ・
  評価利用禁止。学習者の素朴な連想をドメイン知識候補に自動昇格させない。

## §6 標準化判定の実装方針（Phase S の要求仕様）

- llm_worker 基盤の**6系統目アダプタ**として実装（CLAUDE.md 横断基盤ルール:
  コピペ禁止・15〜20行のアダプタで接続）。非同期・コスト上限独立
  （`STDPART_MAX_CALLS_PER_DAY` 等・fast tier 既定）。
- 三角測量（修正③）の3証拠を集め、`standardization_status` + 証拠 + reason + confidence を
  **candidate として** W層 `element_annotations`（`kind='standardization'`）に書く。
  **LLM がライブラリへ直接書き込む経路は作らない**（L層既存ガードレール維持）。
  教員確定で library_entry へ反映（W層コミットルーティング再利用）。
- U層計測: `feature='deliberation:standardization'`（または独立語彙。子設計で確定）。

## §7 フェーズ計画

| Phase | 内容 | 依存 | 規模 |
|---|---|---|---|
| **W-α** | W層設計書の改訂（コード無し）: 「昇格・統合」→「リンク追加（非破壊）」の意味論、`local_expressions`、`element_annotations.kind` に `identity` / `standardization` 追加 | なし | 小（文書のみ） |

推奨順序: W-α（即・コストゼロ）→ W層 Phase 0〜2 と W-β → S → P → B。
W-α を先に行う理由: W層は未実装であり、いま意味論を直すのはコストゼロだが、
実装後に「マージ→リンク」へ直すのは高くつく。

## §8 非スコープ・未決事項

**非スコープ（本ビジョンの範囲外）**:
- 学習者の個人ネットワークの他者への公開（本人のみ可視が既定。共有は将来別途）
- ネットワークの自動マージ・自動確定（KN-3 違反）
- 全体グラフの可視化ダッシュボード（KN-1 違反）

**未決事項**:
1. 標準化判定を独立設計書にするか W層設計書 §追補にするか（Phase S 着手時に判断）。
2. `element_identity_links` の対象を instance ↔ shared_part（ハブ経由）に限定するか、
   instance ↔ instance の直接リンクも許すか。ハブ経由限定が管理は単純（推奨）だが、
   ハブ未作成の2出現を先にリンクしたい場合の UX が課題。
3. 旅の経路探索の提示条件（いつ・どこで提示するか）。atlas 導線の抑制ルール
  （直近閲覧・カード最新1枚）と同じ流儀を踏襲する想定。
4. 個人ネットワークのノード導出規則の詳細（どの trace / どの状態を数えるか）は
   Phase P の設計書で確定する。
