# 前提の地図（D層 / doubt-atlas）の操作

「前提の地図」タブでは、認識的地位台帳（検証状態・検証スコープ）の記帳と、疑義の投稿・
取り下げ・検証提案への昇格を行います。

## 検証状態を記帳する {#record-verification-status}

**対象タブ:** 前提の地図（doubt-atlas） / **必要ロール:** 教員（TEACHER）以上

1. 「前提の地図」タブで、台帳ノード（前提・claim 等）の詳細を開きます。
2. 詳細ペインの「検証状態を記帳する」ボタンを押します。
3. 検証状態（未検証 / 間接的支持 / 直接検証 / 反証 等）を選び、理由を入力します。
4. 「記帳する」を押すと記録されます。この記帳はあなたの操作として帰属され、監査ログに
   残ります。

**直接検証（directly_verified）への昇格には、検証スコープが 1 件以上記帳されている
必要があります。** スコープが無い状態（空欄）はエラーではなく「まだ検証スコープが
記帳されていない」という事実であり、まずは「スコープを記帳」から検証スコープ
（成立条件・領域・精度・系のいずれか + 根拠 + 理由）を記帳してください。

## 疑義を取り下げる・検証提案にする {#manage-challenge}

**対象タブ:** 前提の地図（doubt-atlas） / **必要ロール:** 教員（TEACHER、自分が投稿した疑義のみ）

台帳ノードの詳細ペインの「疑義」セクションに、投稿済みの疑義が一覧表示されます。

- **取り下げ:** 自分が投稿した疑義の「取り下げ」ボタンを押します。取り下げは行削除では
  なく状態遷移（`withdrawn`）として記録され、履歴は保持されます。他の教員が投稿した
  疑義は取り下げられません（API が拒否します）。
- **検証提案にする:** 対応が必要な疑義を「検証提案にする」ボタンで検証提案へ昇格させ、
  未検証合意リストの解消に向けた具体的な検証手順を残します。**昇格には「コーパス外の確認」
  （この環境に取り込んだ論文の外で確認した文献・根拠）の記録が必須です**（空のままでは登録
  できません）。取り下げ済みの疑義は昇格できません。

## 覆る条件を記帳する {#falsification-conditions}

**対象タブ:** 前提の地図（doubt-atlas） / **必要ロール:** 教員（TEACHER）以上

台帳ノードの詳細ペインの「覆る条件」区画では、「この主張は何が起これば覆るのか」を記帳
します。検証スコープ（どこまで確かめられているか）と対になる記録です。

- **手で記帳する:** 「覆る条件を記帳する」を押し、条件の文・区分・到達可能性（この条件を
  実際に確かめられるか）・根拠・理由を入れて記帳します。**到達可能性は人が判断して記帳する
  項目で、AI は書き込みません。**
- **AI の候補から記帳する:** 「AIに候補を出してもらう」を押すと候補が並びます。候補は候補の
  ままで、教員が到達可能性を選んで「確認して記帳」を押すまで確定しません。「見送る」を選んだ
  候補も記録として残ります（行は消えません）。
- まだ何も記帳されていない場合は「覆る条件はまだ記帳されていません。」と表示されます。これは
  エラーではなく、そのままの事実です。

「未検証合意リスト」などに出る「このコーパスの中では検証記録が見つかりません。」という表示は、
**この環境に取り込んだ論文の中に記録が無い**という意味であって、分野全体で誰も検証していない
という意味ではありません。疑義を検証提案へ昇格させるときに「コーパス外の確認」の記録が必須に
なっているのはこのためです。
