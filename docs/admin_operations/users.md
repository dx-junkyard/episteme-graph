# グループ管理（groups）タブの操作

「グループ管理」タブでは、教材・コースをグループ内限定で共有するためのグループを
作成・管理します。学生・教員アカウントの作成は別タブに分かれています
（[学生アカウントを作成する](students.md#create-student) /
[教員アカウントを作成する](teachers.md#create-teacher) 参照）。

## グループを作成・招待する {#manage-groups}

**対象タブ:** グループ管理（groups） / **必要ロール:** 教員（TEACHER）以上

- **グループを作成する**: グループ名（説明は任意）を入力して「グループを作成」を押します。
  作成すると招待コードが発行されます。**確認ダイアログはありません。**
- **招待コードで参加する**: 他のユーザーから受け取った招待コードを入力して
  「招待コードで参加」を押すと、そのグループに参加します。
- **招待コードを再発行する**（グループの管理者のみ）: グループ詳細の「再発行」を押すと
  新しい招待コードが発行され、旧コードは無効になります。**確認ダイアログはありません。**
- **ユーザーを直接招待する**（グループの管理者のみ）: ユーザー名を入力して「招待」を押すと、
  相手の「未承諾の招待」一覧に届きます。相手が「承諾」または「辞退」するまでメンバーには
  なりません。
- **メンバーを除名する**（グループの管理者のみ）: メンバー一覧の「除名」を押すと、その場で
  除名されます。**確認ダイアログはありません。**
- **グループを退会する**（管理者以外の自分自身）: 自分の行の「退会」を押すと確認ダイアログの
  あとに退会します。
- **グループを削除する**（グループの管理者のみ）: 「グループを削除」を押すと確認ダイアログの
  あとにグループごと削除します。**この操作は取り消せません。**

# アカウントの一覧・停止・パスワード再設定・削除・移管

以下の操作は「学生管理（students）」タブと「教員管理（teachers）」タブで行います
（このファイルはアカウント運用の手順をまとめて置いてあります。グループ管理の手順は
上の節です）。正本仕様は `docs/features/account_lifecycle_management_design.md`。

**共通の原則:**

- **停止はログインの拒否だけです。** 停止しても、その人が所有する教材・コースの共有は
  切れず、学習者の受講も続きます。所有者・可視性・グループ・受講状態は変わりません。
- **すでに動き出している背景処理は完走します。** 解析パイプラインや音声一括生成は認証を
  通らないため、停止後もキュー済みの処理は走ります（停止は「進行中ジョブの中断」では
  ありません）。
- **アカウントは行ごと消えません。** 削除は「予約 → 猶予 → 個人データの消去 + 匿名化
  （墓標化）」で行います。承認・引用・疑義・監査などの共同体の記録は残り、表示名だけが
  匿名（`deleted-xxxxxxxx`）になります。
- 学生の利用実績・認証イベントは**アカウント運用（不正利用・休眠の検知）のためだけに**
  使います。学習評価には使いません。

## アカウントを一覧する {#list-users}

**対象タブ:** 学生管理（students） / 教員管理（teachers） / **必要ロール:** 教員（TEACHER）以上

- 一覧には ユーザー名 / メール / 状態 / 最終ログイン / 最終アクセス が出ます。
- **教員（TEACHER）に見えるのは学生アカウントだけです。** 教員・管理者アカウントの
  一覧は管理者（SYSTEM_ADMIN）のみが見られます。
- 状態は `有効` / `停止中` / `削除予定` / `削除済み` の4つです。
- 最終アクセスは書き込み量を抑えるため数分間隔で更新される目安の値です（画面にも同じ注記が
  出ます）。
- 絞り込み欄にはユーザー名・メールの一部を入れられます（入力して「一覧を更新」または Enter）。
  一覧は一度に最大 200 件です。

## 学生アカウントを停止する {#suspend-student}

**対象タブ:** 学生管理（students） / **必要ロール:** 教員（TEACHER）以上

- 対象の行の「停止…」を押し、**理由を入力**して確定します（理由は必須で、監査記録に
  残ります）。
- 停止すると、その学生は新しくログインできず、ログイン中でも最大30秒以内に全操作が
  拒否されます。
- **停止は「再開」で元に戻せます。**
- **ボタンが無効になっている場合:** ①対象がすでに停止中・削除予定・削除済み
  （→ 状態列を確認してください。再開したいときは「再開」を使います）②対象が
  教員・管理者アカウント（→ 管理者（SYSTEM_ADMIN）のみが操作できます）③対象が自分自身、
  または初期管理者（Administrator）（→ 自分自身と初期管理者は停止できません。
  別の管理者に依頼してください）。

## 学生アカウントの停止を解除する {#restore-student}

**対象タブ:** 学生管理（students） / **必要ロール:** 教員（TEACHER）以上

- 停止中の行の「再開」を押すとその場で再開します。停止の理由は監査記録に残ります。
- **ボタンが無効になっている場合:** 対象が停止中ではありません。削除予定の場合は
  「削除予約を取消」を使ってください（「再開」では削除予約は解除されません）。

## 教員アカウントを停止する {#suspend-teacher}

**対象タブ:** 教員管理（teachers） / **必要ロール:** 管理者（SYSTEM_ADMIN）のみ

- 手順は学生の停止と同じです（「停止…」→ 理由入力）。
- **その教員が所有する教材・コースは停止しても生き続けます。** 共有先の教員は今まで
  どおり閲覧でき、学習者は受講を続けられます。学習者側に教員の停止は表示されません。
- **ボタンが無効になっている場合:** ①対象がすでに停止中・削除予定・削除済み
  ②対象が自分自身、または初期管理者（Administrator）。

## 教員アカウントの停止を解除する {#restore-teacher}

**対象タブ:** 教員管理（teachers） / **必要ロール:** 管理者（SYSTEM_ADMIN）のみ

- 停止中の行の「再開」を押すとその場で再開します。
- **ボタンが無効になっている場合:** 対象が停止中ではありません（削除予定の場合は
  「削除予約を取消」を使ってください）。

## パスワードを再設定する {#password-reset}

**対象タブ:** 学生管理（students） / 教員管理（teachers） / **必要ロール:** 管理者（SYSTEM_ADMIN）のみ

- 対象の行の「パスワード再設定…」を押し、新しいパスワード（8文字以上）を入れて確定します。
- **この操作は取り消せません。** 旧パスワードは復元できません。
- **対象の発行済みトークンはすべて失効します**（その人はログインし直す必要があります）。
- 自分自身に対して実行した場合は**自分もログアウトされます**（確定後にログイン画面へ
  移動します）。
- 新しいパスワードは対象の本人へ、システム外の安全な手段で伝えてください。パスワードは
  監査記録にもログにも残りません（記録されるのは「誰がいつ再設定したか」だけです）。
- 学生のパスワード再設定も管理者のみが行えます（教員はできません）。
- **ボタンが表示されない場合:** 教員（TEACHER）でログインしています。管理者
  （SYSTEM_ADMIN）でログインし直してください。

## アカウントの削除を予約する {#schedule-deletion}

**対象タブ:** 教員管理（teachers） / 学生管理（students） / **必要ロール:** 管理者（SYSTEM_ADMIN）のみ

- **先に停止してください。** 削除を予約できるのは停止中のアカウントだけです。
- 「削除予約…」を押し、猶予日数（既定14日）を確認して確定します。確認欄には対象の
  ユーザー名を入力します。
- 猶予中は「削除予約を取消」でいつでも戻せます（状態は停止中に戻ります）。
- 猶予が過ぎると、そのアカウントの個人データ（受講状態・会話履歴・学習痕跡・通知・
  グループ所属・個人設定）が消去され、アカウント行は匿名化されます。
- **所有物が残っているアカウントは削除されません。** 教材・コース・グループが1件でも
  残っていると削除は中止され、管理者の通知に「移管または削除してから再実行されます」と
  いう事実が届きます。先に「移管…」で後任へ渡すか、教材・コースを個別に削除してください
  （受講中の学習者を巻き添えで消さないための仕組みです）。
- **ボタンが無効になっている場合:** ①対象が停止中ではない（→ 先に「停止…」を実行）
  ②対象が自分自身、または初期管理者（Administrator）③教員（TEACHER）でログインしている
  （→ 管理者でログインし直してください）。

## 所有物を別の教員へ移管する {#transfer-ownership}

**対象タブ:** 教員管理（teachers） / **必要ロール:** 管理者（SYSTEM_ADMIN）のみ

- 「移管…」を押し、移管先の教員を選んで確定します。教材（アップロード者）・コース
  （所有者）・グループ（作成者）の所有者が後任に切り替わります。
- グループを移管すると、移管先はそのグループの管理者として登録されます。
- 受講者の学習状態・共有設定・発行済みの版はそのまま生きます。発行済みの版の
  「発行者」表示は当時の事実なので付け替えません。
- **この操作は取り消せません**（逆向きの移管はできますが、元の状態に自動で戻す機能は
  ありません）。
- **移管先に指定できないもの:** ①学生アカウント ②停止中・削除予定・削除済みの
  アカウント ③移管元と同じアカウント。いずれも確定時に理由が表示されます。

## アカウントの利用状況を確認する {#user-activity}

**対象タブ:** 教員管理（teachers） / 学生管理（students） / **必要ロール:** 管理者（SYSTEM_ADMIN）のみ

- 対象の行の「利用状況…」を押すと、認証イベント（ログイン成功・失敗・停止中の試行・
  トークン失効）の時系列と、直近30日の AI トークン利用サマリが出ます。
- トークン数は**実測（reported）と推計（estimated）を分けて**表示します。合算した
  単一の数値は出しません。
- 集計できなかった場合はサマリ部分だけが「利用実績を取得できませんでした」になります
  （認証イベントの表示は続きます）。
- **この情報を学習評価に使わないでください。** 用途はアカウント運用に限られます。
