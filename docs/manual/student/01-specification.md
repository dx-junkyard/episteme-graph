# 仕様編（学生にも共通する全体像）

[← マニュアル目次](../README.md)

このページは episteme-graph の全体像を、学習者（学生）の立場から解説します。
まずこのページで全体の地図を掴んでから、[受講者向けマニュアル](02-student.md) に進んでください。

より詳しい設計・実装解説は [docs/](../../README.md) にまとまっています。本ページはその要点を利用者視点で再構成したものです。

---

## 1. システム概要とコンセプト {#overview}

episteme-graph は、大学院生の学習プロセスを支援する **知識グラフ管理システム** です。PDF 論文をアップロードするだけで、そこに含まれる概念・主張・数式・関係性を自動抽出してナレッジグラフ・理論操作グラフを構築し、それを土台に対話型（RAG チャット）・没入型（音声講義）の学習体験を提供します。

研究者・大学院生が直面する「散在する先行研究の統合」と「前提知識の体系的習得」という課題を解決するため、システムは次の層で設計されています。

| 層 | やること |
|---|---|
| ① 知識の構造化（A層） | PDF をアップロードするだけで、概念・主張・数式・導出を PDF 解析エージェントパイプラインが構造化し、概念グラフ・理論操作グラフを自動生成する |
| ② 適応的学習（B層） | 習得状態・関心痕跡・違和感（tension）を追跡し、前提知識に応じた問いかけで理解を深める |
| ③ 没入型講義 | TTS 音声＋カラオケ式ハイライトで、論文をセミナー形式の講義に変換する |
| ④ 承認・共有（C層） | 教員が説明バージョン単位で査読承認し、教員間で解釈を共有する |

これらの層は独立したモジュールとして実装されており、A層（知識の構造化パイプライン）を書き換えることなく、B層・C層以降が積み上げられています。以降も同じやり方で、再構成ループ（学んだ内容を自分の言葉で言い直す練習）、個人の知識ネットワーク（わたしの地図）、論文そのものと議論するモード、コースの外の論文を見わたす「論文の海」などが、既存の層に手を入れずに積み上げられています。

学習 UI（受講者向け）は、担当の教員またはシステム管理者から案内されるアドレスからアクセスします。教材のアップロードやコース作成を行う管理用の画面は別に用意されており、受講者はそちらを操作する必要はありません。

## 2. データフロー {#data-flow}

### 2.1 PDF → ナレッジグラフ（教材投入、主に教員が実行）{#pdf-to-graph}

```
PDF アップロード
  → MinIO 保存 → GROBID / PyMuPDF でテキスト化
  → PDF解析 Agent パイプライン（2026-09-03 時点、名前付き 29 ステージ）で
     構造・主張（claim）・数式・導出・理論操作グラフを段階的に生成
  → チャンク＋埋め込みを PostgreSQL(pgvector) へ
  → 理論コンポーネント・理論操作グラフを PostgreSQL へ / 図画像を MinIO へ
  → コースビルダーでコース化 → 公開
```

パイプラインは「文書構造の復元（structure-first）」から始まり、以降は「主張の採否・区分」「数式の意味・導出チェーン」「中心命題の再構成」「DSL 接続」「再利用可能コンポーネントの生成」「理論操作グラフの構築」という順で、粗い物理的な塊（ブロック）から意味を持つ最小命題（atomic claim）、さらに再利用可能な理論部品（theory component）へと積み上げます。各出力には根拠（`reason`）と確信度（`confidence`）が付与され、不明な点は削除せず `unknown` / `deferred` / `review_required` として保持されます。

詳細は [PDF 解析パイプライン概要](../../pipeline/overview.md) を参照してください。

### 2.2 学習の流れ（受講、主に受講者が実行）{#learning-flow}

```
公開コースを受講登録（学習状態に1行 INSERT。コース本体は複製しない）
  → 学び方を選ぶ（順番に学ぶ / 論文と議論する）
  → トピック選択 → RAG チャットで質問
     （ベクトル検索（tier 付き）+ 履歴 → LLM 回答）
  → 誤解検出・前提知識チェック・学習進捗トラッキング
  → レクチャーモードで TTS 音声 + ハイライト講義
```

コースの外から論文を見わたして議論を始める入口（「論文の海」）もあり、こちらは受講登録なしで、
自分が閲覧できる論文だけを対象に動きます。

コース本体（マスター）は不変で、受講者ごとの学習状態（進捗・誤解・関心痕跡など）は別に分離して保存されます。受講登録は公開テンプレートのコースを複製するのではなく、個人の学習状態を1行追加するだけの軽量な操作です。

詳細は [学習機能（学生UI）](../../features/learning.md) を参照してください。

## 3. 開示範囲（Visibility）{#visibility}

教材（Document）やコース（LearningCourse）は、次のいずれかの開示範囲を持ちます。

| 開示範囲 | 意味 | アクセス可否 |
|---|---|---|
| Public | システム全体（全ユーザー）に公開 | 全ユーザーが閲覧可能（コースの場合は公開済みのテンプレートのときのみ） |
| Group | 指定されたグループの参加メンバーのみアクセス可能 | 対象グループに所属し、かつ閲覧・編集の権限を持つメンバー |
| Private | 作成者（自分）のみアクセス可能 | オーナーのみ |

グループへの参加は、管理者による直接招待、または招待コードのいずれかの経路で行われます。

詳細は [認証・権限・開示範囲](../../features/auth-visibility.md) を参照してください。

## 4. 用語集 {#glossary}

| 用語 | 説明 |
|---|---|
| ナレッジグラフ | PDF から抽出した概念・主張・数式・関係性をグラフ構造で表現したものです。 |
| 理論操作グラフ（TheoryOperationGraph） | 論文の「理論操作の構造」を表すグラフです。理論構成を表す少数の集約ノードからなる `main` 層と、式単位の step を保持する `equation_detail` 層に分かれます。全ノード・エッジにソースバッキングの状態を明示します。 |
| ソースバッキング | ナレッジグラフ・理論操作グラフの各ノード・エッジが、どのソース（式・主張・エビデンス・導出）に裏付けられているかを示す状態です。「確定」「一部裏付けあり」「推測」「要確認」の4段階で明示され、確定はしません。 |
| claim（主張） | 「1 主張 = 1 最小命題」に正規化された、意味抽出の中核単位です。 |
| チャンク | 文書をセクション境界内で束ねた、埋め込み・RAG 検索の単位です。 |
| DSL | 概念間の抽象構造を1行で表現する独自の記法です。 |
| カートリッジ | ドメイン固有の語彙・検証ルール・成熟度定義などを外部化したものです。カートリッジが無くても各機能は単独動作します。 |
| RAG チャット | ベクトル検索で関連チャンクを取得し、それを根拠として LLM が回答する対話型学習機能です。質問の種類を選ぶ操作はなく、送信ボタンは 1 つだけです。 |
| content_grounding（出所） | RAG チャットの回答が何に基づくかを示す軸です。「教材から回答」「別の資料から回答」「AI の一般知識（出典なし）」の 3 値で判定され、回答バブルと出典タブに表示されます。教員承認状況を示す `tier` とは別軸です。 |
| tier | RAG チャットで採用されたチャンクに付与される、教員承認状況から導出される信頼性の指標です。回答の出所を示す `content_grounding` とは別軸として扱われます。 |
| tension（違和感） | 対話ログから検出される、「理解した上での引っかかり」の候補です。断定はされず、本人が確認画面で「そう、これ」（確定）または「違う」（却下）を選ぶまでは候補のままとなり、教員へは匿名化された集計のみが示されます。 |
| 問いの軌跡 | 学習者が確定させた関心痕跡（tension の確定・帰属付きの問いなど）の記録です。学習進捗タブに表示され、個人の知識ネットワーク（わたしの地図）の材料になります。 |
| 説明バージョン | 1 つの理論コンポーネントに対して複数並存できる説明の版です。AI 由来の標準の説明と、教員が書く独自解釈が並存します。 |
| 承認（endorsement） | 教員が説明バージョン単位（コンポーネント単位ではない）で行う査読承認です。承認は 1 行ずつ記録され、承認の重みは人数・レベル・専門性の広がりから段階ラベル（例:「専門家3名が承認」）として表示されます。数値スコアは学習者には表示されません。 |
| 理論コンポーネント | 採択済みの claim・数式・中心命題（thesis）を束ねて組み上げる、再利用可能な理論部品の単位です。コースや説明生成で再利用されます。 |
| 分野の地図（Field Atlas） | 学習中の箇所が分野全体のどこに位置するかを示す、全画面オーバーレイと常設ミニマップの機能です。踏破率を数値化しない、宣言しない、煽らないことを設計原則としています。 |
| わたしの地図 | 学習者本人が確定させた痕跡（tension の確定・帰属付きの問い・再構成の成功など）から、毎回決定論的に導出される個人の知識ネットワークです。保存物ではなく都度導出され、本人にしか見えません。 |
| わたしの記録 | 学習者本人が残したすべての痕跡（確定したもの・見送ったもの・置き換えられた以前のものを含む）の一覧です。本人だけが読め、JSON ファイルとして持ち出せます。 |
| 論文の海 | コースの受講とは関係なく、自分が閲覧できる論文を分野の地図の上で見わたし、そこから論文と直接議論できる画面です。表示されるのは自分が閲覧できる論文だけで、分野の論文の全体ではありません。 |
| 再構成ループ | 学習者に理論の再構成（予測・言い直し）をさせ、元の資料の記述を答えキー（ground truth）として非 LLM の構造照合でズレを検出し、事実として提示する閉ループの学習機構です。数値スコア・正答率は学習者には表示されません。 |
| スキーマ進化 | 固定の概念カテゴリ・関係種別を超えて、運用中に得られた学生の未回答質問からグラフ DSL の語彙を成長させる仕組みです。未回答クエリの蓄積 → スキーマ提案の生成 → 事前検証 → 教員の承認 → 既存教材の再抽出、という流れで進みます。 |

## 5. 全機能に共通する設計原則 {#common-principles}

複数の機能・レイヤーにまたがって適用されている、システム全体の設計原則です。

- **マスターコースと個人進捗の分離** — コース本体（不変のマスター）と、受講者ごとの学習状態（可変）は分離されています。公開テンプレートをクローンするのではなく、マスターを単一の真実として扱い、受講者の進捗だけを個別に保持します。
- **数値スコアを学習者に見せない** — 承認の厚み（endorsement）、tension・再構成ループの確信度や正誤判定、負荷度など、内部で計算される数値は学習者・教員向けの表示では段階ラベルや事実文に変換され、生の数値スコアとしては提示されません。
- **k-匿名（最小集計単位=3、件数はレンジ表示）** — tension の集計や関心・違和感の匿名化ダッシュボードなど、学習者個人の痕跡を教員向けに集計する箇所では、最小集計単位を 3 とし、該当件数がそれ未満のセルは非表示にします。件数を出す場合も具体的な数値ではなくレンジ（3-5 / 6-10 / 11+ など）で表示し、個人が特定されない形に留めます。
- **学習痕跡は本人のみ可視・成績評価に使わない** — tension、問いの軌跡、わたしの地図などの学習者個人の痕跡は本人にのみ表示され、教員・管理者は個別の記録にアクセスできません（アクセスできるのは匿名化された集計のみ）。これらの記録は成績評価には使用されません。

## 6. あなたについて集計される計器 {#institutional-indicators}

このシステムには、**制度そのものを観察するための計器**（集計）がいくつかあります。
授業やシステムがうまく働いているかを運営側が見直すためのもので、
**あなた個人を測るためのものではありません**。

すべての計器に共通して、次のことが決まっています。

- **個人のランキング・順位付けには使いません。**
- **成績評価には使いません。**
- **個人向けの推薦の入力には使いません。**
- **自動的な判定・切り替え（自動ゲート）には使いません。**
- 教員向けの集計は **k-匿名（最小集計単位 3）** です。関わった人数が 3 人に満たない
  セルは表示されず、件数も具体的な数ではなくレンジ（3-5 / 6-10 / 11+ など）で示されます。
- **質問の文面・発話の逐語は集計に使いません**（数えるのは「どこに」「何件」だけです）。

学習者の活動が入りうる計器は次のとおりです。かっこ内は、その計器が数えるものです。

| 計器の名前 | 何が数えられるか |
|---|---|
| 関心集約ダッシュボード | コースの中で、どのトピックに問い・引っかかりが集まっているか |
| 橋の候補（学習者の重ね合わせ） | あなたが自分の引っかかりを理論の部品に**自分で**結び付けた先 |
| 問いの帰属インサイト | 問いが理論構成のどの段階の、どういう型の引っかかりだったか |
| 素朴な問いの集計 | どの前提の手前で複数の人がつまずいているか |
| 地図の端への関心 | 分野の地図のどの縁に「この先を知りたい」が向いているか |
| 再構成の出題レビューキュー | 再構成の出題そのものが壊れていないかを見るための誤り率など |
| 主張ごとのつまづきサマリー | 教材のどの主張で、つまずきや質問が多いか |
| 使い方の質問の未整備箇所 | 使い方の質問のうち、マニュアルに説明が見つからなかった箇所 |
| 論文ディスカッションの観測状況 | 「論文と話す」がどれだけ使われたか（**発話の本文は含みません**） |
| LLM使用量メトリクス | システム全体で消費された AI のトークン量（誰の発言かは数えません） |
| わたしの記録 | あなたが残した痕跡の一覧（**あなたにしか見えません**） |

これらの計器の**定義・目的・元になるデータ・保持のしかた・使わない用途**は、
「制度指標カタログ」として全員が読める形で公開されています。上の表がその一覧です
（システムに問い合わせて同じ内容を読むこともできます）。

**AI が推測しただけの候補は数えません。** 引っかかりの候補や、問いがどこに向いているかの
推定は、あなた自身が「そうだ」と確定したものだけが集計に入ります。

自分について何が記録されているかは、いつでも「わたしの記録」から一覧・持ち出しできます。
