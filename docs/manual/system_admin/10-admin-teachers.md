# 教員管理（管理画面）

[← マニュアル索引](../README.md)

## 画面の概要 {#overview}

「教員管理」タブでは、教員（TEACHER）のアカウントを作成し、作成済みのアカウントを一覧で
確認・運用（停止・再開・パスワード再設定・利用状況の確認・削除予約・所有物の移管）します。
**このタブはシステム管理者（SYSTEM_ADMIN）ロールでログインしたときのみ表示されます。**
教員（TEACHER）ロールのアカウントには、このタブ自体が表示されません。教員アカウントの作成・
運用は、システム管理者のみが実行できる操作です。

なお、受講者（STUDENT）アカウントの作成は「学生管理」タブから行います。学生管理タブは
教員（TEACHER）以上のロールに表示されるタブで、教員管理タブとは別画面です。

---

## 教員アカウントの作成 {#create-form}

### 教員を作成する {#teacher-form}

新しい教員（TEACHER）アカウントを作成します。手順の詳細は
[教員アカウントを作成する](../../admin_operations/teachers.md#create-teacher) も参照してください。

1. 「ユーザー名」欄にログイン用のユーザー名を入力します（必須）。
2. 「メールアドレス」欄にメールアドレスを入力します（任意）。空欄のまま作成すると、
   ユーザー名から自動生成されたメールアドレスが割り当てられます。
3. 「パスワード」欄に初期パスワードを入力します（必須）。
4. 「教員を作成」を選びます。

ユーザー名・パスワードが未入力のまま送信しようとすると、ブラウザの入力チェックで
送信がブロックされます。送信すると確認ダイアログを挟まず、その場でアカウントが
作成されます。

作成したユーザー名が既に使用されている場合は、フォーム下にエラーメッセージが表示され、
アカウントは作成されません。作成に成功すると、作成した教員のユーザー名を含む成功
メッセージが表示され、フォームは空欄に戻ります。

作成した教員のログイン情報（ユーザー名・初期パスワード）は、本人に個別に伝えてください。

**このタブ自体が表示されない場合**: ログイン中のアカウントのロールが
システム管理者（SYSTEM_ADMIN）でないためです。教員アカウントの作成が必要な場合は、
システム管理者に依頼してください。

## 教員アカウントの運用 {#operations}

### 教員アカウント一覧 {#user-list}

作成フォームの下に、教員（TEACHER）アカウントの一覧が表示されます。列は「ユーザー名 /
メール / 状態 / 最終ログイン / 最終アクセス / 操作」です。

- **状態**: 「有効」「停止中」「削除予定」「削除済み」のいずれかが表示されます。
  「削除済み」の行には操作ボタンが表示されません。
- **最終ログイン**: 最後にログインに成功した日時です。
- **最終アクセス**: 最後に画面・APIを利用した日時です。書き込みを抑えるため数分間隔で
  更新される目安の値で、秒単位の正確さはありません。記録がない場合は「—」が表示されます。

一覧は、このタブを開いたとき、操作が成功したとき、「一覧を更新」を選んだときに読み込まれます。
自動更新（一定間隔での再取得）は行いません。検索欄にユーザー名またはメールの一部を入力して
Enter キーを押すか「一覧を更新」を選ぶと、一致するアカウントだけが表示されます。

一覧が「一覧を取得できませんでした」と表示される場合は、表示されている理由の文をそのまま
確認してください。権限が足りない場合は、システム管理者（SYSTEM_ADMIN）でログインし直します。

### 停止と再開 {#user-suspend}

**停止**（「停止…」）は、そのアカウントのログインを拒否する操作です。

1. 対象の行で「停止…」を選びます。
2. 停止の理由の入力を求められます。**理由は必須です**（監査記録に残ります）。空欄のまま
   進めると「停止の理由を入力してください」と表示され、停止は実行されません。
3. 入力すると、その場で停止が実行されます。

停止の効果は**ログインの拒否だけ**です。停止しても、そのアカウントが所有する教材・コース・
グループの所有者は変わらず、共有設定・受講者の学習状態も変わりません。共有先の教員は引き続き
教材を閲覧でき、受講者は引き続き学習できます。

停止する前に始まっていた解析・音声生成などのバックグラウンド処理は、停止後もそのまま完了まで
進みます（停止は「認証の拒否」であって、進行中の処理の中断ではありません）。

**再開**（「再開」）は、停止中のアカウントを有効に戻します。理由の入力はありません。再開すると
再びログインできるようになります。

**「停止…」が無効（押せない状態）になっている場合**: 対象が自分自身のアカウント、または
システムが最初に作成した `Administrator` アカウントです。この2つは、システムから誰も入れなく
なる事故を防ぐため停止できません。別のアカウントを停止したい場合は対象の行で操作し、自分の
アカウントを止めたい場合は別のシステム管理者に依頼してください。

### パスワード再設定 {#user-reset}

「パスワード再設定…」は、対象アカウントのパスワードを新しい値に置き換えます。パスワードの
再設定は、対象が教員でも学生でも**システム管理者（SYSTEM_ADMIN）のみ**が実行できます。

1. 対象の行で「パスワード再設定…」を選びます。
2. 新しいパスワードを入力します（**8文字以上**）。確認欄にも同じ値を入力します。
   8文字未満のとき、または2つの入力が一致しないときは、理由が表示され「再設定する」は
   押せません。
3. 「再設定する」を選ぶと、その場で再設定されます。

再設定すると、そのアカウントで発行済みのログイン状態（トークン）はすべて無効になります。
本人が別の端末で開いていた画面も、次の操作でログイン画面に戻ります。新しいパスワードは
画面に再表示されないため、その場で控えて本人に個別に伝えてください。

**自分自身のパスワードを再設定した場合**: いま使っているログイン状態も無効になります。
「再ログインが必要です」という案内が表示され、そのままログイン画面に戻ります。新しい
パスワードでログインし直してください。

### 利用状況の見方 {#user-activity}

「利用状況…」は、対象アカウントの認証記録とAI（LLM）利用実績を1つの画面で表示します。
この画面は**システム管理者（SYSTEM_ADMIN）のみ**が開けます。

- **最終ログイン / 最終アクセス**: 一覧と同じ値です。記録がなければ「記録がありません」と
  表示されます。
- **ログインの記録**: 新しい順の時系列です。「できごと」の欄には次のいずれかが入ります。
  「ログイン成功」「ログイン失敗」「停止中のログイン試行」「停止中のアクセス」
  「失効トークンのアクセス」「パスワード再設定」。IPアドレス・ブラウザ（User-Agent）は
  記録があるときだけ表示され、無いときは「—」になります。
- **AI（LLM）の利用実績**: 直近の一定期間（既定30日）の記録です。「実測（プロバイダの
  報告値）」と「推計（トークン数の換算値）」は**別の行として並べて**表示されます。
  実測と推計を足し合わせた1つの数値は表示しません。
  バックグラウンドのバッチ処理は特定の利用者に結び付かない「未帰属」として記録されるため、
  ここには出ません。実績が取得できなかった場合は「利用実績を取得できませんでした」と
  表示されます（記録がゼロであることを意味しません）。

この記録はアカウント運用（不正利用・休眠アカウントの確認）のために表示しています。
**学習の評価には使いません。** 学生の個別の記録も同じ扱いで、教員（TEACHER）ロールには
表示されません。

### 削除予約と取消 {#user-delete}

「削除予約…」は、アカウントの削除を予約する操作です。すぐには消えません。

1. 対象を**停止**します（削除予約は停止中のアカウントにしかできません）。
2. 所有物がある場合は、先に「[所有物の移管](#user-transfer)」で引き継ぎ先を決めます。
3. 「削除予約…」を選び、必要なら猶予日数を入力します（空欄のままだと既定の14日）。
4. 確認のため、対象のユーザー名を正確に入力します。一致するまで「削除を予約する」は
   押せません。
5. 「削除を予約する」を選ぶと予約されます。状態は「削除予定」になります。

猶予期間の間は、行に表示される「削除予約を取消」でいつでも元に戻せます（停止中の状態に
戻ります）。

猶予期間が過ぎると、システムがアカウントを削除します。このとき、教材・コース・グループを
所有したままのアカウントは**削除されません**（所有物が巻き添えで消えることはありません）。
所有物が残っている間は削除は中止され、システム管理者に事実が通知されます。移管または個別の
削除を済ませると、次回以降に削除が進みます。

削除後もアカウントの行自体は「削除済み」として残り、監査記録・ログイン記録・利用実績は
保持されます。本人の学習履歴・会話・受信箱などの個人データは削除されます。

**「削除予約…」が無効（押せない状態）になっている場合**: 次のいずれかです。
- 対象が「有効」または「削除予定」の状態である → 削除予約は**停止中**のアカウントにだけ
  できます。まず「停止…」を実行してください（すでに「削除予定」なら予約済みです）。
- 対象が自分自身のアカウント、または `Administrator` である → この2つは削除できません。

### 所有物の移管 {#user-transfer}

「移管…」は、対象アカウントが所有する教材・コース・グループの所有者を、別の教員に
引き継ぐ操作です。

1. 対象の行で「移管…」を選びます。
2. 引き継ぎ先を選びます。候補は**有効な教員またはシステム管理者のアカウント**（対象本人を
   除く）です。管理者のアカウントは名前の後ろに「（管理者）」と表示されます。教員が1人しか
   いない環境では、管理者を引き継ぎ先にできます。
3. 「移管する」を選ぶと確認が表示されます。所有が移ること・元の所有者が自分の教材／
   コースとして操作できなくなることを確認して実行します。
4. 実行後、移した教材・コース・グループの件数が表示されます。

移管しても、受講者の学習状態・共有設定・発行済みの版はそのまま残ります。発行済みの版に
記録された発行者名は、発行時点の事実なので変わりません。

**「移管する」が無効（押せない状態）になっている場合**: 引き継ぎ先が選ばれていません。
一覧に候補が出ない場合は、引き継ぎ先にできる「有効な」教員・管理者アカウントが他にない
ためです。先に教員アカウントを作成するか、停止中のアカウントを再開してください。

## 学生アカウントへの操作（システム管理者のみ） {#student-operations}

「学生管理」タブの学生アカウント一覧には、教員（TEACHER）にも表示される「停止…」「再開」の
ほかに、**システム管理者（SYSTEM_ADMIN）のときだけ表示される操作**があります。操作の内容は
教員アカウントに対するものと同じです。

### パスワード再設定…（学生） {#student-user-reset}

学生アカウントのパスワードを新しい値に置き換えます。**システム管理者のみ**の操作です
（教員には、このボタン自体が表示されません）。入力の条件・再設定後にログイン状態が無効に
なることは教員アカウントと同じです。詳細は
[パスワード再設定](#user-reset) を参照してください。

**このボタンが表示されない場合**: ログイン中のアカウントが教員（TEACHER）ロールです。
学生のパスワード再設定が必要な場合は、システム管理者に依頼してください。

### 利用状況…（学生） {#student-user-activity}

学生アカウントの認証記録とAI（LLM）利用実績を表示します。**システム管理者のみ**の操作です。
表示内容は [利用状況の見方](#user-activity) と同じです。

学生個人の記録は、アカウント運用（不正利用・休眠アカウントの確認）のためだけに使います。
**学習の評価には使いません。** この画面を教員（TEACHER）に開放していないのは、学習者の
行動監視にしないためです。

**このボタンが表示されない場合**: ログイン中のアカウントが教員（TEACHER）ロールです。

### 削除予約…（学生） {#student-user-delete}

学生アカウントの削除を予約します。**システム管理者のみ**の操作です。手順・猶予期間・取消の
方法は [削除予約と取消](#user-delete) と同じです。学生アカウントは通常、教材・コース・
グループを所有しないため、猶予期間が過ぎると削除が進みます。

**「削除予約…」が無効（押せない状態）になっている場合**: 対象がまだ停止されていません。
先に「停止…」を実行してください。
