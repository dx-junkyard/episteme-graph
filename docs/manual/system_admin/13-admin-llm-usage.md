# LLM使用量（管理画面）

[← マニュアル索引](../README.md)

「LLM使用量」タブでは、システム全体の LLM トークン消費量を確認します（基本操作の要約は
[LLM使用量メトリクスを確認する](../../admin_operations/llm_usage.md#view-metrics) も
参照してください）。**このタブはシステム管理者（SYSTEM_ADMIN）ロールでログインしたときの
み表示されます。** ヘッダー・タブナビゲーション・確認モーダルなど、管理画面に共通の操作は
[管理画面の共通操作](../teacher/10-admin-common.md) を参照してください。

## 画面の概要 {#overview}

表には、選んだ集計軸（内訳）ごとに、実測（reported）と推計（estimated）のトークン数・
呼び出し回数が分けて表示されます。混ぜた単一の数値は表示されません。

---

## メトリクスを確認する {#metrics}

### 集計軸を選ぶ {#groupby}

内訳の粒度を選びます。「feature × model」（既定）・「feature」・「model」・
「provider」・「operation」・「day」・「ユーザー別」・「ユーザー別 × feature」から
選べます。選ぶと自動的に表が再取得されます。

「ユーザー別」を選ぶと、内訳の列に生のユーザーID（UUID）の代わりにユーザー名が
表示されます。ユーザー名が引けない場合は「不明ユーザー」、そもそもユーザーに
紐づいていない記録（バッチ処理・自動解析など）は「未帰属」と表示されます。
表の上に「バッチ処理・自動解析による消費は『未帰属』に計上されます。」という
注記が出ます。この個票（誰が・どれだけ使ったか）を見られるのは
システム管理者（SYSTEM_ADMIN）のみです。教員・学生本人には自分の利用実績も
含めて一切表示されません。

### 更新 {#refresh}

現在選んでいる集計軸のまま、表を再取得します。

### 表示される数値の見方 {#reading-metrics}

- 実測（reported）と推計（estimated_tokenizer / estimated_heuristic）は常に分離して
  集計表示されます。合算した単一数値は作られません。
- 記録バッファから溢れて記録できなかったイベント数（dropped_events）は、0件のときも
  必ず表示されます（隠しません）。
- 「費用(概算)」列は、価格表（環境変数 `LLM_PRICE_TABLE_PATH`）が設定されている場合のみ
  金額が入ります。設定が無い場合、費用は表示されません（金額のハードコードはしません）。

教材ごとの解析コスト**事前見積り**（レンジのみ・金額なし）は、教員（TEACHER）以上が
教材管理タブから確認できます。本タブとは別の窓口です。

## 計器の定義と用途（指標カタログ） {#indicator-catalog}

本タブの数値をはじめ、システムには制度を観察するための**集約計器**が複数あります。
それらの**定義・目的・値の宛先・粒度・元データ・保持・使わない用途**は、
`backend/core/indicator_catalog.py` の**指標カタログ**に一元宣言されており、
`GET /api/indicators` で**認証済みの全ユーザー（学習者を含む）**が読めます。
公開されるのは**定義だけ**で、値は一切含まれません — 値の閲覧権限は
これまでどおり各計器の API のロールゲートのままです。

### 全計器に共通する非利用宣言 {#indicator-non-uses}

カタログのすべての計器は、次の4つに**使わない**ことを構造的に宣言しています
（この宣言を外した計器は登録できません）。

- 個人のランキング・順位付けには使いません
- 成績評価には使いません
- 個人向け推薦の入力には使いません
- 自動的な判定・切り替え（自動ゲート）には使いません

### カタログに載っている計器 {#indicator-list}

| 計器の名前 | 値を読めるのは | 粒度 |
|---|---|---|
| LLM使用量メトリクス | システム管理者 | システム全体の集約 |
| AI利用枠の見通し | 教員 | システム全体の集約（残数・金額は返さない） |
| 教材ごとの解析トークン見積り | 教員 | 教材単位（人に紐づかない） |
| 疑いと検証の制度KPI | システム管理者 | システム全体の集約 |
| 論文ディスカッションの観測状況 | システム管理者 | システム全体の集約 |
| 関心集約ダッシュボード | 教員 | k-匿名の集約 |
| 橋の候補（学習者の重ね合わせ） | 教員 | k-匿名の集約 |
| 問いの帰属インサイト | 教員 | k-匿名の集約 |
| 素朴な問いの集計 | 教員 | k-匿名の集約 |
| 地図の端への関心 | 教員 | k-匿名の集約 |
| 再構成の出題レビューキュー | 教員 | k-匿名の集約 |
| 主張ごとのつまづきサマリー | 教員 | k-匿名の集約 |
| 使い方の質問の未整備箇所 | 教員 | k-匿名の集約 |
| アカウント個票（認証・利用実績） | システム管理者 | 1アカウント単位の運用データ |
| わたしの記録 | 本人（学習者） | 本人の記録のみ |

「アカウント個票（認証・利用実績）」だけは集約でも匿名化でもなく、**1人単位の運用
データ**です。用途は不正利用・乗っ取り・休眠アカウントの検知に限られ、学習の記録
（問い・引っかかり・再構成・意図）は含まれません。学習記録とは別の領域として分離され、
学習の評価・比較には使いません。

### 副作用のレビュー {#indicator-side-effect-review}

指標は、放っておくと「観察のための計器」から「達成すべき目標」へ漂流します
（Goodhart の法則）。本システムはこの漂流の検出を**自動判定にはしません**。
各計器は `side_effect_review` に「オーナーの定期レビュー（自動判定なし）」を宣言しており、
指標が目標化していないか・意図しない副作用が出ていないかは、人がまとめて見直します。

### 指標の意味を変えるとき {#indicator-change}

数え方・粒度・値の宛先を変えるときは、**指標カタログ（`core/indicator_catalog.py`）と
その計器の設計書（`design_doc` フィールドが指すファイル）の両方**を同時に更新してください。
片方だけを変えると、同じ名前で別のものを数えることになり、過去の数値との比較が
静かに壊れます。集約を返すエンドポイントを新設した場合も、カタログに1件足します
（足さないとガードレールテストが失敗します）。
