# 仕様編（全ロール共通）

[← マニュアル目次](README.md)

このページは episteme-graph の全体像を、ロールによらず共通する観点（コンセプト・アーキテクチャ・データフロー・権限・開示範囲・用語）から解説します。
受講者（学生）・教員・システム管理者のいずれの立場で読んでも、まずこのページで全体の地図を掴んでから、各ロール向けのページに進んでください。

より詳しい設計・実装解説は [docs/](../README.md) にまとまっています。本ページはその要点を利用者視点で再構成したものです。

---

## 1. システム概要とコンセプト

episteme-graph は、大学院生の学習プロセスを支援する **知識グラフ管理システム** です。PDF 論文をアップロードするだけで、そこに含まれる概念・主張・数式・関係性を自動抽出してナレッジグラフ・理論操作グラフを構築し、それを土台に対話型（RAG チャット）・没入型（音声講義）の学習体験を提供します。

研究者・大学院生が直面する「散在する先行研究の統合」と「前提知識の体系的習得」という課題を解決するため、システムは次の層で設計されています。

| 層 | やること |
|---|---|
| ① 知識の構造化（A層） | PDF をアップロードするだけで、概念・主張・数式・導出を PDF 解析エージェントパイプラインが構造化し、概念グラフ・理論操作グラフを自動生成する |
| ② 適応的学習（B層） | 習得状態・関心痕跡・違和感（tension）を追跡し、前提知識に応じた問いかけで理解を深める |
| ③ 没入型講義 | TTS 音声＋カラオケ式ハイライトで、論文をセミナー形式の講義に変換する |
| ④ 承認・共有（C層） | 教員が説明バージョン単位で査読承認し、教員間で解釈を共有する |

これらの層は独立したモジュールとして実装されており、A層（知識の構造化パイプライン）を書き換えることなく、B層・C層以降が積み上げられています。

アクセス先:

| UI | URL |
|---|---|
| 学習UI（受講者向け） | `http://localhost:3000` |
| 管理UI（教員・システム管理者向け） | `http://localhost:3000/admin.html` |

## 2. 全体アーキテクチャ

### 2.1 アーキテクチャ図

```
┌────────────────────────────────────────────────────────────┐
│ ブラウザ                                                    │
│   index.html + app.js   … 学習UI（学生, ES6+ SPA）          │
│   admin.html + admin.js … 管理UI（教員/管理者, ES5互換 SPA） │
└───────────────┬────────────────────────────────────────────┘
                │ HTTP (REST/JSON, JWT)
        ┌───────▼────────┐  ← 外部公開はこの 3000 番ポートのみ
        │ frontend       │  nginx：静的配信 + /api リバースプロキシ
        │ (nginx :3000)  │
        └───────┬────────┘
                │ (Docker内部ネットワーク episteme)
        ┌───────▼─────────────────────────────────────────────┐
        │ api-server (FastAPI :8001)                           │
        │   backend/api/   … 認証・学習・管理エンドポイント     │
        │   backend/core/  … 抽出・埋め込み・RAG・講義・スキーマ │
        │   src/episteme_graph/agents/ … PDF解析Agent群        │
        └──┬──────────┬──────────┬──────────────────────────────┘
           │          │          │
   ┌───────▼──┐ ┌─────▼────┐ ┌───▼─────────┐
   │PostgreSQL│ │ MinIO    │ │ LLM / TTS   │
   │+ pgvector│ │(S3互換   │ │ OpenAI /    │
   │ (正本)   │ │ 原本)    │ │ Gemini      │
   └──────────┘ └──────────┘ └─────────────┘
                              ┌─────────────┐
                              │ GROBID      │
                              │ (PDF解析)   │
                              └─────────────┘
```

外部に公開されるポートは `frontend`（nginx, 3000番）のみで、API サーバーや各データストアへは Docker 内部ネットワーク経由でのみ到達できます。

### 2.2 技術スタック

| レイヤー | 技術 |
|---|---|
| フロントエンド | Vanilla JS SPA + nginx（フレームワーク不使用） |
| API サーバー | FastAPI（Python 3.11） |
| RDB + ベクトル検索 | PostgreSQL 16 + pgvector（cosine 類似度、次元数は `LLM_EMBEDDING_DIM`、既定 3072） |
| オブジェクトストレージ | MinIO（S3 互換。PDF 原本・図画像を保存） |
| PDF 構造解析 | GROBID（TEI-XML）／利用不可時は PyMuPDF にフォールバック |
| LLM | OpenAI API または Google Gemini / Vertex AI（`LLM_PROVIDER` で切替） |
| TTS 音声合成 | OpenAI TTS（tts-1）または Google Cloud Text-to-Speech |
| 音声文字起こし | OpenAI Whisper 系（`LLM_TRANSCRIBE_MODEL`、ハンズフリー音声会話用） |
| 認証 | JWT（HS256）+ bcrypt |

知識の正本は PostgreSQL に一本化されており、MinIO は PDF 原本・図画像などバイナリの保存専用です。

## 3. データフロー

### 3.1 PDF → ナレッジグラフ（教材投入、主に教員が実行）

```
PDF アップロード
  → MinIO 保存 → GROBID / PyMuPDF でテキスト化
  → PDF解析 Agent パイプライン（26 ステージ）で
     構造・主張（claim）・数式・導出・理論操作グラフを段階的に生成
  → チャンク＋埋め込みを PostgreSQL(pgvector) へ
  → 理論コンポーネント・理論操作グラフを PostgreSQL へ / 図画像を MinIO へ
  → コースビルダーでコース化 → 公開
```

パイプラインは「文書構造の復元（structure-first）」から始まり、以降は「主張の採否・区分」「数式の意味・導出チェーン」「中心命題の再構成」「DSL 接続」「再利用可能コンポーネントの生成」「理論操作グラフの構築」という順で、粗い物理的な塊（ブロック）から意味を持つ最小命題（atomic claim）、さらに再利用可能な理論部品（theory component）へと積み上げます。各出力には根拠（`reason`）と確信度（`confidence`）が付与され、不明な点は削除せず `unknown` / `deferred` / `review_required` として保持されます。

詳細は [PDF 解析パイプライン概要](../pipeline/overview.md) を参照してください。

### 3.2 学習の流れ（受講、主に受講者が実行）

```
公開コースを受講登録（`learning_states` に1行 INSERT。コース本体は複製しない）
  → トピック選択 → RAG チャットで質問
     （pgvector 検索（tier 付き）+ 履歴 → LLM 回答）
  → 誤解検出・前提知識チェック・学習進捗トラッキング
  → レクチャーモードで TTS 音声 + ハイライト講義
```

コース本体（マスター）は不変で、受講者ごとの学習状態（進捗・誤解・関心痕跡など）は別テーブルに分離して保存されます。受講登録は公開テンプレートのコースを複製するのではなく、個人の学習状態を1行追加するだけの軽量な操作です。

詳細は [学習機能（学生UI）](../features/learning.md) を参照してください。

## 4. ロールと権限

システムは 3 段階のロールベースアクセス制御（RBAC）を採用しています。権限は上位ロールほど広く、**受講者（STUDENT）⊂ 教員（TEACHER）⊂ システム管理者（SYSTEM_ADMIN）** という累積構造になっています（上位ロールは下位ロールの権限をすべて含みます）。

| ロール | できること |
|---|---|
| 受講者（STUDENT） | 学習UIの利用、RAGチャット、コース受講登録 |
| 教員（TEACHER） | 受講者の権限に加えて、教材アップロード、コース作成・公開、グループ管理、理論コンポーネントの承認・共有（C層）、学生アカウント作成 |
| システム管理者（SYSTEM_ADMIN） | 教員の権限に加えて、教師アカウント作成を含む全権限 |

権限チェックは `_require_teacher()`（TEACHER 未満は 403）・`_require_system_admin()`（SYSTEM_ADMIN 以外は 403）という依存関数で実装されています。受講者アカウントは教員以上が管理UIから作成します。教員アカウントの作成はシステム管理者のみが行えます。初期のシステム管理者は起動時に環境変数 `ADMIN_PASSWORD` で作成されます。受講者が自分でアカウントを新規登録することはできません。

詳細は [認証・権限・開示範囲](../features/auth-visibility.md) を参照してください。

## 5. 開示範囲（Visibility）

教材（Document）やコース（LearningCourse）は、次のいずれかの開示範囲を持ちます。

| 開示範囲 | 意味 | アクセス可否 |
|---|---|---|
| Public（`public`） | システム全体（全ユーザー）に公開 | 全ユーザーが閲覧可能（コースの場合は `is_published=true` かつ `is_template=true` のときのみ） |
| Group（`group`） | 指定されたグループの参加メンバーのみアクセス可能 | 対象グループに所属し、かつ権限テーブル（`object_group_permissions`。viewer/editor）を持つメンバー |
| Private（`private`） | 作成者（自分）のみアクセス可能 | オーナーのみ |

グループへの参加は、管理者による直接招待、または招待コードのいずれかの経路で行われます。更新はオーナーまたは editor 権限を持つグループ員、削除はオーナーのみが行えます。

詳細は [認証・権限・開示範囲](../features/auth-visibility.md) を参照してください。

## 6. 用語集

| 用語 | 説明 |
|---|---|
| ナレッジグラフ | PDF から抽出した概念・主張・数式・関係性をグラフ構造で表現したものです。抽象構造は SMILES 風の独自 DSL（`(varID:OntologyType:value) ==[CorePredicate:verb:polarity]=> (...)`）で表されます。 |
| 理論操作グラフ（TheoryOperationGraph） | ComponentGraphAgent が導出チェーン（DerivationChain）から決定論的に構築する、論文の「理論操作の構造」を表すグラフです。理論構成を表す少数の集約ノードからなる `main` 層、式単位の step を保持する `equation_detail` 層、fallback/inferred ノードのみの `debug` 層に分かれます。全ノード・エッジにソースバッキングの状態を明示します。 |
| ソースバッキング | ナレッジグラフ・理論操作グラフの各ノード・エッジが、どのソース（式・主張・エビデンス・導出）に裏付けられているかを示す状態です。`source_backed` / `partially_source_backed` / `inferred` / `review_required` の 4 段階で明示され、確定はしません（`review_required` には理由が必ず付きます）。 |
| claim（主張） | 「1 主張 = 1 最小命題」に正規化された、意味抽出の中核単位です。ClaimQualificationAgent が採否・区分・粒度を判定して atomic rewrite（1 命題への再構成）を行い、ClaimObjectBuilder が最終的な `claims.json`（`ClaimObjectRecord`）に組み立てます。 |
| チャンク | ブロック（文書構造の最小単位）をセクション境界内で束ねた、埋め込み・RAG 検索の単位です（上限は目安として約 1800 字）。pgvector に埋め込みベクトルとして保存され、RAG チャットの検索対象になります。 |
| DSL | 化学の SMILES 記法に着想を得た独自の記法です。`(varID:OntologyType:value) ==[CorePredicate:verb:polarity]=> (...)` の形式で、概念間の抽象構造を 1 行で表現します。 |
| カートリッジ | ドメイン固有の語彙・検証ルール・成熟度定義などを JSON で外部化したものです（例: `backend/cartridges/particle_physics/`）。Agent のコードにドメイン知識をハードコードせず、ここから読み込むことでコアロジックを domain-independent に保ちます。カートリッジが無くても各 Agent は単独動作できます。 |
| RAG チャット | pgvector によるベクトル検索で関連チャンクを取得し、それを根拠として LLM が回答する対話型学習機能です。送信ボタンは「質問」1 つに統合されています。 |
| content_grounding（出所） | RAG チャットの回答が何に基づくかを示す軸です。`course_material`（このコースの教材に基づく）／`other_material`（コース教材外の資料に基づく）／`model_generated`（出典なし、モデルの一般知識）の 3 値で判定され、回答バブルと出典タブに表示されます。教員承認状況を示す `tier` とは別軸です。 |
| tier | RAG チャットで採用されたチャンクに付与される、教員承認状況から導出される L1 信頼性の指標です。回答の出所を示す `content_grounding` とは別軸として扱われます。 |
| tension（違和感） | 対話ログから TensionMiningAgent（B層）が検出する、「理解した上での引っかかり」の候補です。断定はされず、本人が確認画面で「そう、これ」（確定）または「違う」（却下）を選ぶまでは候補のままとなり、教員へは k-匿名化された集計のみが示されます。 |
| 問いの軌跡 | 学習者が確定させた関心痕跡（tension の確定・帰属付きの問いなど）の記録です。学習進捗タブに表示され、個人の知識ネットワーク（わたしの地図）の材料になります。 |
| 説明バージョン | 1 つの理論コンポーネントに対して複数並存できる説明の版です。A層が生成した `summary` から遅延生成される標準の説明（`kind='standard'`）と、教員が書く独自解釈（`kind='personal'`）が並存します。 |
| 承認（endorsement） | 教員が説明バージョン単位（コンポーネント単位ではない）で行う査読承認です。承認は 1 行ずつ記録され、承認の重みは人数・レベル・専門性の広がりから段階ラベル（例:「専門家3名が承認」）として表示されます。数値スコアは学習者には表示されません。 |
| 理論コンポーネント | ComponentAssemblyAgent が、採択済みの claim・数式・中心命題（thesis）を束ねて組み上げる、再利用可能な理論部品の単位です。コースや説明生成で再利用されます。 |
| リビジョンラン | PDF 解析結果を反復改善する仕組みです。解析実行（`document_analysis_runs`）に `initial`/`revision` の種別と `preparing → auditing → proposed → accepted/rejected/superseded` の状態遷移を持たせ、複数のリビジョン候補を並存させながら、アクティブなランは常に 1 つに保ちます。 |
| 分野の地図（Field Atlas） | 学習中の箇所が分野全体のどこに位置するかを示す、全画面オーバーレイと常設ミニマップの機能です。踏破率を数値化しない、宣言しない、煽らないことを設計原則としています。 |
| わたしの地図 | 学習者本人が確定させた痕跡（tension の確定・帰属付きの問い・再構成の成功など）から、毎回決定論的に導出される個人の知識ネットワークです。保存物ではなく都度導出され、本人にしか見えません。 |
| 再構成ループ | 学習者に理論の再構成（予測・言い直し）をさせ、A層が生成した `theory_claims` を答えキー（ground truth）として非 LLM の構造照合でズレを検出し、事実として提示する閉ループの学習機構です。数値スコア・正答率は学習者には表示されません。 |
| スキーマ進化 | 固定の `OntologyType`（概念カテゴリ）・`CorePredicate`（関係種別）を超えて、運用中に得られた学生の未回答質問からグラフ DSL の語彙を成長させる仕組みです。未回答クエリの蓄積 → スキーマ提案の生成 → Shadow Testing による事前検証 → 教員の承認 → 既存教材の再抽出、という流れで進みます。 |

## 7. 全機能に共通する設計原則

複数の機能・レイヤーにまたがって適用されている、システム全体の設計原則です。

- **マスターコースと個人進捗の分離** — コース本体（`learning_courses`、不変のマスター）と、受講者ごとの学習状態（`learning_states`、可変）は別テーブルに分離されています。公開テンプレートをクローンするのではなく、マスターを単一の真実として扱い、受講者の進捗だけを個別に保持します。
- **数値スコアを学習者に見せない** — 承認の厚み（endorsement）、tension・再構成ループの確信度や正誤判定、負荷度など、内部で計算される数値は学習者・教員向けの表示では段階ラベルや事実文に変換され、生の数値スコアとしては提示されません。
- **k-匿名（k=3、n<3 は非表示、件数はレンジ表示）** — tension の集計や関心・違和感の匿名化ダッシュボードなど、学習者個人の痕跡を教員向けに集計する箇所では、最小集計単位（k）を 3 とし、該当件数が 3 未満のセルは非表示にします。件数を出す場合も具体的な数値ではなくレンジ（3-5 / 6-10 / 11+ など）で表示し、個人が特定されない形に留めます。
- **学習痕跡は本人のみ可視・成績評価に使わない** — tension、問いの軌跡、わたしの地図などの学習者個人の痕跡は本人にのみ表示され、教員・管理者は個別の記録にアクセスできません（アクセスできるのは k-匿名化された集計のみ）。これらの記録は成績評価には使用されません。
