# 教員編（運用マニュアル）

[← マニュアル索引](../README.md)

このページは教員（TEACHER）ロールでの日常運用を管理画面のタブ単位で解説します。
システムの全体像・用語・データモデルを先に把握したい場合は、先に
[仕様編](../student/01-specification.md) を読むことをおすすめします。各操作の詳しい手順は
`docs/admin_operations/` の該当ページへリンクしていますので、本ページは
「何ができ、どんな注意が必要か」の要点に絞っています。

管理画面は `http://localhost:3000/admin.html` からアクセスします（学習用画面 `/` とは別）。

---

## 0. ロールと画面アクセスの前提 {#roles-and-access}

権限の詳細は [認証・権限・開示範囲](../../features/auth-visibility.md) を参照してください。要点のみ:

| ロール | できること |
|---|---|
| 受講者（STUDENT） | 学習画面の利用、チャット、コース受講登録 |
| 教員（TEACHER） | 上記に加え、教材アップロード、コース作成・公開、受講者アカウント作成 |
| システム管理者（SYSTEM_ADMIN） | 全権限（教員アカウント作成を含む） |

階層は **システム管理者 > 教員 > 受講者** です。

注意点として、システム管理者は権限としては教員の操作をすべて行えますが、管理画面の
UI 上ではコンテンツ系4タブ（教材管理・コース構築・コース管理・原稿スタジオ）が
非表示になり、これらの教材・コース運用は事実上「教員としてログインしたときの画面」に
なります（初期タブはエラー解析）。本ページの 1〜3 章はこの教員向けコンテンツタブを
対象にしています。

### タブ一覧 {#tab-list}

管理画面のタブは4つのグループ（プルダウン）に束ねられています。教員（TEACHER）で
ログインしたときに見えるのは次のタブです。

| グループ | タブ | 本ページの該当章 |
|---|---|---|
| コンテンツ | 教材管理 / コース構築 / コース管理 / 原稿スタジオ | [1](#materials) / [2](#course-management) / [3](#lecture-studio) |
| 学習インサイト | つまづきデータ / 関心集約 / 分野の地図 / 前提の地図 | [7](#learner-dashboard) / [5](#field-atlas) / [9](#doubt-atlas) |
| ナレッジ基盤 | スキーマ提案 / ナレッジライブラリ / DSL進化分析 | [6](#schema-proposals) / [10](#knowledge-library) |
| 運用 | グループ管理 / 学生管理 | [8](#user-group-management) |

システム管理者（SYSTEM_ADMIN）ではこれに加えて「教員管理」と、運用グループの
システム統計・LLM使用量・エラー解析・マニュアル編集・discuss 観測・AIモデルが
表示されます（[11. システム管理者専用機能](#system-admin-only)）。**その代わり、
コンテンツグループの4タブ（教材管理 / コース構築 / コース管理 / 原稿スタジオ）は
システム管理者では表示されません** — 教材・コースの運用は教員（TEACHER）ロールで
ログインして行う画面構成です（[管理画面の共通操作](10-admin-common.md#overview)）。タブごとの UI 要素の
リファレンスは [管理画面の共通操作](10-admin-common.md) 以降の各ページにあります。

以降の各表の「確認ダイアログ」欄は、管理UI（`admin.js` / `admin-lecture-studio.js`）の
実装を確認し、実際に確認モーダルが挟まる操作にのみ「あり」と記載しています
（記載なしは、読み取りのみ、または実装上ダイアログを挟まない操作です）。

## 1. 教材管理 {#materials}

「教材管理」タブでは、PDF / TeX 教材のアップロードと、解析パイプラインが生成した
成果物の開示・共有・削除を扱います。

| 操作 | 必要ロール | 取り消し可否 | 確認ダイアログ |
|---|---|---|---|
| [教材をアップロードする](../../admin_operations/materials.md#upload) | 教員（TEACHER）以上 | 新規作成のため対象外 | なし（ファイルを選択・ドロップすると即座にアップロードが始まります） |
| [URL から取得する](11-admin-materials.md#url-upload) | 教員（TEACHER）以上 | 新規作成のため対象外 | なし（モーダルで URL を入力して実行します） |
| [arXiv から探して取り込む](../../admin_operations/materials.md#arxiv-discovery) | 教員（TEACHER）以上 | 新規作成のため対象外 | なし（候補を選んで実行した論文だけが取り込まれます） |
| [開示範囲を変更する](../../admin_operations/materials.md#visibility) | 教員（自分の教材のみ） | 可（後から戻せます） | 公開（public）に変更するときのみあり。非公開・グループ限定への変更には確認ダイアログはありません |
| [削除する](../../admin_operations/materials.md#delete) | 教員（自分の教材のみ） | **不可（取り消せません）** | **あり** |
| [解析コストを見積る](../../admin_operations/materials.md#estimate-cost) | 教員（自分の教材のみ） | 該当なし（読み取りのみ） | 不要 |
| [共有版を発行・削除予約する](../../admin_operations/materials.md#manage-shared-version) | 教員（自分の教材のみ） | 発行＝不変版として残る／削除予約は猶予期間中のみ取消可 | 発行にはなし。削除予約にはあり（取消操作には確認ダイアログはありません） |
| [図・画像の分類を確認する](../../admin_operations/materials.md#review-figures) | 教員 | 確定後は AI 再解析で上書きされない | 記載なし |
| [位置づけ（分野マップ）を確認する](11-admin-materials.md#landscape-open) | 教員（閲覧可能な教材。変更は編集権限が必要） | 確認・却下・再検討はいつでも状態を変えられます（行は削除されません） | 記載なし |
| [近い論文を探す（論文レーダー）](../../admin_operations/materials.md#paper-radar) | 教員（閲覧可能な教材） | 該当なし（検索・比較は保存されません） | 記載なし |
| [グラフレビューで承認する](26-admin-graph-review.md#graph-review-open) | 教員（閲覧は閲覧権限、承認・却下は編集権限） | 却下も状態遷移として記録されます（行は削除されません） | 記載なし |
| [ゼミ前ブリーフを確認する](11-admin-materials.md#seminar-brief-open) | 教員（閲覧可能な教材） | 該当なし（読み取りのみ） | 不要 |
| [検出要素を一覧する](11-admin-materials.md#row-inventory) | 教員（閲覧可能な教材） | 該当なし（読み取りのみ） | 不要 |

補足:

- アップロード後は解析パイプラインが非同期で走ります（状態は「処理中 → 完了」）。
- 開示範囲は **public（全体公開）/ group（グループ限定）/ private（自分のみ）** の3種類です。
- 解析コスト見積りは **金額を表示しません**。価格表が設定されていても、表示されるのは
  LLM トークン量の目安（レンジ）のみです。
- 共有版（リリース）は「開示範囲・グループ共有」とは別機能です。発行すると、その時点の
  解析成果が不変の版として固定され、共有先に更新通知が届きます。削除予約は既定14日の
  猶予期間があり、期限を過ぎると物理削除されます。
- 図・画像の分類（機能構成図 / データグラフ / 解説画像 / 混在 / 不明）は AI 候補の段階では
  確定していません。教員が確認・確定するまで「次にやること」パネルに事実として表示され続けます。

## 2. コース構築・管理 {#course-management}

コースは「コース構築」タブで AI と設計し、「コース管理」タブで公開・開示範囲・共有・削除を
管理します。

| 操作 | 必要ロール | 取り消し可否 | 確認ダイアログ |
|---|---|---|---|
| [AI とコースを設計する](../../admin_operations/course.md#builder) | 教員（TEACHER）以上 | セッションとして保存され、後から再開できます | 記載なし |
| [リリース前の確認（確認して公開）](13-admin-course-management.md#release-review-modal) | 教員（自分のコースのみ） | 各ステップに「あとで」があり、飛ばしても受講者への表示は変わりません | 最後の「公開する」のみあり |
| [議論テーマを設定する](13-admin-course-management.md#course-focus-modal) | 教員（自分のコースのみ） | 何度でも書き換え・空欄化できます | 空欄で保存するときのみあり |
| [受講チャットの AI モデルを設定する](13-admin-course-management.md#course-model-modal) | 教員（自分のコースのみ） | 何度でも変更・解除できます | **あり**（保存・解除とも） |
| [開示範囲を変更する](../../admin_operations/course.md#visibility) | 教員（自分のコースのみ） | 可（後から戻せます） | 公開（public）に変更するときのみあり。非公開・グループ限定への変更には確認ダイアログはありません |
| [受講者に公開する](../../admin_operations/course.md#publish) | 教員（自分のコースのみ） | 開示範囲変更と同一操作。非公開へ戻すと、既に受講登録した学習者は次回アクセス時点でコース内容を閲覧できなくなります（進捗などの学習状態は保持され、再公開すると閲覧できる状態に戻ります） | **あり（受講対象化に直結するため）** |
| [削除する](../../admin_operations/course.md#delete) | 教員（自分のコースのみ） | **不可（取り消せません）** | **あり** |
| [学習マップ（分野の地図）を割り当てる](../../admin_operations/course.md#atlas-binding) | 教員（自分のコースのみ） | 再編集して保存し直せます | 通常の割り当て保存にはなし。対応するトピックが0件のまま保存しようとした場合と、現行の割り当てが候補にない状態で未選択のまま保存（解除）しようとした場合のみ確認ダイアログが挟まります |
| [共有ダッシュボードを確認する](../../admin_operations/course.md#sharing-dashboard) | 教員（閲覧可能なコース） | 該当なし（読み取りのみ） | 不要 |
| [共有版を発行・削除予約する](../../admin_operations/course.md#manage-shared-version) | 教員（自分のコースのみ） | 発行＝不変版として残る／削除予約は猶予期間中のみ取消可 | 発行にはなし。削除予約にはあり（取消操作には確認ダイアログはありません） |

補足:

- AI コースビルダーの対話履歴はセッションとして永続化され、リロード後も設計を続けられます。
- 「公開する」は内部的には開示範囲を public にする操作と同じで、専用の別 API はありません。
  public にしたコースは公開テンプレートとして受講者の受講対象になります。
- コースの削除は「コース構築」タブの
  [既存コースを読込](12-admin-course-builder.md#import-course-btn) で開く一覧の各行から
  行います（「コース管理」タブの行操作には削除ボタンはありません）。
- 学習マップの割り当ては、対応する分野の骨格が凍結済みでないと学習者側に表示されません。
  骨格の凍結については [5. 分野の地図](#field-atlas) を参照してください。
- 共有ダッシュボードは個人ごとの追跡ではなく、コンポーネントの説明バージョンごとの
  承認・引用の**集計**です。所有者に限らず、閲覧可能なコースであれば確認できます。

## 3. 原稿スタジオ {#lecture-studio}

「原稿スタジオ」タブでは、チャンク・トピックのレクチャー原稿を編集し、AI に書き換えを
依頼できます。再構成ループ（R層）のレビューや、要素検討ワークスペース（W層）の
同一性リンク・標準化度の確定もここから行います。

| 操作 | 必要ロール | 取り消し可否 | 確認ダイアログ |
|---|---|---|---|
| [AI で原稿を書き換える](../../admin_operations/lecture_studio.md#rewrite-chunk) | 教員（自分のコースのみ） | Copilot 経由なら「戻す」で復元可／原稿スタジオから直接実行した場合は取り消せません | なし（指示文を入力して実行すると、確認なしにその場で書き換えが保存されます） |
| [コース原稿の音声を生成する](../../admin_operations/lecture_studio.md#audio) | 教員（自分のコースのみ） | 既存音声があるチャンクは再生成をスキップ（実質的に再実行安全） | 記載なし |
| [再構成レビューキューを確認する](../../admin_operations/lecture_studio.md#review-queue) | 教員（自分のコースのみ） | 状態遷移で保持（削除 API なし） | 記載なし |
| [同一性リンクを確定する・標準化度を評価する](../../admin_operations/lecture_studio.md#identity-links-standardization) | 教員（自分のコースのみ） | 既存表記は書き換えず追加のみ。確定（confirmed）・却下（rejected）は候補（candidate）状態からのみ遷移でき、一度確定・却下すると取り消せません | 記載なし |
| [教材図スタジオで説明図を作る](14-admin-lecture-studio.md#figure-studio) | 教員（自分のコースのみ。図の一覧・画像の閲覧は editor 共有の教員も可） | 図は削除されず「回収する」「採用に戻す」で状態を切り替えます | 保存せずに閉じようとしたときのみあり |
| [図の提案を確認する](14-admin-lecture-studio.md#figure-suggestions) | 教員（自分のコースのみ。一覧の閲覧は editor 共有の教員も可） | 却下は候補を消さず記録として残します | 未判断の候補があるまま「提案を生成」を押したときのみあり |

補足:

- **重要:** AI による原稿書き換えは実行するとその場で保存されます。原稿が変わるため、
  そのチャンクの既存音声キャッシュは無効化され、音声の再生成が必要になります
  （Copilot 経由で「戻す」を使って復元した場合も同様に音声キャッシュは無効化されます）。
- 再構成ループは claim を自動で出題形式（ELICIT）に変換して受講者に配信する仕組みです。
  教員は事後の監査役として、疑わしさランク順のレビューキューから
  `confirmed`（追認）/ `flagged`（要修正）/ `retired`（回収）へ状態遷移させます。
- 標準化度の評価は、対象が共通部品（shared_part）の場合のみ表示され、AI の候補
  （LLM の事前知識・ライブラリ内の類似・コーパス内の反復による三角測量）を教員が
  対話ペインの候補カードから確定します。自動では確定しません。

## 4. 承認・共有（C層） {#endorsement-sharing}

受講者の質問から生まれた AI 回答を、教員の査読を経て承認し、承認済みの理論・概念を
「コンポーネント」として教員間で共有・再利用できるようにする層です。管理画面上は
原稿スタジオのコンポーネントカードから操作します。詳細な設計は
[承認・共有レイヤー（C層）](../../features/endorsement-sharing.md) を参照してください。

### 承認は「説明バージョン」単位 {#endorsement-per-explanation}

1コンポーネントには複数の説明バージョンが並存できます（AI 由来の「標準の説明」/
教員ごとの「独自の説明」）。承認はコンポーネントそのものではなく、**どの説明バージョンを
承認したか**を区別するために説明バージョン単位で記録されます。

| 操作 | 必要ロール | 取り消し可否 | 確認ダイアログ |
|---|---|---|---|
| 質問+回答から候補を生成する（`POST .../candidates/from-query`） | 教員 | 候補は `confirmed=false` のまま保持 | 記載なし |
| 説明バージョンを追加・編集する | 教員（編集は作者またはシステム管理者） | 上書き保存で、以前の内容を版として遡って確認することはできません（履歴は保持されません） | 記載なし |
| 説明バージョンを承認する / 承認を取り消す | 教員 | 取り消しは行削除ではなく `revoked=TRUE` への状態遷移（履歴は保持） | 記載なし |
| 他コースで引用する | 教員 | 帰属付きで記録（削除 API なし） | 記載なし |

補足:

- 承認の重みは学習者への評価点にはしません。表示は「未承認」「暫定的に1名が承認」
  「強い支持: 3名の教員が承認（専門2分野）」のような**段階ラベル**のみで、数値スコアは
  受講者に出しません。
- claim（主張）への紐づけの最終確定は必ず教員が行います。AI は候補提示に限定され、
  教員が確定するまで確定済み扱いにはなりません。
- 承認・引用・共有切替・査読状態遷移はすべて監査記録されます。

## 5. 分野の地図 {#field-atlas}

「分野の地図」タブでは、分野の骨格（スケルトン）を生成・レビュー・凍結します。骨格は
受講者に「いま学んでいる箇所が分野のどこに当たるか」を示すために使われます。

| 操作 | 必要ロール | 取り消し可否 | 確認ダイアログ |
|---|---|---|---|
| [骨格を生成する](../../admin_operations/atlas.md#generate) | 教員（TEACHER）以上 | 凍結前であれば作り直せます | 記載なし |
| [骨格を凍結する](../../admin_operations/atlas.md#freeze) | 教員（TEACHER）以上 | **不可（取り消せません）** | **あり** |
| [修正報告をレビューする](17-admin-atlas.md#reports-section) | 教員（TEACHER）以上 | 採用・見送りは状態遷移として記録されます | 記載なし |
| [論文の解析から見つかった候補をレビューする](17-admin-atlas.md#gap-candidates) | 教員（TEACHER）以上 | 見送りも行削除ではなく状態遷移。「見送りから戻す」で候補に戻せます | 見送り（却下）は理由の入力が必須で、未入力のままでは実行されません |
| [関係（辺）の候補をレビューする](17-admin-atlas.md#edge-candidates) | 教員（TEACHER）以上 | 同上 | 同上 |
| [この分野を廃止する・復帰する](17-admin-atlas.md#domain-retire) | 教員（TEACHER）以上 | 「復帰する」で戻せます（受講者側の地図の表示は廃止後も変わりません） | **あり** |

補足:

- 骨格 draft はレビューを終えるまで何度でも作り直せます。凍結すると版として確定し、
  以降は受講者向けの地図に使われます。
- カートリッジファイルのない新しい分野でも、分野名・説明を入力して骨格を生成できます。
- 骨格に足すかどうかの判断は必ず教員が行います。AI やサーバが次版の下書きを直接書き換える
  経路はなく、候補の取り込みも教員の明示操作（「次版の下書きに取り込む…」→ 保存 → 凍結）で
  のみ行われます。
- 各タブの個々の操作は [分野の地図タブの操作](17-admin-atlas.md) を参照してください。

## 6. スキーマ提案 {#schema-proposals}

「スキーマ提案」タブでは、未回答クエリの分析から AI が提案したスキーマ拡張
（新しい概念タイプ・述語）を、シミュレーション（Shadow Testing）で検証してから
承認・却下します。提案は承認されるまでシステムに反映されません。

| 操作 | 必要ロール | 取り消し可否 | 確認ダイアログ |
|---|---|---|---|
| [提案を確認・承認する](../../admin_operations/schema_proposals.md#review)（システム全体に適用） | 教員 | **不可（取り消せません）** | **あり** |
| 同上（カナリアリリース） | 教員 | 選択コースのみに再抽出の対象を限定しますが、スキーマへの追加自体は全体適用と同じく取り消せません（異なるのは再抽出ジョブの対象範囲だけです） | 記載なし |
| 同上（却下） | 教員 | 却下は一方向の状態遷移で、却下を取り消して再度承認可能な状態に戻すことはできません | 記載なし |

補足:

- 同じ提案データは「DSL進化分析」タブ（ナレッジ基盤グループ）からも扱えます。こちらは
  つまづきデータの AI メタ分析による**提案の生成**と、現在のスキーマ定義の確認が中心で、
  シミュレーションを挟まずに承認・却下します。詳細は
  [DSL進化分析（管理画面）](23-admin-schema.md#overview) を参照してください。
- 提案の「シミュレーション」実行で、既存教材への影響（マッチ件数・適用例）を事前確認できます。
- 「システム全体に適用」は全教材の再抽出ジョブを開始する影響の大きい操作のため、実行前に
  確認ダイアログが入ります。「カナリアリリース」は選択した特定コースのみに適用され、影響を
  限定して試せます。

## 7. 学習者ダッシュボード（つまづき・関心集約） {#learner-dashboard}

受講者の学習状況を、個人の追跡ではなく**集計**として確認するための画面です。

| 操作 | 必要ロール | 取り消し可否 | 確認ダイアログ |
|---|---|---|---|
| [つまづきデータを確認する](../../admin_operations/stumbles.md#view) | 教員 | 該当なし（読み取りのみ） | 不要 |
| [橋の候補集約（Phase B）を確認する](../../admin_operations/interest_dashboard.md#bridge-insights) | 教員（TEACHER）以上 | 該当なし（読み取りのみ） | 不要 |

補足:

- つまづきデータは、RAG 検索で教材から回答できなかった受講者の質問（未回答クエリ）の一覧です。
  教材の補強やコース改善に使うためのデータです。
- これらの集計は **k-匿名化（k=3）** で保護されます。該当者が3人未満（n<3）のセルは
  表示されず、件数も生の数値ではなくレンジ（3-5 / 6-10 / 11+）で表示されます。個々の受講者の
  履歴を追跡する画面はありません。
- **これらのデータを成績評価に使用することは禁止されています。**

## 8. ユーザー・グループ管理 {#user-group-management}

受講者・教員アカウントの作成は「学生管理」「教員管理」タブで、グループの管理は
「グループ管理」タブで行います。アカウント作成の権限はロールによって異なります。

| 操作 | 必要ロール | 取り消し可否 | 確認ダイアログ |
|---|---|---|---|
| [受講者（学生）アカウントを作成する](../../admin_operations/students.md#create-student) | 教員（TEACHER）以上 | **不可（取り消せません）** | **なし**（送信すると即座に作成されます） |
| [教員アカウントを作成する](../../admin_operations/teachers.md#create-teacher) | **システム管理者（SYSTEM_ADMIN）のみ** | **不可（取り消せません）** | **なし**（送信すると即座に作成されます） |

補足:

- 教員アカウントの作成は教員自身の権限ではできません。システム管理者のみが実行できます。
- どちらの作成も確認ダイアログを挟まないため、入力内容（特にユーザー名・パスワード）を
  よく確認してから送信してください。
- グループの作成・招待コードの発行・メンバー管理については
  [グループを作成・招待する](../../admin_operations/users.md#manage-groups) や
  [認証・権限・開示範囲](../../features/auth-visibility.md) も参照してください。

## 9. 前提の地図（D層）— 補足 {#doubt-atlas}

「前提の地図」タブは、暗黙の前提や主張の検証状態を記帳し、疑義（challenge）を管理する
画面です。分野の地図（Field Atlas）とは別機能です。

| 操作 | 必要ロール | 取り消し可否 | 確認ダイアログ |
|---|---|---|---|
| [検証状態を記帳する](../../admin_operations/doubt.md#record-verification-status) | 教員（TEACHER）以上 | 記帳は何度でも上書きでき、以前の記帳内容を別の状態に書き換えられます（`directly_verified` への変更のみ検証スコープが1件以上必要という制約があります） | 記載なし |
| [疑義を取り下げる・検証提案にする](../../admin_operations/doubt.md#manage-challenge) | 教員（自分が投稿した疑義のみ） | 取り下げは状態遷移（`withdrawn`）で履歴保持。他教員の疑義は取り下げ不可 | 記載なし |

補足:

- 「直接検証（directly_verified）」への昇格には、検証スコープの記帳が 1 件以上必要です
  （スコープが空欄でもエラーにはなりません。条件の詳細は上記リンク先を参照してください）。
- 疑義の取り下げは行削除ではなく状態遷移として記録され、履歴は保持されます。

## 10. ナレッジライブラリ（L層）— 補足 {#knowledge-library}

「ナレッジライブラリ」タブでは、分野（domain）ごとの装置・パーツ・理論コンポーネントの
共同財（library entries）を参照・編集・凍結します。パイプラインが実際に参照するのは
**凍結版のみ**で、draft は参照されません。

| 操作 | 必要ロール | 取り消し可否 | 確認ダイアログ |
|---|---|---|---|
| [エントリを参照・凍結する](../../admin_operations/library.md#view-and-freeze)（draft 編集） | 教員（TEACHER）以上 | 楽観ロック（`expected_revision`）。競合時は 409 で再読み込みが必要 | 記載なし |
| 同上（凍結＝版発行） | 教員（TEACHER）以上 | 凍結版は履歴として蓄積（既存版は残る） | **あり**（「取り消せません。修正は次版で行います」という確認が入ります） |
| 同上（廃止／`retired`） | 教員（TEACHER）以上 | 行削除ではなく状態遷移。廃止後は参照検索に出ませんが、`restore` 操作で active 状態に戻せます（取り消し可能） | **あり** |

補足:

- 例示画像をライブラリエントリに含めるかどうかは、元教材（document）の所有者のみが
  明示的に選択でき、それ以外の教員が画像を含めようとすると拒否されます。エントリ本文の
  テキストは教員全体に開示されます。

## 11. システム管理者専用機能（参考） {#system-admin-only}

以下はシステム管理者（SYSTEM_ADMIN）専用の画面で、通常の教員アカウントからは
操作できません。

| 操作 | 必要ロール | 取り消し可否 | 確認ダイアログ |
|---|---|---|---|
| [LLM 使用量メトリクスを確認する](../../admin_operations/llm_usage.md#view-metrics) | システム管理者のみ | 該当なし（読み取りのみ） | 不要 |

補足:

- 実測（reported）と推計（estimated_tokenizer / estimated_heuristic）は分離して表示され、
  混ぜた単一の数値は表示されません。価格表が設定されていなければ費用は表示されません
  （金額のハードコードはしません）。
- 教材ごとの解析コスト**事前見積り**（レンジのみ・金額なし）は教員でも教材管理タブから
  確認できます。詳細は [1. 教材管理](#materials) を参照してください。
- ほかに、教員管理・システム統計・エラー解析・マニュアル編集・discuss 観測・AIモデルの
  各タブもシステム管理者専用です。教員の日常運用に関わるのは次の2点です。
  - **AIモデル**タブ: LLM モデルのシステム既定と、[URLから取得](11-admin-materials.md#url-upload)・
    [arXivから探す](11-admin-materials.md#arxiv-discovery) の**取得先ドメインの許可リスト**を
    設定します。許可リストは初期状態では空で、登録するまでこれらの取り込みは行えません。
  - **教員管理**タブ: 教員アカウントの作成（[8. ユーザー・グループ管理](#user-group-management)）。
