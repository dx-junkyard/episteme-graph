# 関心集約（管理画面）

[← 教員編に戻る](03-teacher.md#learner-dashboard)

「関心集約」タブ（ヘッダーの「学習インサイト」グループ）では、クラス全体の関心・
違和感の傾向を、個人を特定しない**集団集計**として確認します。点数化やランキングでは
なく、どこで問いが深まっているか・どこで引っかかりが多いかを見せる設計です。

## 画面の概要 {#overview}

コース選択プルダウン・関心集約ダッシュボード・橋の候補（学習者の重ね合わせ）の3つの
要素で構成される、読み取り専用の画面です。橋の候補セクションは、上のコース選択と連動
しますが独立したセクションとして表示されます。

## コースを選んで確認する {#course-and-refresh}

### コース選択 {#course-select}

関心集約を確認したいコースを選びます。

1. プルダウンから対象のコースを選びます。
2. 選択すると、ダッシュボード本体と「橋の候補」セクションの両方が、そのコースの内容に
   更新されます。

コースを選んでいない間、両セクションには「コースを選択してください」と表示されます。

### 更新 {#refresh-btn}

選択中のコースの集計を最新の状態に読み込み直します。

## 関心集約ダッシュボード {#dashboard-body}

コースを選ぶと表示される、以下の集計です。

- **対象クラス規模**: そのコースで関心の痕跡が記録されている学習者の人数（個人は
  特定しません）。
- **関心が集まっている領域**: トピックごとの関心の件数・未消化（まだ解決していない
  問い等）の割合・関与した学習者数を、件数の多い順に一覧表示します。
- **未消化の総量**: 未解決の問い・反復した寄り道・反復する誤答の、コース全体での件数です。
- **疑問が集中している構造（どこに・どう引っかかったか）**: 学習者が自分で確定した
  構造上の引っかかり（構造帰属型の問い）を、対象箇所（トピック・理論の段階など）と
  引っかかり方の種類ごとに集計します。**関与した学習者が3名未満の項目は表示されません**
  （k-匿名化）。表示される件数は学習者3名以上が確定した項目に限られます。

「対象クラス規模」「関心が集まっている領域」「未消化の総量」は、個人を特定しない集団の
件数として表示されます（誰の痕跡かは分かりません）。3名未満のときに表示ごと伏せる
k-匿名化がかかるのは、下記の「疑問が集中している構造」と「橋の候補」です。

このコースにまだ関心の痕跡が1件も記録されていない場合は「このコースにはまだ関心痕跡が
記録されていません。」と表示されます。「疑問が集中している構造」の項目自体は、3名以上が
同じ箇所に帰属した組み合わせが無い場合、一覧ごと表示されません（表示されないことがデータ
不足の証拠であり、エラーではありません）。

## 橋の候補（学習者の重ね合わせ） {#bridge-insights-section}

複数の学習者が、自分の引っかかり（tension）を同じ構造要素（コンポーネントや構造グラフの
関係）へ自分で結び付けた場合に、その要素を「橋の候補」として一覧表示します。個人は
特定できず、ドメイン知識としての自動採用も行われません（あくまで候補の提示です）。

一覧の各項目には、結び付けた学習者の人数が「3-5名」のようなレンジで添えられます
（正確な人数は表示されません）。

**データが表示されない場合**: 選択したコースで、まだ3名以上の学習者が同じ構造要素に
自分の引っかかりを結び付けていません（k-匿名化のため、3名未満では集約自体を表示しません）。
「まだ表示できる集約はありません（3名以上の確定痕跡が必要です）。」と表示されている間は、
学習者の利用が進んで該当者が3名以上になるまで待つ必要があります。

このセクションで得られる情報は、説明を重点的に補強すべき箇所を見つけるための材料であり、
個々の学習者の評価には使いません。

### この計器の定義 {#indicator-fact}

ダッシュボードの先頭には、「計器: 関心集約ダッシュボード — …個人の比較・成績・
自動判定には使いません。」という1行の事実文が表示されます。これは**指標カタログ**
（制度を観察するための計器の定義を一元宣言したもの）から取得したもので、
この画面が何のための計器かを常に読める場所に置くためのものです。

カタログには、この計器が**何を数えるか / 何のためか / 元データは何か / どう保持するか /
何には使わないか**の全文が載っており、`GET /api/indicators` から**学習者を含む全員**が
読めます。定義の一覧は
[LLM使用量（管理画面）の「計器の定義と用途」](../system_admin/13-admin-llm-usage.md#indicator-catalog)
と [仕様編の「あなたについて集計される計器」](../student/01-specification.md#institutional-indicators)
にもあります。

**事実文が表示されない場合**: カタログの取得に失敗しています（推測で文章を作らない
設計のため、読めないときは何も表示しません）。ダッシュボード本体の表示には影響しません。

## 教員が値を読める計器の一覧 {#teacher-indicator-list}

指標カタログのうち、**教員が値を読める**ものは次のとおりです（この画面の計器だけでは
ありません）。名前はカタログの宣言と一字一句同じで、定義の全文は `GET /api/indicators`
から読めます。それぞれの画面での見え方は、各画面のページを参照してください。

| 計器の名前 | 何を数えるか |
|---|---|
| 関心集約ダッシュボード | コースの中で、どのトピックに問い・引っかかりが集まっているか |
| 橋の候補（学習者の重ね合わせ） | 学習者が自分の引っかかりを理論の部品へ自分で結び付けた先 |
| 問いの帰属インサイト | 問いが理論構成のどの段階の、どういう型の引っかかりだったか |
| 素朴な問いの集計 | どの前提の手前で複数の学習者がつまずいているか |
| 地図の端への関心 | 分野の地図のどの縁に「この先を知りたい」が向いているか |
| 再構成の出題レビューキュー | 再構成の出題そのものが壊れていないかを見る誤り率など |
| 主張ごとのつまづきサマリー | 教材のどの主張で、つまずきや質問が多いか |
| 使い方の質問の未整備箇所 | 使い方の質問のうち、マニュアルに説明が無かった箇所 |
| 未回答の質問一覧（個票） | 教材が答えられなかった質問（**集約ではなく、学習者名と原文のまま**） |
| 認識的地位台帳のサマリ | コースの台帳のうち、検証スコープが記帳された行と空欄の行の数 |
| 未検証合意リスト | 依存が多いのに確かめられた範囲が書かれていない対象 |
| 前提の地図 | 依存の多さ×確かめられ具合の分布（段階に丸めた散布） |
| ゼミ前ブリーフ | 1論文の脆い前提・一点吊りの支持線・検証記録の見つからない箇所 |
| 説明の承認と引用のダッシュボード | 説明ごとの承認人数・引用件数（教員の行為を数えます） |
| 分野マップ上の論文の集まり | 分野の地図のノードごとに配置されている論文（題名の列挙） |
| AI利用枠の見通し | 大きな解析を始める前に、今日の枠に収まらない可能性があるか |
| AI利用枠の見通し（教材ごと） | 同じ判定を、1つの教材の再解析について行ったもの |
| 教材ごとの解析トークン見積り | 1つの教材の解析で消費するトークン量（レンジのみ） |
| 論文取り込みの事前見積り | これから取り込む論文の解析で消費するトークン量（レンジのみ） |

同じカタログには、**システム管理者だけが値を読める**計器（LLM使用量メトリクス /
疑いと検証の制度KPI / 論文ディスカッションの観測状況 / 教材パイプラインの進捗統計 /
アカウント個票（認証・利用実績））もあります。教員には値が出ませんが、**定義は同じように
読めます**（何が数えられているかを隠さないためです）。

上の一覧は「値を読める人」を書いたもので、**使ってよい用途**はすべての計器で同じです —
個人のランキング・成績評価・個人向け推薦・自動的な判定には使いません。

**表示されるはずの計器が画面に無い場合**: 値を読む画面がまだ用意されていない計器が
あります（「分野マップ上の論文の集まり」は現在この状態です）。カタログには定義だけが
先に載っているためで、不具合ではありません。
