# DSL進化分析（管理画面）

[← 教員編に戻る](03-teacher.md#schema-proposals)

「DSL進化分析」タブ（ヘッダーの「ナレッジ基盤」グループ）では、学習者のつまづきデータ
（未回答クエリ）を AI が分析し、スキーマ拡張（新しい概念タイプ・述語）の提案を生成します。
提案の一覧・承認・却下に加え、現在のスキーマ定義（概念カテゴリ・関係性タイプ）も
このタブから確認できます。

## 画面の概要 {#overview}

本タブは[スキーマ提案（管理画面）](22-admin-schema-proposals.md#overview) タブと
**同じ提案データを扱いますが、フローが異なる別の画面**です。

- **スキーマ提案タブ**: 保留中の提案について、まずシミュレーションで教材への影響を
  確認してから、システム全体 / カナリアリリースを選んで適用します。
- **本タブ（DSL進化分析）**: シミュレーションの手順を挟まず、提案一覧の「承認して適用」
  「却下」から**直接**スキーマへ反映します。加えて、つまづきデータからの提案生成
  （AIメタ分析の実行）自体も本タブでのみ行えます。

どちらのタブで操作しても、提案は同じ一覧を参照するため、一方のタブで承認・却下した
提案は、もう一方のタブの一覧にも反映されます。

## 提案を生成・更新する {#generate-and-refresh}

### AIメタ分析を実行 {#analyze-btn}

学習者のつまづきデータ（未回答クエリ）を AI に分析させ、新しいスキーマ拡張提案を
生成します。

1. 「AIメタ分析を実行」を押します。
2. 分析中は「AIがつまづきデータを分析中...」と表示されます。
3. 新しい提案が生成されると「提案が生成されました: 〈提案の要約〉」と表示され、
   提案一覧に追加されます。

分析対象のクエリが少ない、または現在のスキーマで十分にカバーされている場合は、提案は
生成されず「分析の結果、スキーマ拡張の提案はありません。未回答クエリが不足しているか、
現在のスキーマで十分カバーされています。」と表示されます（エラーではありません）。

実行中はボタンが押せなくなり、分析が完了する（成功・失敗いずれの場合も）と再び
押せるようになります。分析自体が失敗した場合は「分析に失敗しました」と表示されます。

### 提案を更新 {#refresh-btn}

新しい分析は実行せず、提案一覧・再抽出ジョブ・現在のスキーマ定義を最新の状態に
読み込み直します。

## 提案一覧 {#proposals-list}

生成された提案がカードで一覧表示されます。各カードには提案の要約・状態（保留中 / 承認済 /
却下）・理由・分析対象クエリ数・提案アイテム（概念 / 関係の種別・キー・説明）が表示されます。
提案がまだ無い場合は「提案はまだありません。「AIメタ分析を実行」ボタンで生成できます。」と
表示されます。

保留中の提案には、シミュレーションを介さず直接操作する2つのボタンが表示されます。

### 承認して適用 {#approve-btn}

提案をそのままスキーマへ反映します。**確認ダイアログは表示されず、押すとその場で
新しい概念タイプ・述語がスキーマに追加されます。**

事前に教材への影響を確認したい場合は、本タブではなく
[スキーマ提案タブ](22-admin-schema-proposals.md#simulate-btn) の
「シミュレーションを実行」から確認してください。

実行中はボタンが「処理中...」に変わり押せなくなります。処理が完了すると提案一覧が
更新され、対象の提案は保留中ではなくなります（承認済みとして扱われます）。

### 却下 {#reject-btn}

提案を却下します。却下は一方向の状態遷移で、却下した提案を再び保留中（承認可能な状態）に
戻すことはできません。実行中はボタンが押せなくなります。

## 再抽出ジョブ {#jobs-list}

提案の承認によって開始された再抽出ジョブを、ID・ステータス（待機中 / 実行中 / 完了 /
失敗）・処理済み件数 / 対象教材数・開始日時の一覧で確認します。読み取り専用です。
ジョブがまだ無い場合は「再抽出ジョブはありません」と表示されます。

## 現在のスキーマ定義 {#schema-definitions}

承認済みの拡張を含む、現在のスキーマ定義を確認できます。いずれも読み取り専用です。

### 概念カテゴリ（OntologyType） {#types-list}

登録されている概念カテゴリの一覧です。組み込みではなく提案の承認によって追加された
カテゴリには「[拡張]」の表示が付きます。

### 関係性タイプ（CorePredicate） {#preds-list}

登録されている関係性タイプの一覧です。概念カテゴリと同様、提案の承認によって追加された
ものには「[拡張]」の表示が付きます。
