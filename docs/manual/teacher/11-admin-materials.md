# 教材管理タブの操作

「教材管理」タブでは、PDF / TeX 教材のアップロードと、解析パイプラインが生成した
成果物（理論コンポーネント・主張・図表など）の実行・確認・共有・削除を行います。
アップロードや開示範囲・削除・解析コスト見積り・共有版・図の分類確認の基本手順は
[教材（materials）タブの操作](../../admin_operations/materials.md) にまとまっています。
本ページはこのタブに並ぶ個々の UI 要素のリファレンスです。ヘッダー・タブ共通の操作は
[管理画面の共通操作](10-admin-common.md) を参照してください。

## 画面の概要 {#overview}

上段に教材アップロード領域、下段にアップロード済み教材の一覧（ファイル名・タイトル・
ステータス・アップロード日時・操作）が表示されます。一覧の各行から、解析パイプラインの
実行・図や検出要素の確認・共有設定・削除などを行います。

## アップロード {#upload-area}

### アップロードゾーン {#upload-zone}

PDF または TeX（`.tar.gz` / `.tgz`）の教材ファイルをアップロードする領域です。

1. ファイルをドラッグ&ドロップするか、「ファイルを選択」からファイルを選びます。
2. アップロードすると解析パイプラインが自動で開始され、一覧の状態が
   「アップロード済み → 処理中 → 完了」と進みます。

対応していない形式のファイルを選ぶと、アップロードは開始されずエラーメッセージが
表示されます。詳しい手順は
[教材をアップロードする](../../admin_operations/materials.md#upload) を参照してください。

**アップロード中は操作できません**: アップロード処理の実行中は、アップロード領域全体が
淡色表示になり操作を受け付けません。アップロードが完了するかエラーになると、自動的に
元に戻ります。

### URLから取得（arXiv など） {#url-upload}

アップロードゾーンの中にあるリンクです。手元にファイルが無くても、論文の URL を指定して
教材を取り込めます。押すと[URLから教材を取得モーダル](#url-upload-modal)が開きます。
押した時点では取得は始まりません（モーダルで URL を入力してから実行します）。

取得できるのは、システム管理者が許可したドメインのものだけです。許可されていない
ドメインの URL を指定すると、取得は行われず理由が表示されます。

### モーダル: URLから教材を取得 {#url-upload-modal}

教材の URL を1つ入力して取得するモーダルです。

1. 「教材のURL」欄に論文の URL を入力します（PDF の URL、または TeX ソースの
   `.tar.gz` の URL）。
2. [アップロード](#url-upload-submit) を押すと、サーバがそのファイルをダウンロードし、
   ファイルを選んでアップロードした場合とまったく同じ解析パイプラインが始まります。
   一覧の状態も同じく「アップロード済み → 処理中 → 完了」と進みます。
3. 入力欄で Enter を押しても実行できます。「キャンセル」「×」、またはモーダルの外側を
   クリックすると閉じます。

入力欄の下には、取得できるドメインの一覧が事実として表示されます（「取得できるのは
管理者が許可したドメインのみです: …」）。

このモーダルを開いたとき、アップロードゾーンの
[図面・画像を解析する](#analyze-images) のチェック状態と
[解析モデル（変更）](#llm-model-change) で選んだモデルは、そのまま今回の取得にも
引き継がれます。取得する前に、必要ならモーダルを閉じてこれらを設定してください。

**ファイルの種類は中身で判定されます**: 取り込めるのは PDF と TeX の `.tar.gz` だけです。
URL の末尾が `.pdf` でも実際の中身が別の形式であれば、対応していない形式として
取得は行われません。

### アップロード（URL取得の実行） {#url-upload-submit}

[URLから教材を取得モーダル](#url-upload-modal)の右下にあるボタンです。押すと取得が
始まり、「取得しています...」と表示されます。取得が受理されるとモーダルは閉じ、教材
一覧に新しい行が追加されて解析の進行が表示されます。

**ボタンが無効になっている場合**: 次のいずれかです。理由は必ずボタンの上（URL 入力欄の下）に
表示されます。

- **許可ドメインが1件も登録されていない**: 「URLからの取得は、管理者が取得先ドメインを
  許可すると利用できます。」と表示されます。この機能は最初は無効な状態で、システム管理者が
  取得先ドメインを登録するまで使えません。システム管理者に、取得したいサイトのドメイン
  （例: `arxiv.org`）の登録を依頼してください。
- **許可ドメインの一覧を取得できなかった**: 「許可ドメインを取得できませんでした。時間を
  おいて開き直してください。」と表示されます。モーダルを閉じてもう一度開き直してください。
- **取得の実行中**: 送信してから応答が返るまでの間だけ押せなくなります（二重実行の防止）。
  完了するか失敗すると自動的に元に戻ります。

**取得に失敗した場合**: モーダルは閉じず、「取得に失敗しました: （理由）」が表示されます。
理由は次のような事実文です。

- 「このURLのドメインは許可されていません」——
  取得先が許可リストにありません。システム管理者に、そのドメインの登録を依頼してください。
- 「URL の接続先が内部アドレスのため取得できません」——
  取得先がサーバ内部のアドレスに解決されたため中止されました。外部に公開されている
  URL を指定してください。
- 「取得したファイルはPDFでもTeXアーカイブ（.tar.gz）でもありません」——
  論文本体のファイルを直接指す URL（紹介ページではなくファイルの URL）を指定してください。
- 「ファイルサイズが上限を超えています」——
  取り込めるサイズの上限を超えています。ファイルをいったん手元にダウンロードし、
  軽量化したうえで[アップロードゾーン](#upload-zone) からアップロードしてください。
- 「URLからの取得に失敗しました」——
  取得先に接続できなかった、または取得先がエラーを返しました。URL を確認し、時間をおいて
  再度お試しください。
- 「http/https 以外の URL は取得できません」——
  `http://` または `https://` で始まる URL を指定してください。

失敗した場合も教材は登録されません。表示される理由は事実の提示のみで、サーバ内部の
アドレスなどの内部情報は含まれません。

### arXivから探す {#arxiv-discovery}

アップロードゾーンの中にある、[URLから取得（arXiv など）](#url-upload) の隣のリンクです。
分野の条件（arXiv カテゴリとキーフレーズ）で arXiv を検索し、候補の一覧から選んだ論文だけを
教材として取り込みます。押すと [arXivから探すモーダル](#arxiv-discovery-modal) が開きます。
押した時点では検索も取得も始まりません（モーダルで条件を指定してから実行します）。

**候補を一覧するところまでが自動で、解析パイプラインに入るのはあなたが選んで実行した
論文だけです。** 条件に合う論文が自動で取り込まれることはありません。候補が見つかっても
通知やバッジは出ません（このモーダルを開いたときに新しいものが並んでいるだけです）。

取り込みには、システム管理者が取得先ドメインとして `arxiv.org` を許可していることが必要
です。未登録でも検索と候補の閲覧はできますが、
[選択した論文を取り込む](#arxiv-discovery-ingest) ボタンは無効になります。

### モーダル: arXivから探す {#arxiv-discovery-modal}

上から「検索・購読パネル」「候補一覧」「取り込み」の3つの区画で構成されます。
「閉じる」「×」、またはモーダルの外側をクリックすると閉じます。

**① 検索・購読パネル（上段）**

- **分野**: 条件を保存する単位です。入力欄をクリックすると、保存済みの購読条件・
  カートリッジ・ナレッジライブラリの分野が候補として表示されます。一覧にない分野名を
  自由に入力することもできます。分野を選ぶと、保存済みの条件があれば読み込まれ、欄の右に
  「前回の検索: …」または「この分野の購読条件はまだ保存されていません。」と表示されます。
- **arXiv カテゴリ**: `astro-ph.CO` のような arXiv のカテゴリを入力して「追加」で足します
  （入力欄で Enter を押しても追加できます）。チップの「×」で外します。
- **キーフレーズ**: 検索語です。「追加」で自由に足せるほか、分野の語彙（分野の地図の概念・
  カートリッジ語彙・承認済みの理論部品）から候補が自動で供給されます。各チップにマウスを
  重ねると、そのフレーズがどこから来たか（「分野の地図の概念から」「カートリッジ語彙から」
  「承認済み理論部品から」「手動」）が表示されます。**チップをクリックすると外れ、
  打ち消し線の表示で残ります**（消えるのではなく「使わない」状態として保持され、もう一度
  クリックすると戻ります）。既に保存済みの分野に新しい候補が供給されたときは「N件の新しい
  キーフレーズ候補が分野語彙から供給されました（外れた状態です。使うにはクリックして
  ください）。」と表示されます。**供給された候補が、あなたのクリックなしに検索条件へ
  加わることはありません。**
- **著者フォロー（任意）**: 追いたい著者名を足せます。

**② 候補一覧（本体）**

一覧の上には、実際に使われた検索条件と該当件数、そして「この一覧は検索条件に一致した範囲
のみを示します。」が常に表示されます。**この一覧は arXiv をその条件で検索した結果であって、
その分野の論文の全体ではありません。**

各カードにはタイトル・著者・日付・カテゴリが並び、条件に当たったキーフレーズが「一致: …」の
1行で示されます（順位や点数は表示されません）。並び順は既定では arXiv の新着順で、
[並び順](#arxiv-discovery-order) で関連度順に変えられます。「要旨」を開くと
アブストラクトを読めます。「arXiv で開く」で arXiv のページを別タブで開けます。

カードに「地図上の近い領域: …（近さの段階・骨格 版…）」の1行が出ることがあります。これは
**取り込んだとしたら分野の地図のどのあたりに落ちそうか**の目安で、[並び順](#arxiv-discovery-order)
を「関連度順」にしたときにだけ表示されます。取り込み前の目安であって、確定した配置では
ありません（実際の配置は取り込んだ後の解析で決まり、教員が確認します）。どの版の地図の中での
言明かを示すため、骨格の版が併記されます。数値は表示されず、近さは段階の言葉だけです。行が
出ない候補は、近い領域が見つからなかったか、その分野の地図がまだ公開されていない場合です。

- **見送る**: その論文をこの分野の候補から外します。行は消えず、「見送り済み」として保持
  されます。一覧の上の「見送り済みを表示」にチェックを入れると表示され、「戻す」で候補に
  戻せます。
- **取り込み済み**: 既に取り込まれている論文はチェックボックスが出ず、「取り込み済み」と
  表示されます。判定できるのは URL 経由（このモーダル、または
  [URLから取得](#url-upload)）で取り込まれた論文だけです。ファイルを選んでアップロードした
  同じ論文は判定できません（一覧の上にもその事実が注記されています）。

**③ 取り込み（下段）**

チェックを入れた論文の件数と、実行すると何が起きるかの説明が表示され、
[選択した論文を取り込む](#arxiv-discovery-ingest) で実行します。

**検索・候補一覧・見送りでは AI（LLM）は使いません。** arXiv が公開しているメタデータを
読むだけです。LLM を使うのは、取り込んだ後の解析パイプラインです（唯一の例外は
[並び順](#arxiv-discovery-order) を「関連度順」にしたときの並べ替えで、候補の要旨の
ベクトル化だけを行います。候補が増減することはありません）。

### 並び順 {#arxiv-discovery-order}

検索・購読パネルの下、[この条件で検索](#arxiv-discovery-search) の上にある選択欄です。
「新着順」（既定）と「関連度順」から選べます。

**選び直しただけでは一覧は並び替わりません**（欄の隣に「並び順は次の検索から適用されます。」
と表示されています）。次に [この条件で検索](#arxiv-discovery-search) を押したときから
適用されます。モーダルを開き直すと既定の「新着順」に戻ります。

- **新着順**: arXiv が返した新しい順です。
- **関連度順**: **その分野で既に取り込んだ論文との近さの目安**で並べ替えます。各カードには
  「関連: 高」「関連: 中」「関連: 低」の段階ラベルが付きます。**数値（点数・類似度・順位）は
  表示されません。** 並べ替えるだけで、候補が絞り込まれたり捨てられたりすることはありません
  （検索条件そのものはカテゴリとキーフレーズのままです）。

一覧の上の条件行には、**実際に適用された並び順**が表示されます（選んだ並び順ではありません）。

**関連度順が使えなかったとき**は、候補は**新着順のまま**表示され、その理由が一覧の上に
表示されます。理由は次のいずれかです。

- 「並べ替える候補がありません。」（候補が0件のとき）
- 「この分野には、関連度の基準にできる取り込み済み論文がまだありません。新着順で表示します。」
  （その分野の教材がまだ無いとき。この分野に論文が無いという意味ではありません）
- 「本日の関連度計算の上限に達しました。新着順で表示します。」
- 「関連度を計算できませんでした。新着順で表示します。」

いずれの場合も検索そのものは成立し、候補は表示されます。このとき段階ラベルは付きません
（測れていないものを測れたように見せないためです）。

[引用グラフから探す](#arxiv-discovery-citation-search) で表示した一覧は、並び順の対象外です
（関連度のラベルも付きません）。

### この条件で検索 {#arxiv-discovery-search}

検索・購読パネルの下にあるボタンです。押すと「arXiv を検索しています...」と表示され、
結果が候補一覧に並びます。押した時点で使われるのは**画面に表示されている条件**
（分野・カテゴリ・外していないキーフレーズ）で、保存済みの条件とは限りません。条件を
変えただけでは保存されません（保存は [この条件を保存](#arxiv-discovery-subscribe) です）。

- **候補が0件だったとき**: 「この検索条件では候補が見つかりませんでした。条件を変えると
  別の論文が見つかることがあります。」と表示されます。これは「この分野に論文が無い」
  という意味ではありません。
- **カテゴリもキーフレーズも指定していないとき**: arXiv は検索されず、一覧の上に
  「検索条件: 指定されていません（カテゴリまたはキーフレーズを指定してください）。」と
  表示されます。
- **分野を入力していないとき**: 「分野を入力してください。」と表示され、検索は行われません。
- 検索の実行中はボタンを押せません（二重実行の防止）。失敗したときは理由が上部に表示され、
  ボタンは元に戻ります。

### 引用グラフから探す {#arxiv-discovery-citation-search}

[この条件で検索](#arxiv-discovery-search) の隣にあるボタンです。**その分野で既に取り込んだ
arXiv 論文を起点（シード）にして、引用・推薦の関係でつながる論文を候補として並べます。**
arXiv カテゴリやキーフレーズは使いません（検索条件とは別の探し方です）。押すと
「引用グラフから候補を探しています...」と表示されます。

結果は通常の検索結果と混ざりません。一覧の上には出所が常に表示されます。

> 候補の出所: 引用グラフ ／ シード: （起点にした論文のタイトル）… ／
> この一覧は取り込み済み論文の引用・推薦関係から導出した範囲のみを示します。

各カードには「引用元: …」の行が付き、**どの取り込み済み論文から辿った候補なのか**が
分かります。「見送る」「取り込み済み」の扱いと、
[選択した論文を取り込む](#arxiv-discovery-ingest) による取り込みは通常の検索結果と同じです。
**このボタンは候補を並べるだけで、取り込みは行いません。**

- **起点になる論文がまだないとき**: 「この分野には、引用関係をたどる起点になる取り込み済みの
  arXiv 論文がまだありません。」と表示されます。まず[この条件で検索](#arxiv-discovery-search)
  などで論文を取り込んでください。判定に使えるのは URL 経由で取り込まれた arXiv 論文だけです。
- **候補が0件だったとき**: 「引用グラフからは候補が見つかりませんでした。取り込み済みの論文が
  増えると候補が変わることがあります。」と表示されます。
- **外部の照会に届かなかったとき**: 「引用グラフの照会に接続できませんでした。時間をおいて
  再度お試しください。」と表示されます。
- **分野を入力していないとき**: 「分野を入力してください。」と表示され、照会は行われません。

**この探し方でも AI（LLM）は使いません。** 外部の引用グラフが公開しているメタデータを読む
だけです。関連度の段階ラベルは付きません（[並び順](#arxiv-discovery-order) の対象外です）。

**ボタンが無効になっている場合**: 次のいずれかです。理由はボタンの下に表示されます。

- **サーバで有効化されていない**: 「引用グラフによる候補供給は有効化されていません
  （サーバ設定）。」と表示されます。この機能はサーバ環境変数
  `DISCOVERY_CITATION_SOURCE_ENABLED` による任意設定で、**既定では無効**です。システム管理者に
  有効化を依頼してください（管理画面から切り替えることはできません）。
- **利用可否を確認できなかった**: 「引用グラフによる候補供給の利用可否を確認できませんでした。」
  と表示されます。購読条件の読み込みに失敗した場合などです。モーダルを閉じて開き直すと
  再確認されます（この間も[この条件で検索](#arxiv-discovery-search)は使えます）。
- **照会の実行中**: 応答が返るまでの間だけ押せなくなります（二重実行の防止）。

### この条件を保存 {#arxiv-discovery-subscribe}

いま画面に表示されている条件（arXiv カテゴリ・キーフレーズ・著者フォロー）を、その分野の
購読条件として保存するボタンです。保存すると「この分野の購読条件を保存しました。」と表示
され、次にこの分野を選んだときに同じ条件が読み込まれます。

外した（打ち消し線の）キーフレーズも「使わない」状態のまま一緒に保存されます。捨てられる
わけではないので、あとから戻せます。

購読条件は**分野ごとに1つの共同の設定**です。同じ分野を扱う他の教員も同じ条件を読み込み、
保存すると上書きされます（最後に保存した内容が残ります）。自分専用の条件にはなりません。

分野を入力していない場合は「分野を入力してください。」と表示され、保存は行われません。
保存に失敗した場合は理由が上部に表示され、条件は画面に残ります。

### 選択した論文を取り込む {#arxiv-discovery-ingest}

モーダル右下のボタンです。チェックを入れた論文を arXiv から取得し、ファイルを選んで
アップロードした場合とまったく同じ解析パイプラインに乗せます。

押す前に、ボタンの上に必ず次の事実が表示されます。

> N件の論文を取得し、解析パイプラインを実行します。解析には LLM を使用します。解析結果は
> 候補として保存され、公開するまで学習者には表示されません。

**選んだ件数によって、押したときに起きることが変わります。**

- **5件まで**: その場で取得と解析が始まります（上の事実文が表示されます）。
- **6件以上**: 取得は[取り込みキュー](#arxiv-discovery-queue)への登録になります。サーバが
  1件ずつ・間隔をあけて順に取得・解析します。この場合は事実文が次の内容に切り替わります。

  > N件をキューに登録します。サーバが順に取得・解析します（1件ずつ・間隔をあけて実行）。
  > 進捗はこのモーダルの取り込みキュー欄と教材一覧で確認できます。解析には LLM を使用します。
  > 解析結果は候補として保存され、公開するまで学習者には表示されません。

**一度にキューへ登録できるのは50件までです。** 51件以上を選ぶと「一度にキューへ登録できるのは
50件までです。選択を減らしてください。」と表示され、ボタンは押せません（この上限はサーバ側でも
拒否されます）。

論文を選ぶと、確認欄に**1論文あたりのトークン目安**の1行が出ることがあります
（「1論文あたりの解析トークンの目安: …」）。これは過去の解析実績にもとづく目安をレンジで
示すもので、実測（reported）と推計（estimated）は合算せず並べて表示されます。金額は表示
されません。実績がまだない場合は「解析の実績がまだないため、目安を示せません。」と表示され、
目安そのものを取得できなかったときは行が出ません（どちらの場合も取り込みは止まりません）。

このとき使われる解析の設定は、アップロードゾーンの
[図面・画像を解析する](#analyze-images) のチェック状態と
[解析モデル（変更）](#llm-model-change) で選んだモデルです。必要なら、取り込む前に
モーダルを閉じてこれらを設定してください。

その場で取得したとき（5件まで）は「N件の取り込みを開始しました。進捗は教材一覧で確認
できます。」と表示され、教材一覧に行が追加されて「アップロード済み → 処理中 → 完了」と
進みます。取り込みのための専用の進捗画面はありません。一部だけ失敗した場合は、成功した
件数と、失敗した論文ごとの理由（arXiv ID と事実文）が並べて表示されます。

キューへ登録したとき（6件以上）は「N件をキューに登録しました。進捗は下の「取り込みキュー」で
確認できます。」と表示され、[取り込みキュー](#arxiv-discovery-queue)が自動的に開きます。
**キューに登録された時点では、まだ取得も解析も終わっていません。** 候補一覧の表示は
「取り込み済み」にはならず、チェックだけが外れます。登録できなかった論文があれば、その
arXiv ID と理由が並べて表示されます。取得先ドメインが許可されていない状態で登録した場合は、
受理はされたうえで「現在、取得先ドメインが許可されていないため、許可されるまで取り込みは
失敗します。」が併せて表示されます。

**ボタンが無効になっている場合**: 次のいずれかです。理由は必ずボタンの上に表示されます。

- **論文を1件も選んでいない**: 「取り込む論文を選択してください。」と表示されます。候補
  一覧でチェックボックスを入れてください（「取り込み済み」「見送り済み」の論文は選べません）。
- **許可ドメインが登録されていない**: 「取得先ドメインが許可されていません。システム管理者が
  「AIモデル」タブで設定できます。」と表示されます。システム管理者に、「AIモデル」タブの
  取得先ドメイン設定で `arxiv.org` を登録するよう依頼してください（登録するまでは、この
  ボタンだけでなく[URLから取得](#url-upload)も使えません）。
- **取り込みの実行中**: 送信してから応答が返るまでの間だけ押せなくなります（二重実行の
  防止）。完了するか失敗すると元に戻ります。

なお、許可ドメインの一覧を確認できなかったときは「許可ドメインを確認できませんでした。
取り込みはサーバ側で拒否される場合があります。」と表示されます。この場合ボタンは押せますが、
実際に許可されていなければサーバ側で拒否され、その理由が表示されます（許可の判定は必ず
サーバ側で行われます）。

### 取り込みキュー {#arxiv-discovery-queue}

候補一覧と取り込み確認の間にある、**既定で閉じた**「取り込みキュー」欄です。見出しを
クリックすると開閉します。[選択した論文を取り込む](#arxiv-discovery-ingest) で6件以上を
登録したときは、登録の直後に自動で開きます。

キューに並ぶのは、サーバがこれから取得・解析する（あるいは既に処理を終えた）項目です。
新しい順に並び、**分野で絞り込まれません**（どの分野の項目かは各行に表示されます）。

各行には、論文のタイトル（無ければ arXiv ID）と、状態・arXiv ID・分野が表示されます。
状態は次の4つです。

- **待機中**: 登録済みで、まだ取得を始めていません。
- **取得中**: サーバが arXiv から取得しています。
- **受理済み**: 取得が終わり、解析パイプラインに渡されました。以降の進捗は教材一覧で
  確認します。
- **失敗**: 取得または受理に失敗しました。理由が行の中に事実文で表示されます。

**失敗した行は消えません。** 理由の下に「再試行」ボタンが出て、押すとその項目だけが
「待機中」に戻り、サーバが改めて取得します。前回の理由は消さずに残ります。再試行できるのは
失敗した項目だけで、それ以外を再試行しようとすると「再試行できるのは失敗した項目だけです。」
と表示されます。

**この欄は自動では更新されません**（欄の中にも「自動では更新されません。」と表示されて
います）。状態が進んでも、開いたままにしているだけでは表示は変わりません。最新の状態を
見るには [更新](#arxiv-discovery-queue-refresh) を押してください。キューの件数を知らせる
バッジや通知はありません。

キューが空のときは「キューに項目はありません。」と表示されます。読み込めなかったときは
「取り込みキューを読み込めませんでした。」と表示されます（この場合も候補の検索や取り込みは
続けられます）。

### キューの更新 {#arxiv-discovery-queue-refresh}

[取り込みキュー](#arxiv-discovery-queue)の中にある「更新」ボタンです。押すと、その時点の
キューをサーバから読み直して一覧を描き直します。読み込み中は「読み込んでいます...」と
表示されます。

キューを読みに行くのは、**モーダルを開いたとき・キューに登録した直後・このボタンを押した
とき**の3つだけです。定期的な自動更新（ポーリング）は行いません。「待機中」や「取得中」の
項目がどこまで進んだかを知りたいときは、このボタンを押してください。

読み込みに失敗したときは「取り込みキューを読み込めませんでした。」と表示されます。もう一度
押せば読み直せます。

### 学習者の関心 {#arxiv-discovery-interest}

検索・購読パネルのすぐ下に出ることがある区画です。学習者が「論文の海」（コースの外から
分野の地図と論文を見わたす画面）で**地図の端**を開き、「この先を知りたい」を押した記録の
集計を、事実の行として表示します。

各行は次の形です。

**学習者の関心: {領域または分野} — {地図の縁 または 地図の外} — {人数の範囲}人**

- **地図の縁** — 既に取り込まれているのに、現在の分野の地図のどこにも置けていない主題です。
- **地図の外** — 保存済みの購読条件による前回の検索で、まだ取り込まれていない論文が
  arXiv にあった、ということです。

**表示されるのは人数の範囲だけです**（3-5 / 6-10 / 11+）。誰が押したか・いつ押したか・
どの行が多いかという順位は表示されません。人数が少ない集計は、範囲であっても表示されません
（同じ設定を使う他の集計と同じ、人数のしきい値による非表示です）。**この表示を学習者個人の
評価に使うことはできません。**

**行が1つも無いときは、この区画ごと表示されません。** 表示されないことは「関心が無い」と
いう意味ではなく、「範囲として表示できる集計がまだ無い」という意味です。読み込めなかった
ときも同じように表示されません。

読みに行くのは、**モーダルを開いたときと、分野を選び直したとき**の2つだけです。定期的な
自動更新（ポーリング）や更新ボタン、件数バッジはありません。分野を選んでいるときはその分野の
行だけが、まだ分野を選んでいないときは表示できるすべての分野の行が並びます。

**この表示は何も自動で変えません。** 学習者の関心にもとづいて検索条件が広がったり、論文が
自動で取り込まれたり、分野の地図が書き換わったりすることはありません。関心の行を見て
[この条件で検索](#arxiv-discovery-search) するか、条件を足すか、何もしないかは教員の判断です。

### 図面・画像を解析する {#analyze-images}

アップロードする教材の図・画像に対して、装置・パーツの同定に vision AI を使う解析
（apparatus_semantics ステージ）を追加で実行するかどうかのチェックボックスです。既定は
オフで、明示的にオンにしたときだけ vision AI が呼ばれます。

このチェックボックスをオンにすると、[解析モデル（変更）](#llm-model-change) のパネルを
開いたときに図の解析用モデルの選択肢も表示されます。

### 解析モデル（変更） {#llm-model-change}

このアップロードで使う解析モデルの1行サマリです。既定では自分にとっての実効モデル
（システム既定またはあなたが以前保存した既定）がそのまま表示されます。

1. 「変更」を押すとモデル選択パネルが開きます。パネルが開いている間、このボタンの
   ラベルは「閉じる」に変わります。
2. 解析モデル（テキスト系ステージ用）を選び直せます。「図面・画像を解析する」を
   オンにしている場合は、図の解析（vision）用モデルの選択欄も表示されます。
3. 「ステージ別に指定する（詳細）」を開くと、テキスト系ステージごとに個別のモデルを
   指定できます（既定は「継承（実効モデル）」）。図の解析（vision）はこの表には
   含まれません（手順 2 の選択欄で指定します）。ここでの指定は今回のアップロードだけに
   適用され、既定として保存されません。
4. 「この設定で解析する」を押すと選択したモデルがあなたの既定として保存されます。
   「既定に戻す」を押すと、以前保存した既定を解除してシステム既定に戻します。
5. 保存せずに閉じたいときは、パネル右上の「閉じる」または「変更」（＝「閉じる」）を
   押します。選択内容は保存されません。

選ばれたモデルはあなた自身のアップロード・解析再開にのみ適用され、他の教員には影響しません。
表示されるのは実際のモデル名のみで、内部の性能区分（fast/standard/deep など）は表示されません。

**「変更」ボタンが押せない（グレーアウトしている）場合**: モデルの選択肢を取得できません
でした（モデルカタログが未設定、または取得に失敗しました）。隣に理由が表示されます。
システム管理者にモデルカタログの設定を確認してください。

### AI利用枠の見通し {#cost-forecast-note}

解析モデルのサマリ行の下（および[解析を再開モーダル](#reanalyze-modal)の解析モデル行の
下）に、「この規模の処理は、今日のAI利用枠に収まらない可能性があります。分けて実行する
こともできます」という趣旨の一行が表示されることがあります。

- 今日のAI利用枠に収まる見込みのときは、この行自体が表示されません（何も表示されて
  いないのが平常の状態です）。
- 表示は事実の提示までです。アップロード・再解析のボタンが無効になったり、処理が
  止められたりすることはありません。実行するか、分けて実行するかは教員の判断に
  委ねられます。
- 件数・残回数などの数値は表示されません。見通しの取得に失敗した場合も何も表示されず、
  処理は通常どおり実行できます。

### 一覧を更新 {#refresh-materials}

アップロード済み教材の一覧をサーバから再取得します。アップロード直後や、他の操作の完了後に
最新の状態を確認したいときに押します。

## 教材一覧の行操作 {#row-actions}

各教材の行の「操作」列には、左から **「パイプラインを実行 ▼」、グラフのアイコン
（[グラフレビュー](26-admin-graph-review.md#graph-review-open)）、📡 アイコン
（[近い論文を探す](#radar-open)）、「⋯」（操作メニュー）** が並びます。頻繁に使う2つの
入口だけをアイコンとして行に出し、確認・共有・削除などその他の操作は「⋯」メニューの中に
まとめられています。2つのアイコンは解析結果（document_id）が付いた教材にのみ表示されます。
教材のアップロード直後は解析がまだ進んでいないため、アイコンと一部のメニュー項目はまだ
表示されません。アイコンにマウスを重ねると名称と説明が表示されます。

解析が失敗した教材では、ステータス列にも「解析を再開」「PDFを再登録」のリンクが表示され、
メニューを開かずにその場で対処できます（メニュー内の同じ項目と同じ動作です）。

### 操作メニュー（⋯） {#row-more-menu}

その教材に対して行える操作をまとめたメニューです。「⋯」を押すと開き、もう一度押すか
メニューの外側をクリックすると閉じます。項目を選ぶとメニューは閉じます（PDF再登録だけは、
項目のラベル上で進捗を表示するため開いたままになります）。

メニューには上から順に次の項目が並びます。

1. [図・画像](#row-figures)
2. [検出要素](#row-inventory)
3. [共有設定…](#row-share)
4. [版の管理…](#row-version)
5. [位置づけ（分野マップ）…](#landscape-open)
6. [ゼミ前ブリーフ…](#seminar-brief-open)
7. [解析コスト見積り…](#row-estimate)
8. [PDF再登録](#pdf-reupload)
9. [解析再開](#resume-analysis)（ステータスが「失敗」の教材のみ）
10. 区切り線の下に [削除…](#row-delete)（赤字。取り消せない操作なので分離しています）

[グラフレビュー](26-admin-graph-review.md#graph-review-open) と
[近い論文を探す](#radar-open) はこのメニューには入っておらず、行のアイコンボタンから
直接開きます。

**項目が表示されていない場合**:

- 「図・画像」「検出要素」「共有設定…」「版の管理…」「位置づけ（分野マップ）…」「ゼミ前ブリーフ…」が無い: その教材にまだ document_id が
  付与されていません（解析が完了・失敗まで進んでいない状態です）。アップロード後、
  ステータスが「処理中」から先へ進むまで待ってください。
- 「解析再開」が無い: ステータスが「失敗」ではない教材、または document_id が未付与の教材では
  表示されません。解析が成功している教材をやり直したい場合は
  [パイプラインを実行](#pipeline-run)を使います。

### パイプラインを実行 {#pipeline-run}

解析パイプラインを（全ステージ、または個別ステージから）再実行するメニューです。

1. 「パイプラインを実行 ▼」を押すとメニューが開きます。
2. 「パイプライン全実行」または、グループ別に並んだ個別ステージのいずれかを選ぶと、
   確認モーダル（[危険確認モーダル](10-admin-common.md#danger-confirm-modal)）を経て
   そのステージ（または全体）が再実行されます。既存の実行結果は上書きされます。
3. メニュー内の「反復改善（採用版を保ったまま）」は[反復改善モーダル](#revision-modal)を、
   「外部レビュー用に書き出し」は[外部レビュー用に書き出しモーダル](#export-modal)を開きます。

**ボタンが無効（グレーアウト）になっている場合**: 教材の解析がまだ進んでおらず
document_id が付与されていません。アップロード後、解析が処理中から完了（または失敗）に
進むまで待ってください。

### PDF再登録 {#pdf-reupload}

[操作メニュー（⋯）](#row-more-menu)の中にあります。保存済みの教材に対して、PDF ファイル
本体だけを差し替えます（解析のやり直しではなく、ファイルの登録のみを行います）。すでに
PDF が登録済みの場合は項目に「PDF再登録（登録済）」と表示されます。

1. 項目を押してファイルを選びます。
2. アップロード中は項目が「登録中...」と表示され、押せなくなります。
3. 完了すると「完了」と表示され、しばらくすると元のラベルに戻ります。

既存の PDF と内容が一致しない場合は登録に失敗し、エラーメッセージが表示されます。
チャンク作成に失敗した教材（ステータスが失敗かつチャンク件数0件）では、項目に
「失敗 (PDF再登録)」と表示され、PDF の再登録が必要であることを示します。この場合は
ステータス列にも「PDFを再登録」のリンクが出るので、メニューを開かずに実行できます
（動作は同じです）。

### 解析再開 {#resume-analysis}

[操作メニュー（⋯）](#row-more-menu)の中にあります。解析が失敗した教材について、保存済みの
PDF から解析を再開します。ステータスが「失敗」で、かつ document_id が付与されている教材の
行にのみ表示されます。

1. 「解析再開」を押すと[解析を再開モーダル](#reanalyze-modal)が開きます。
2. モーダルでオプションを確認し、「再開する」を押すと解析が再開されます。

失敗した教材ではステータス列にも「解析を再開」のリンクが出ます（動作は同じです）。

### 図・画像 {#row-figures}

[操作メニュー（⋯）](#row-more-menu)の中にあります。教材から抽出された図・画像を確認する
[図・画像モーダル](#figures-modal)を開きます。document_id が付与された教材にのみ
表示されます。

### 検出要素 {#row-inventory}

[操作メニュー（⋯）](#row-more-menu)の中にあります。この教材からパイプラインが検出した
理論コンポーネント・主張・数式・図をまとめて一覧表示する
「検出要素」モーダルを開きます。表示はすべて既存データの読み出しで、確定済みの判断では
ありません。各要素の「深く検討」から、要素検討ワークスペース（内訳の確認・AI との対話・
候補としての解釈の付与）を開けます。document_id が付与された教材にのみ表示されます。

### 共有設定 {#row-share}

[操作メニュー（⋯）](#row-more-menu)の中にあります。教材の開示範囲（公開/グループ限定/
非公開）と、解析成果（理論コンポーネント・グラフ・
主張）のグループ単位の共有を設定するモーダルを開きます。document_id が付与された教材にのみ
表示されます。

1. 「開示範囲」で公開/グループ限定/非公開を選び、「適用」を押します。
2. 「解析成果のグループ共有」では、グループごとに viewer（閲覧・引用）または editor
   （編集・再解析）の権限を追加・変更・解除できます。

開示範囲を **public（公開）** に変更しようとすると、
[危険確認モーダル](10-admin-common.md#danger-confirm-modal)が表示されます。

## 位置づけ（分野マップ） {#landscape}

解析パイプラインは、教材（論文）が**分野マップ（基準地図）のどの領域に位置づくか**の候補を
AI で生成します。1つの論文が複数の領域に、しかも複数の観点（対象から・問いから・方法から・
理論から・観測から・応用から）で置かれるのが通常の状態です。分野マップは唯一の正しい分類
ではなく投影のひとつなので、複数の位置に置かれることは矛盾ではありません。

各配置には、なぜその領域と関係するのかの理由と、教材の原文からの引用（根拠）が付きます。
関連の強さは「強い関連 / 関連 / 弱い関連」の段階ラベルで表示され、内部の数値スコアは
教員にも表示されません。

### 位置づけ（分野マップ）… {#landscape-open}

[操作メニュー（⋯）](#row-more-menu)の中にあります。この教材の配置候補を確認・確定する
[位置づけモーダル](#landscape-modal)を開きます。document_id が付与された教材にのみ
表示されます。

### 位置づけモーダル {#landscape-modal}

配置候補を分野ごとにグループ化して一覧表示します。分野の見出しの下には、その配置に
使われた骨格（分野マップ）の版が表示されます。

各行には、配置先のアンカー名・観点ラベル・関連の段階ラベル・状態のラベル・理由が並び、
「原文の引用を見る」を開くと根拠となった原文の逐語引用（主張と対応づいている場合は
その主張のID）が表示されます。教員が入力したメモがある行では、メモも表示されます。

状態は次の4つです。

- **AIによる推定（未確認）**: AI が生成したままで、まだ誰も確認していない候補です。
- **教員確認済み**: 教員が[確認]を押して確定した配置です。
- **確認待ち（AI推定）**: 教員が[再検討]を押して、判断を保留した配置です。
- **却下**: 教員が[却下]を押した配置です。行は履歴として残ります（消えません）。

各行のボタンの動作は次のとおりです。押すとその場でサーバに保存され、一覧が読み直されます。

1. **[確認]** — その配置を「教員確認済み」にします。
2. **[却下]** — その配置を「却下」にします。行は削除されず履歴として残ります。
3. **[再検討]** — その配置を「確認待ち（AI推定）」に戻します。

**学習者に見えるもの**: 「AIによる推定（未確認）」「確認待ち（AI推定）」「教員確認済み」の
配置は、学習者にも**出所のラベル付きで**表示されます（未確認のものは「AIによる推定
（未確認）」と明示されます）。**[却下]した配置は学習者側からすぐに見えなくなります。**
数値は学習者にも表示されません。

**配置できなかった分野**: どの領域にも置けなかった分野は、「この論文は「◯◯」の地図に
配置できませんでした: （AIの理由）」という事実文で下部に表示されます。これは失敗ではなく、
分野マップの構造を見直す材料として記録されているものです。

**現在の状態を押しているボタンは押せません（グレーアウト）**: すでにその状態になっている
配置では、同じ状態にするボタンだけが無効になります（例: 「教員確認済み」の行では[確認]が
押せません）。別の状態へ変えることはいつでもできます。

一覧の一番下には、この表示の出所（AI 推定を含むこと）と、最終生成日時・使用した骨格の版が
事実として表示されます。配置候補がまだ1件も無い場合は「配置候補はまだありません。
[AIで再提案] で生成できます。」と表示されます。

### AIで再提案 {#landscape-propose}

モーダル右上にあります。押すと AI が配置候補を作り直します。

1. 押すとラベルが「生成中...」に変わり、完了するまで押せなくなります。
2. 完了すると結果が事実文で表示され、一覧が読み直されます。
3. **教員が[確認]・[却下]・[再検討]した配置は上書きされません。** 作り直されるのは
   未確認（AIによる推定）の候補だけです。

**ボタンが無効（グレーアウト）になっている場合**: 次のいずれかです。

- 再提案の処理を送信してから応答が返るまでの間だけ押せなくなります（二重実行の防止）。
  応答が返ると自動的に元に戻ります。
- 生成に失敗した場合も元に戻ります。その際は理由が事実文で表示されます。

また、次の場合は押しても配置候補が作られず、理由が事実文で表示されます。

- **凍結済みの分野マップ（骨格）がまだありません**: 「分野の地図」タブで骨格を凍結すると
  配置候補を生成できます。
- **配置の判断に使える解析結果がまだありません**: 中心命題や主張が抽出されていません。
  解析パイプラインの完了後に再度お試しください。
- **本日の生成上限に達しました**: 翌日以降に再度お試しください（上限は分野マップの配置
  候補生成だけの日次上限で、他の AI 機能とは別に数えられます）。

### 地図への候補として記録されています {#landscape-gap-signal}

「配置できなかった分野」の行の下に、「この分野の地図への候補として記録されています
（分野の地図タブで確認できます）」という一行が出ることがあります。これは、この論文で
見つかった「いまの地図では言い表せなかった主題」が、その分野の候補として記録されている
という事実の表示です。

- この行は**表示だけ**です。ここから地図を変更する操作はありません（1本の論文の画面で
  共同の地図を直せてしまわないようにしています）。
- 記録された主題が**複数の論文に共通して現れた場合だけ**、「分野の地図」タブの
  [論文の解析から見つかった候補](17-admin-atlas.md#gap-candidates)にレビュー対象として
  並びます。1本の論文だけの主題は、この行の記録だけに留まります。
- 地図に足すかどうかの判断と、次版の下書きへの取り込みは「分野の地図」タブで行います。

## 論文レーダー（近い論文を探す） {#radar}

この教材（論文）を**起点**に、arXiv から近さ（距離）を選んで他の論文を探す機能です。
[arXivから探す](#arxiv-discovery) が「分野の条件で網を張る」発見であるのに対し、
論文レーダーは「1本の論文から周辺を照らす」発見です。

**候補を並べるところまでが自動で、解析パイプラインに入るのはあなたが選んで実行した
論文だけです。** 条件に合う論文が自動で取り込まれることはありません。検索も、AI による
比較分析も、ボタンを押したときだけ実行されます（自動検索・自動比較・通知・バッジは
ありません）。

この画面から分野の購読条件が書き換わることはありません（保存ボタンはありません）。
[arXivから探す](#arxiv-discovery) の「見送り」の記録も、レーダーからは読み書きしません。

**距離は3つです。**

- **近い** — 分野もテーマも近い論文です。アプローチや結論の違いを見るのに向いています。
  この距離のときだけ、キーフレーズによる絞り込みが使われます。
- **中間** — 同じ分野で、テーマが部分的に重なる論文です。
- **同じ分野の別テーマ** — 同じ arXiv カテゴリで、テーマが離れている論文です。分野の地図の
  まだ埋まっていないところを広げたいときに使います。

候補には「距離: 近い / 中間 / 遠い」の**段階ラベル**だけが付きます。近さの数値スコアは
教員にも表示されません。**距離を測れなかった候補にはラベルを付けず**、「距離を判定できません
でした」の区画に分けて表示します（測れなかったものを「遠い」に見せかけることはしません）。

距離のほかに、候補が**分野の地図のどこに落ちそうか**、起点の論文の**どの部品と重なりそうか**、
起点の位置づけに**無い場所**はどこかが、候補ごとに短く表示されます
（[モーダル: 論文レーダー](#radar-modal)）。これらはすべてタイトルと要旨からの推定で、
件数や数値は表示されません。

**この一覧は「その論文に近い論文の全体」ではありません。** 指定した条件で arXiv を検索した
範囲の結果です。使われた検索条件と、その旨の注記が候補一覧の上に常に表示されます。

### 近い論文を探す（📡 アイコン） {#radar-open}

教材行の「操作」列にある 📡 のアイコンボタンです（「⋯」メニューの中ではなく、
「パイプラインを実行 ▼」とグラフのアイコンの右隣に直接並びます）。マウスを重ねると
「近い論文を探す」と説明が表示されます。この教材を起点にした
[論文レーダーモーダル](#radar-modal) を開きます。document_id が付与された教材にのみ
表示されます。押した時点では検索も取得も始まりません（モーダルで距離と条件を指定してから
実行します）。

**アイコンが表示されない場合**: その教材にまだ解析結果（document_id）がありません。
先に「パイプラインを実行」で解析を進めてください。

### モーダル: 論文レーダー {#radar-modal}

上から「起点の教材」「距離と検索条件」「候補一覧」「取り込み」の区画で構成されます。
「閉じる」「×」、またはモーダルの外側をクリックすると閉じます。

**起点の教材**: 教材のタイトルと、分かる場合は arXiv ID（論文ページへのリンク）が表示され
ます。arXiv 由来として登録されていない教材（手元のファイルからアップロードしたものなど）
でも、ファイル名から arXiv ID を推定できた場合は、それを使って検索条件が用意されます
（[出所（arXiv）の登録](#radar-provenance)）。推定もできない場合は「この教材は arXiv 由来
として登録されていないため、カテゴリを指定してください」という趣旨の事実文が表示されます。
この場合は [検索条件のカテゴリ](#radar-search)を自分で入力してください。

**検索条件**: arXiv カテゴリのチップと、キーフレーズのチップ（[距離](#radar-distance)が
「近い」のときだけ表示）です。カテゴリは、起点の教材の arXiv メタデータから供給され、
引けない場合はファイル名から推定した arXiv ID のメタデータ（この場合は「ファイル名からの
推定」と出所が表示されます）、それも無い場合はその教材が属する分野の購読条件から供給され
ます。どれも引けないときは空のまま（手入力待ち）です。キーフレーズは起点の教材から抽出された理論部品のラベルが供給され、
チップをクリックして外す・足すことができます。ここで変えた条件は保存されません
（このモーダル内の検索にだけ使われます）。

**候補一覧**: タイトル・著者・日付・カテゴリ・要旨（折りたたみ）と、
[距離](#radar-distance)の段階ラベルが並びます。選んだ距離の候補が開いて表示され、
**他の距離の候補も「他の距離の候補 N件」の折りたたみとして残ります**（捨てられません）。
起点の論文そのものは一覧から除かれます。すでに取り込み済みの論文には「取り込み済み」の
ラベルが付きます（arXiv 経由ではなく手元のファイルから登録した教材は、同じ論文であっても
取り込み済みと判定できません）。

**候補の「どう近いか」の表示**: 候補一覧の各行には、次の3つが表示されることがあります。
いずれも**タイトルと要旨だけから推定したもの**で、確定した情報ではありません。候補一覧の
上には、その旨の凡例が1行、常に表示されます（実際に何であるかは、取り込んで解析し、
あなたが確認したときに決まります）。

- **落ちそうな場所（着地）** — 「取り込むと: {領域} / {概念} の近くに落ちそうです」の
  1行です。分野の地図（骨格）の**いま凍結されている版**の中で、どこに近いかだけを言い
  ます。近さは「かなり近い / 近い可能性」の段階ラベルで示され、数値は表示されません。
  近さが低い候補・地図に近い場所が見つからない候補には、この行自体が出ません
  （無理に当てはめません）。この表示には[分野の地図タブ](17-admin-atlas.md)の
  「ベクトル索引」が作られていることが必要です。
- **≒ 部品「X」と重なりそう** — 起点の教材から抽出済みの**承認された理論部品**のラベルが、
  候補のタイトル・要旨に現れているものです。多いときは一部だけを表示し、残りは「ほか」と
  だけ示します（件数は表示されません）。
- **✚「Y」の近く（起点論文は未言及）** — 候補が地図の上で近い場所のうち、**起点の教材の
  位置づけには含まれていない**ものです。「起点の論文が扱っていない主題」という意味では
  ありません（この教材の位置づけとして記録されていない、という意味です）。

近さを測るための材料が用意できなかった候補には、これらは**付きません**（「重なりなし」と
表示することもしません）。その場合は「着地・重なりの近さは測定できませんでした（このまま
取り込みできます）」という趣旨の事実文が出ます。測れなかったことと、測ったうえで何も
無かったことは区別して表示されます。これらの表示の有無は取り込みの可否には関係しません。

**距離を判定できなかったとき**: 起点の教材から近さを測るための材料（解析済みの本文や要旨）が
用意できなかった場合、候補は距離ラベルなしの新着順で表示され、その理由が事実文で示されます。
検索そのものは成立します。

### 出所（arXiv）の登録 {#radar-provenance}

[URLから取得](#url-upload)や[arXivから探す](#arxiv-discovery)から入った教材には、どの
arXiv 論文なのかという**出所**が記録されています。手元のファイルからアップロードした教材には
これが記録されていないため、そのままではレーダーの検索条件（カテゴリ）を用意できません。
この区画は、その出所を後から登録するためのものです。

**1. ファイル名からの推定**: 出所が未登録の教材でレーダーを開くと、**ファイル名**から
arXiv ID を推定します（`arXiv-2407.01221v2.tar.gz` のような名前を想定しています）。推定
できた場合はその ID で arXiv からカテゴリと要旨を取得し、検索条件に入れた状態でモーダルが
開きます。この段階の条件には「ファイル名からの推定」という出所が表示されます。**この時点
では教材に何も書き込まれません**（モーダルを閉じると推定は消えます）。ファイル名から複数の
異なる arXiv ID が読み取れる場合は、どれが本体か決められないため推定を行いません。

**2. タイトルが一致したときは自動で登録されます**: 推定した arXiv 論文のタイトルと、教材から
抽出済みのタイトルを見比べて、（大文字小文字・記号・全角半角の違いを無視して）**完全に一致**
した場合は、その論文の出所が自動的に登録されます。登録されると、この教材は URL や
[arXivから探す](#arxiv-discovery)から取り込んだ教材と同じ扱いになり、候補一覧の「取り込み
済み」判定にも反映されるようになります。

**3. 一致しなかったときは「この論文として登録する」**: タイトルが一致しなかった場合は、
arXiv 側のタイトルと教材側のタイトルが**並べて**表示され、「この論文として登録する」ボタンが
出ます。2つを見比べて同じ論文だと確認できたときだけ押してください。押すと出所が登録されます。
自動判定に任せず並置して見せているのは、タイトルが少しでも違うときに「たぶん同じ」で登録
してしまわないためです。

**登録した内容は取り消せません。** 別の論文として登録してしまうと、以後この教材は誤った
出所の論文として扱われます（レーダーの検索条件も、取り込み済み判定も、その論文のものに
なります）。押す前に必ずタイトルを確認してください。

**「この論文として登録する」が表示されない・押せない場合**: 次のいずれかです。理由はボタンの
位置に事実文で表示されます。

- **すでに出所が登録されている**: この教材には arXiv ID が記録済みで、上書きは行いません
  （先に記録された出所が優先されます）。ヘッダーに表示されている arXiv ID が違う論文を
  指している場合は、システム管理者に相談してください。
- **この教材の編集権限がない**: 他の教員が所有し、閲覧のみ共有されている教材です。出所の
  登録は所有者（または編集権限を持つ共有先）が行ってください。
- **arXiv に接続できなかった**: 照合の相手になるタイトルを取得できていないため、登録は
  行えません。「arXiv に接続できなかったため確認できません」という趣旨の事実文が表示され
  ます。arXiv 側の混雑・一時的な障害のことがあります。時間をおいてモーダルを開き直すと
  照合できます。
- **ファイル名から arXiv ID を推定できなかった**: 登録の対象になる論文が決まりません。この
  場合は [検索条件のカテゴリ](#radar-search)を手入力して検索してください（出所を登録しなくても
  レーダーは使えます）。

### 距離 {#radar-distance}

モーダル上部にある「近い（テーマも近い） / 中間 / 同じ分野の別テーマ」の3択です。既定は
「近い」です。

- 距離を選び直しただけでは検索は始まりません。[この条件で検索](#radar-search) を押した
  ときに、その距離で検索・並べ替えが行われます。
- 「近い」ではキーフレーズによる絞り込みが使われます。「中間」「同じ分野の別テーマ」では
  カテゴリだけで検索します（キーフレーズで絞ると結果が「近い」側に寄ってしまうためです）。
- 「近い」の中は近さの順、「中間」「同じ分野の別テーマ」の中は新着順に並びます
  （遠い順に並べることはしません。順位として意味のある精度がないためです）。

### この条件で検索 {#radar-search}

いま表示されている距離・カテゴリ・キーフレーズで arXiv を検索するボタンです。押すと
候補一覧が読み直されます。**この検索では文章生成 AI（LLM）を使いません**（近さの判定には
文章の埋め込み表現を使います）。

候補一覧の上には、実際に使われた検索条件と、「この一覧は検索条件に一致した範囲のみで、
その分野の論文の全体ではありません」という趣旨の注記が常に表示されます。

**検索できない・結果が出ない場合**:

- **カテゴリが1つも指定されていない**: 検索は実行されません（条件が無い状態で arXiv を
  呼ぶことはしません）。起点の教材が arXiv 由来でない場合によく起こります。カテゴリを
  1つ以上入力してから押してください。
- **arXiv から取得できなかった**: 「arXiv への接続に失敗しました」という趣旨の事実文が
  表示されます。arXiv 側の混雑・一時的な障害のことがあります。時間をおいて再度お試し
  ください。
- **検索の実行中**: 応答が返るまでの間だけ押せなくなります（二重実行の防止）。

### 違いを分析 {#radar-compare}

チェックを入れた候補について、**起点の論文との共通点と違いを AI が推定**して、各候補の
カードの中に表示するボタンです。

表示されるのは次の内容です。結果は**2つの区画**に分かれます。

- **≒ 重なっていそうな要素 — 別の表現・文脈で同じ内容** — 起点の論文から抽出済みの
  理論部品のうち、その候補が**別の言い方・別の文脈で同じことを扱っていそうな**ものです。
  「どの部品と重なるか」は、起点の教材から抽出された部品の一覧の中からだけ選ばれます
  （AI が新しい部品名を作ることはありません）。部品との対応が付かなかった指摘も、
  指摘そのものは残ります。
- **✚ 異なっていそうな要素 — 関連するが別の知識** — アプローチ・結論・対象・方法・テーマ
  などの観点ごとの違いの箇条書きです。
- **共通点**（1行）もこれまでどおり表示されます。
- 各項目には、その候補の**要旨からの逐語引用**が根拠として添えられます（折りたたんで
  表示されます）。引用と照合できなかった項目は表示されません。
- 「アブストラクト（要旨）の比較に基づく AI の推定です。本文は確認されていません。」という
  注意書きが必ず添えられます。優劣の評価や点数は表示されません。

候補一覧の行に出ている「≒ 部品「X」と重なりそう」のチップ（[モーダル: 論文レーダー](#radar-modal)）は
文字の一致だけで出しているもので、AI は使っていません。この「違いを分析」は、それより
踏み込んで**別の言い方をしている場合**も拾います。どちらも推定である点は同じです。

**この結果は保存されません。** モーダルを閉じるか、検索し直すと消えます。教材や解析結果に
書き込まれることはありません。もう一度見たいときは、改めて分析してください。

引き当てられなかった候補があった場合は、その論文と理由が事実文で並べて表示されます
（黙って落とされることはありません）。

**ボタンが無効になっている場合**: 次のいずれかです。理由はボタンの近くに表示されます。

- **候補を1件も選んでいない**: 候補一覧のチェックボックスで、比較したい論文を選んで
  ください。
- **選んだ候補が多すぎる**: 一度に分析できるのは10件までです。選択を減らしてください
  （この上限はサーバ側でも拒否されます）。
- **本日の分析上限に達した**: 「本日の比較分析の上限に達しました。」という趣旨の事実文が
  表示されます。翌日以降に再度お試しください（この上限は比較分析だけの日次上限で、他の
  AI 機能とは別に数えられます）。
- **分析の実行中**: 応答が返るまでの間だけ押せなくなります（二重実行の防止）。

**分析に失敗した場合**: 「比較分析に失敗しました」という趣旨の事実文が表示され、候補一覧は
そのまま残ります。次のような場合です。

- **起点の教材に比較の材料が無い**: 起点の論文の要旨も解析結果（中心命題・目的）も取得
  できないときは、AI を呼ばずに理由が表示されます。解析パイプラインの完了後に再度お試し
  ください。
- **AI の応答が得られなかった**: 時間をおいて再度お試しください。

### 選択した論文を取り込む（レーダー） {#radar-ingest}

チェックを入れた論文を arXiv から取得し、ファイルを選んでアップロードした場合とまったく
同じ解析パイプラインに乗せるボタンです。取り込みの仕組みは
[arXivから探す](#arxiv-discovery-ingest) とまったく同じで、押す前に何が起きるかが事実文で
表示されます。

- **5件まで**: その場で取得と解析が始まります。教材一覧に行が追加され、「アップロード済み →
  処理中 → 完了」と進みます。
- **6件以上**: [取り込みキュー](#arxiv-discovery-queue)への登録になり、サーバが1件ずつ・
  間隔をあけて順に取得・解析します。一度に登録できるのは50件までです。

このとき使われる解析の設定は、アップロードゾーンの
[図面・画像を解析する](#analyze-images) のチェック状態と
[解析モデル（変更）](#llm-model-change) で選んだモデルです。必要なら、取り込む前に
モーダルを閉じてこれらを設定してください。

**ボタンが無効になっている場合**: 次のいずれかです。理由は必ずボタンの近くに表示されます。

- **論文を1件も選んでいない**: 「取り込む論文を選択してください。」と表示されます。候補
  一覧でチェックボックスを入れてください（「取り込み済み」の論文は選べません）。
- **許可ドメインが登録されていない**: 「取得先ドメインが許可されていません。システム管理者が
  「AIモデル」タブで設定できます。」と表示されます。システム管理者に、「AIモデル」タブの
  取得先ドメイン設定で `arxiv.org` を登録するよう依頼してください（登録するまでは、この
  ボタンだけでなく[URLから取得](#url-upload)も使えません）。検索と候補の閲覧・比較分析は
  未登録でも行えます。
- **51件以上を選んでいる**: 「一度にキューへ登録できるのは50件までです。選択を減らして
  ください。」と表示されます（この上限はサーバ側でも拒否されます）。
- **取り込みの実行中**: 送信してから応答が返るまでの間だけ押せなくなります（二重実行の
  防止）。完了するか失敗すると元に戻ります。

許可ドメインの一覧を確認できなかったときは「許可ドメインを確認できませんでした。取り込みは
サーバ側で拒否される場合があります。」と表示されます。この場合ボタンは押せますが、実際に
許可されていなければサーバ側で拒否され、その理由が表示されます（許可の判定は必ずサーバ側で
行われます）。

## ゼミ前ブリーフ {#seminar-brief}

輪講（ゼミ）の前に、対象論文の「何が崩れたら危ういか」を短時間で把握するための
**読み取り専用**の合成ビューです。新しい解析は走らず、すでに記録されている前提・支持線・
検証記録の投影を1画面に集めて表示するだけです（このモーダルから何かを変更する操作は
ありません）。

表示は次の4つの区画に分かれます。

1. **脆い前提** — 検証されておらず、かつ理論の下流への影響が大きい前提です。影響の
   大きさや疑義の多さは「高」「3-5件」のような**段階ラベル・レンジ**で表示されます。
2. **一点吊りの支持線** — 中心的な主張を支える独立な経路が1本しかない箇所の事実文です。
3. **晴れ間** — 「このコーパスの中では検証記録が見つかりません」という閉世界の事実文です。
   分野全体で未検証という意味ではなく、この教材群の記録の中に無いという意味です。
4. **学習者からの問い** — この区画は現在は空欄のまま予約されています
   （手渡しの仕組みは準備中のためです）。空欄はエラーではありません。

**数値が出ない理由**: 件数・人数などの生の数値は、教員向けでも表示されません（段階ラベル・
レンジ・事実文のみ）。学習者の行動を数で測る計器にしないための設計です。同じ理由で、
誰がどの問いを挙げたかというような学習者個人単位の情報はこの画面には一切出ません。

**つまづき情報がほぼ出ないことについて**: 脆い前提に添えられるつまづきの情報は
k-匿名化（3人未満のデータは表示しない）を通ったものだけです。少人数のゼミでは
この条件をほぼ満たさないため、つまづきの行が出ないのがふつうの状態です。

中身のない区画は表示されません（第4区画だけは常に表示されます）。表示できる材料が
まだ何も記録されていない教材では、その旨の事実文だけが表示されます。

### ゼミ前ブリーフ… {#seminar-brief-open}

[操作メニュー（⋯）](#row-more-menu)の中にあります。この教材の
[ゼミ前ブリーフモーダル](#seminar-brief-modal)を開きます。document_id が付与された教材にのみ
表示されます。

### ゼミ前ブリーフモーダル {#seminar-brief-modal}

上記の4区画（脆い前提 / 一点吊りの支持線 / 晴れ間 / 学習者からの問い）を順に表示する
読み取り専用のモーダルです。確認・却下などのボタンはありません。表示の元になっている
前提の記帳・疑義・検証提案を変更したい場合は「前提の地図」タブで行います。

## モーダル: 解析を再開（オプション） {#reanalyze-modal}

「解析再開」から開く、解析再開前のオプション確認モーダルです。

1. 「図面・画像を解析する」チェックボックスは、前回の解析設定を引き継いで初期表示されます。
2. 「解析モデル: ◯◯（前回と同じ）」の行から、今回の再解析に使うモデルを確認・変更でき
   ます。前回の指定が無いときは、いまの実効モデルとその出所が表示されます。
3. 「再開する」を押すと解析が再開されます。

### 解析モデルの変更（再解析） {#reanalyze-model-change}

解析モデルの行の **「変更」**を押すと、モデルを選ぶプルダウンがその場に開きます
（もう一度押すと閉じます）。「図面・画像を解析する」にチェックが入っているときは、
「図の解析（vision）」用のプルダウンも一緒に出ます。

アップロードゾーンの [解析モデル（変更）](#llm-model-change) とは**作りが異なります**。

- 選択肢はプルダウンだけで、「この設定で解析する」「既定に戻す」「ステージ別に指定する
  （詳細）」といったボタンはありません。選んだ内容は「再開する」を押したときに使われます。
- **ここでの選択は今回の再解析にだけ適用され、あなたの既定としては保存されません。**
- 前回の解析でステージ別の指定を使っていた場合は、行の下に「ステージ別の指定があります
  （…件・前回と同じ）」と表示されます。この画面ではステージ別の指定を変更できません
  （変更したいときは、教材のアップロード時に指定し直してください）。そのまま再開すると
  前回のステージ別指定が引き継がれます。

**「変更」が押せない場合**: モデルの一覧を取得できていません。行の表示が
「取得できませんでした」になっているときは、そのまま「再開する」を押せば
これまでどおりの既定モデルで解析されます。

前回は「図面・画像を解析する」がオンで、今回オフにして再解析しようとすると、追加の
[危険確認モーダル](10-admin-common.md#danger-confirm-modal)が表示されます。これは
オフにすることで、まだ確認していない AI の図分類・装置候補が失われるためです。件数が
取得できた場合は対象件数も表示されます。この確認を経ないと、明示的にオフへ変更した
再解析は実行されません。

## モーダル: 図・画像 {#figures-modal}

「図・画像」から開く、教材から抽出された図の一覧です。装置候補は AI による推定であり、
常に教員の確認が必要です（確定はライブラリへの昇格操作でのみ行われます）。各図には
抽出方式（埋込画像/領域推定）のバッジと、装置候補があればその名称・一致状況
（一致候補/新規候補/不明、いずれも「要確認」注記付き）・パーツが表示されます。

### 深く検討 {#figure-deliberate}

図を要素検討ワークスペースで開き、内訳（分類・装置候補など）の確認、AI との対話、
候補としての解釈の付与ができます。

### 図で確認 {#figure-overlay}

装置候補のパーツや図中のラベルの位置を、図画像の上に矩形で重ねて確認できるオーバーレイを
開きます。矩形をクリックすると、そのパーツの名称・図中ラベル・役割・本文根拠が
右側に表示されます。

このボタンは、図の領域情報（bbox）があり、かつ装置候補のパーツに位置情報があるか、
図中にラベルが抽出できている場合にのみ表示されます。これらの情報が無い図では表示されません。

### ライブラリへ昇格 {#figure-promote}

この装置候補を、分野のナレッジライブラリ（教員間の共同財）へ新規エントリとして登録するか、
既存エントリに統合するための[ライブラリへ昇格モーダル](#library-entry-modal)を開きます。

## モーダル: ライブラリへ昇格 {#library-entry-modal}

装置候補またはコンポーネントを、分野のナレッジライブラリへ新規エントリとして登録する
モーダルです。AI の候補をそのまま登録せず、自分の言葉で書き直すことが推奨されます。

分野・種別・名称・別名・要約に加え、種別が「装置」の場合は見た目の特徴・構成パーツ・
典型的な構成・計測対象を入力できます。名称や分野を入力すると、既存の似たエントリが
自動的に検索され、統合先の候補として提示されます。

### 統合先を選ぶ {#library-entry-merge-target}

新規作成ではなく、既存の似たエントリに統合して登録することもできます。

**「例示画像を含める」チェックボックスが無効（グレーアウト）になっている場合**: 統合先の
既存エントリを選んでいます。統合では画像は引き継がれない仕様のため、統合先を選ぶと
自動的にチェックが外れ、無効化されます。画像を含めたい場合は、統合ではなく「新規作成」を
選んでください。

（このチェックボックス自体は、図から起動し、かつ自分がその図の元教材の所有者である
場合にのみ表示されます。例示画像は教材の所有者のみが含める判断をでき、含めた場合は
ライブラリを閲覧できる全教員に表示されます。エントリ本文のテキストは所有者以外でも
登録できます。）

## モーダル: 外部レビュー用に書き出し {#export-modal}

コースまたは教材単位で、根拠スニペット・レビュー項目・NDJSON・デバッグデータを含む
書き出しファイルをダウンロードするモーダルです。

1. 書き出し範囲（「現在のコース」または「現在の教材」）を選びます。
2. 含めるデータ（根拠スニペット・レビュー項目・NDJSONファイル・デバッグデータ）を
   チェックボックスで選びます。
3. 「ダウンロード」を押すとファイルが生成され、ダウンロードされます。

**「現在のコース」が選べない（グレーアウトしている）場合**: 教材管理タブの行から
（教材単位で）このモーダルを開いています。この起動経路では書き出し範囲は「現在の教材」に
固定され、コース単位の書き出しは選べません。コース単位で書き出したい場合は、
「コース管理」タブから同じモーダルを開いてください。

## モーダル: 反復改善 {#revision-modal}

パイプラインの採用済み成果物（active run）を保ったまま、改善候補を生成・検証・採否する
モーダルです。「パイプラインを実行 ▼」メニューの「反復改善（採用版を保ったまま）」から
開きます。

現在の採用版（active run）と最新run（処理状況）が上部に表示され、過去の改善run一覧
（revision・状態・base）が並びます。各行の「詳細」から個別のrevisionを開けます。

### 改善処理を開始 {#revision-start}

新しい改善run（原論文の監査 → 修正候補の生成 → 検証 → 差分レポート作成）を開始します。

**ボタンが無効（グレーアウト）になっている場合**: 開始処理を送信してから応答が返るまでの
一瞬だけ押せなくなります（二重実行の防止）。応答が返ると自動的に元に戻ります。

なお、採用版（active run）がまだ存在しない教材でこの処理を開始しようとすると、
「採用版（active run）がありません。先に解析を完了してください。」という案内が表示され、
実行されません。

### 採用・却下・再修正 {#revision-decision}

個別のrevisionの詳細画面で、「監査＋候補生成」の実行と、生成された差分レポートに対する
「採用」「却下」「再修正」の決定を行います。

**「採用」ボタンが無効（グレーアウト）になっている場合**: このrevisionにはまだ差分
レポートがありません。「監査＋候補生成」を実行し、レポートが作成されるまで待ってください。

**すべての決定ボタンが無効（グレーアウト）になっている場合**: このrevisionに対する
監査＋候補生成の処理が実行中です。処理が完了するまで、採用・却下・再修正のいずれも
実行できません。処理が完了すると自動的に元に戻ります。
